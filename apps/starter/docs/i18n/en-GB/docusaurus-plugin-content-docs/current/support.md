Use **Contact support** in the bottom corner of the signed-in web application to ask the platform team for help. You can contact support even when you do not have an active organisation. Your requests are private to you and platform support; other organisation members cannot read them.

## Start or continue a request

1. Select **Contact support**, then **New request**.
2. Enter a short subject and describe what you need in **Message**. Select **Send message**.
3. Select a request from **Support requests** to read its replies or send another message. Choose **More requests** to continue through older requests. Use **Older messages** and **Latest messages** to move through long histories.
4. Select **Mark as read** after reading new replies. The number beside a request shows unread messages. Only replies on the page you viewed are marked read; a reply that finishes translation later remains unread.

Start a separate request for an unrelated issue. A new message in a resolved request reopens that same request, however long ago it was resolved. Closing the Support widget does not resolve the request. Your unsent draft and retry identity remain available when you reopen it during the same signed-in session.

If sending fails, keep the message and retry. Retrying the same message after a connection failure does not create a duplicate. **Retry** retries your latest failed send with its original contents and request identity, and refreshes failed reads. If you edit the draft while an earlier send finishes, the newer text stays in the composer. Replies become available when you return to the application; email and push notifications are not provided for Support.

## Files and languages

After creating a request, use **Attach files** when sending a message. The default limit is five files per message and 10 MiB per file. JPEG, PNG, WebP, PDF and plain-text/log files are supported. An invalid or oversized upload cannot be sent. Choose the attachment button in a message to download it. A redacted message or attachment is no longer available.

**Support language** controls the language used for replies. A choice you make takes priority over automatic detection and your application language. Use a supported language tag, such as `en` or `en-GB`, then **Save**. The team may support message languages beyond those available for the application menus.

When translation is enabled, a reply shows the exact translated text that was delivered. **Show original** reveals the authored text. Your original messages remain available even if translation fails. A reply awaiting translation is not yet sent to you, and its files remain unavailable until it is sent. If your support language changes while a reply is waiting, translation follows the new language automatically.

## AI and human help

When enabled, the **AI assistant** can answer from the application's published help. Its complete answers include source links. It cannot change your account or take other actions for you. Select **Talk to a person** whenever you want a human; unfinished AI replies will stop. Human support hours and an expected reply message may appear above your requests. Messages stay queued outside those hours, while enabled AI may still answer.

## Resolve and rate

Select **Resolve** when your issue is finished. You can select **Reopen** or send another message if you need more help. Where feedback is enabled, a genuine resolved exchange shows three faces: 🙁, 😐 and 🙂. Select one face to rate the experience; no text is required. You may change the rating while that resolution cycle stays resolved. A new message starts another cycle and retires the previous unanswered survey.

If your account is Closed, you cannot use Support until an administrator Restores access. Purge removes the related history. See [signing in](signing-in.md) for account access problems.
