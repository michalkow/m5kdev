# PostHog error tracking migration

## Summary

PostHog replaces Sentry for backend error reporting and captures browser/React failures. Error capture stays optional,
reports unexpected server failures once, and preserves native causes, structured
context, available User/Organization identity, and OpenTelemetry trace identifiers.

The Webapp bundles the PostHog exception extension, explicitly enables uncaught
errors and unhandled rejections, and reports React render failures with component
context. Its translated recovery screen offers **Reload page**. Expected tRPC
mutation errors are not indiscriminately recaptured in the browser.

## Who needs this migration

Apps using `@m5kdev/backend` error reporting or the Starter server instrumentation.
Apps with custom Sentry reporter adapters, imports, or log consumers must migrate
those contracts. Expo/native instrumentation is outside this migration.

## Prerequisites and upgrade order

Use Node.js 24 and upgrade `@m5kdev/backend`, `@m5kdev/frontend`,
`@m5kdev/web-ui`, and `create-m5kdev` to **0.45.0** with
the rest of the lockstep m5kdev release. First update the Managed catalog, then
server composition, custom reporting integrations, and deployment configuration.
Configure a PostHog project before enabling capture.

## What changed

- `initPosthog` and `shutdownPosthog` explicitly initialize and flush one optional
  client shared by error reporting and existing analytics helpers.
- `ErrorReporter.captureException(error, properties)` accepts flat structured
  properties. Sentry's hint/`extra` types are removed.
- `ServerError.sentryEventId` becomes `errorEventId`, including serialized errors
  and structured boundary logs. The ID matches the PostHog event UUID.
- `lib/sentry` and its `@sentry/node` dependency are removed; the old eager
  `posthogClient` export is replaced by explicit initialization.
- Expected 4xx failures remain local logs. ServerError capture remains idempotent;
  terminal plain Workflow failures capture once, and intermediate retries warn.
  Errors already captured when created retain that capture on retries.
- Errors still annotate active OTel spans when PostHog is unconfigured. Framework
  Actor scopes bridge into the SDK request context, so process-level uncaught
  exceptions/rejections retain available User/Organization identity. The SDK
  snapshots the active OTel span as `$trace_id`/`$span_id` and retains its native
  fatal-exit/flush behavior; unrelated detached work stays anonymous.

## Migration steps

1. **Manual:** update the catalog/dependencies above and run `pnpm install`.
2. **Manual:** initialize OTel before loading PostHog/reporting modules. The
   CommonJS Starter instrumentation uses a deferred require after `initTelemetry`:

   ```ts
   const { initPosthog } =
     require("@m5kdev/backend/lib/posthog") as typeof import("@m5kdev/backend/lib/posthog");
   initPosthog();
   ```

   An ESM app can import its OTel instrumentation first, then a separate PostHog
   instrumentation module that imports and invokes `initPosthog`. Do not import
   the reporter before the OTel initialization runs.
3. **Manual:** compose shutdown through the existing Kernel hook:

   ```ts
   import { shutdownPosthog } from "@m5kdev/backend/lib/posthog";
   import { shutdownTelemetry } from "@m5kdev/backend/lib/otel";

   // Within createBackendApp configuration:
   onShutdown: async () => {
     const results = await Promise.allSettled([shutdownPosthog(), shutdownTelemetry()]);
     const failures = results.flatMap(result => result.status === "rejected" ? [result.reason] : []);
     if (failures.length > 0) throw new AggregateError(failures, "Failed to flush observability");
   },
   ```

4. **Conditional:** replace `sentryEventId` reads with `errorEventId` and Sentry
   hints with flat `ErrorProperties`. Custom `setErrorReporter` adapters accept
   `(error, properties)` and return a correlation ID or `undefined`.
5. **Conditional:** remove `lib/sentry`, eager `posthogClient` imports, Sentry
   initialization, and obsolete Sentry secrets from your application's setup.
   Existing analytics helpers use the client registered by `initPosthog`.

6. **Conditional (Webapp):** copy the browser initializer and error boundary into
   the equivalent app paths. Pass the optional client from `main.tsx` through
   `App` into `Providers`. Keep the existing route tree and centralize the
   PostHog provider and global providers in `Providers.tsx`. Retain i18next error
   messages and the help-page recovery instructions.

7. **Conditional (Webapp uploads):** add the official Rollup plugin to the Vite
   build only when the private key and project ID are both set. Load shared env
   with `loadEnv(mode, envDir, "")`, pass private values only to the plugin,
   and retain `deleteAfterUpload: true`. Starter uses `releaseMode: "symbol-set"`
   for compatibility with its browser SDK's chunk-ID symbolication. Partial
   upload configuration fails with an actionable message; dev serving skips
   uploads.
8. **Conditional (Turbo):** add `VITE_*`, `POSTHOG_API_KEY`, `POSTHOG_PROJECT_ID`,
   and `POSTHOG_HOST` to the build task's `env` allowlist/hash inputs. Otherwise
   strict env handling can strip upload configuration or reuse the wrong cache.
9. **Conditional (Fly):** retain the Docker `ALL_SECRETS` BuildKit mount. The
   upgraded wrapper incorporates upload configuration into `VITE_CONFIG_HASH`
   and excludes upload-only variables from runtime secret imports.

10. **Conditional (custom sign-out):** route app sign-out through
    `useSession().signOut()` so `AuthProvider` clears its session and invokes
    `onSession(null)` before navigation. The operation now returns `Promise<void>`;
    custom context implementations/test doubles should use `async` functions.
    Shared Web UI logout and account-closure components already use this path.

    ```tsx
    const { signOut } = useSession();
    const onSignOut = async () => {
      await signOut();
      navigate("/login");
    };
    ```

11. **Conditional (browser regression tests):** keep the encoding API setup when
    merging the colocated tests. React Router needs these browser APIs under jsdom.
    Add `setupFiles: ["<rootDir>/src/modules/app/tests/setup.ts"]` in
    `jest.config.cjs` and create that small setup file:

    ```ts
    import { TextDecoder, TextEncoder } from "node:util";
    Object.assign(globalThis, { TextDecoder, TextEncoder });
    ```

#### `apps/webapp/src/utils/posthog.utils.ts`

```ts
import posthog, { type PostHog } from "posthog-js";
// Bundle exception conversion/listeners so capture works before remote scripts load.
import "posthog-js/dist/exception-autocapture";

export function initBrowserPosthog({
  apiKey,
  host,
}: {
  apiKey?: string;
  host?: string;
}): PostHog | undefined {
  const normalizedKey = apiKey?.trim();
  if (!normalizedKey || normalizedKey === "demo") return undefined;
  return posthog.init(normalizedKey, {
    api_host: host || "https://us.i.posthog.com",
    defaults: "2025-05-24",
    capture_exceptions: {
      capture_unhandled_errors: true,
      capture_unhandled_rejections: true,
      capture_console_errors: false,
    },
  });
}

/** Keep exception identity in sync with authenticated session transitions. */
export function syncBrowserPosthogIdentity(
  client: PostHog | undefined,
  session:
    | { user: { id: string }; session: { activeOrganizationId?: string | null } }
    | null
    | undefined
): void {
  if (!client) return;
  const userId = session?.user.id;
  const previousUserId = client.get_property("user.id");
  if (previousUserId && previousUserId !== userId) client.reset();
  if (!userId) {
    client.unregister("user.id");
    client.unregister("organization.id");
    return;
  }
  client.identify(userId);
  client.register({ "user.id": userId });
  const organizationId = session?.session.activeOrganizationId;
  if (organizationId) client.register({ "organization.id": organizationId });
  else client.unregister("organization.id");
}
```

#### `apps/webapp/src/modules/app/components/AppErrorBoundary.tsx`

```tsx
import { Button } from "@heroui/react";
import type { PostHog } from "posthog-js";
import { Component, type ErrorInfo, type PropsWithChildren } from "react";
import { useTranslation } from "react-i18next";

function AppErrorFallback() {
  const { t } = useTranslation("starter-app");
  return (
    <main
      role="alert"
      className="flex min-h-screen flex-col items-center justify-center gap-4 p-6 text-center"
    >
      <h1 className="text-2xl font-semibold">{t("errors.title")}</h1>
      <p className="text-muted">{t("errors.body")}</p>
      <Button onPress={() => window.location.reload()}>{t("errors.reload")}</Button>
    </main>
  );
}

// React exposes componentDidCatch/getDerivedStateFromError only through class
// components; this infrastructure boundary is the narrow exception to function components.
export class AppErrorBoundary extends Component<
  PropsWithChildren<{ client?: PostHog }>,
  { failed: boolean }
> {
  override state = { failed: false };

  static getDerivedStateFromError() {
    return { failed: true };
  }

  override componentDidCatch(error: Error, info: ErrorInfo) {
    this.props.client?.captureException(error, { componentStack: info.componentStack });
  }

  override render() {
    return this.state.failed ? <AppErrorFallback /> : this.props.children;
  }
}
```

#### Vite build integration

Merge this complete Starter config into customized Vite configuration, preserving
your existing plugins, aliases, and i18next paths. The additions are private
`loadEnv` configuration and the conditional PostHog plugin, not browser defines:

```ts
import path from "node:path";
import posthog from "@posthog/rollup-plugin";
import tailwindcss from "@tailwindcss/vite";
import react from "@vitejs/plugin-react";
import { defineConfig, loadEnv } from "vite";
import i18nextLoader from "vite-plugin-i18next-loader";
import tsconfigPaths from "vite-tsconfig-paths";

export default defineConfig(({ command, mode }) => {
  const envDir = path.resolve(__dirname, "../shared");
  // Load private build configuration without exposing it through VITE_* defines.
  const env = loadEnv(mode, envDir, "");
  const apiKey = env.POSTHOG_API_KEY?.trim() ?? "";
  const projectId = env.POSTHOG_PROJECT_ID?.trim();
  if (command === "build" && Boolean(apiKey) !== Boolean(projectId)) {
    throw new Error(
      "PostHog source map uploads require POSTHOG_API_KEY and POSTHOG_PROJECT_ID together"
    );
  }
  const uploadSourceMaps = command === "build" && Boolean(apiKey && projectId);

  return {
    root: __dirname,
    plugins: [
      ...(uploadSourceMaps
        ? [
            posthog({
              personalApiKey: apiKey,
              projectId,
              host: env.POSTHOG_HOST || "https://us.posthog.com",
              sourcemaps: { enabled: true, deleteAfterUpload: true, releaseMode: "symbol-set" },
            }),
          ]
        : []),
      tailwindcss(),
      react({
        babel: {
          plugins: ["babel-plugin-react-compiler"],
        },
      }),
      tsconfigPaths(),
      i18nextLoader({
        include: ["**/*.json"],
        paths: [
          path.resolve(__dirname, "./node_modules/@m5kdev/web-ui/dist/translations"),
          path.resolve(__dirname, "./translations"),
        ],
        namespaceResolution: "basename",
      }),
    ],
    resolve: {
      dedupe: ["react", "react-dom", "react-i18next", "react-router", "nuqs"],
    },
    envDir,
  };
});
```

#### Replace direct `posthogClient` usage

`initPosthog()` registers the shared optional client. Callers that used the removed
eager export can obtain it without creating another instance:

```ts
import { getPosthog } from "@m5kdev/backend/utils/posthog";

getPosthog()?.capture({ distinctId: "user-123", event: "report_opened" });
```

When no valid ingestion token is configured, `getPosthog()` is `undefined`; handle
that explicitly or use optional chaining. SDK shutdown first flushes pending
messages, then opts the retired client out so later errors in a still-running
process cannot send to the previous destination. The Kernel's terminal Express
error middleware is installed after module and SPA routes: raw async HTTP 5xx
exceptions are captured; expected 4xx retain their status and are not reported.
Register extra HTTP through module `express` hooks so it precedes that boundary.

Workflow trigger metadata and trigger-override `userId` now travel as minimal
BullMQ options metadata, with precedence over a payload `userId`. The handler
receives the original payload unchanged. Older jobs without metadata continue
to use their payload identity. No queue drain or data migration is required.

## Environment and deployment changes

Set `VITE_PUBLIC_POSTHOG_KEY` to the public project ingestion token and
`VITE_PUBLIC_POSTHOG_HOST` to its ingestion host, for example
`https://us.i.posthog.com` or `https://eu.i.posthog.com`. The server and browser
share these public configuration values. Missing, empty, or `demo` keys disable
initialization. OTel configuration remains independent.

For uploads, set these **private build** values in each environment's ignored env
file and GitHub `APP_ENV_FILE` secret:

```dotenv
POSTHOG_API_KEY=<personal-api-key-with-error-tracking-write-access>
POSTHOG_PROJECT_ID=<project-id>
POSTHOG_HOST=https://us.posthog.com
```

EU Cloud uses `https://eu.posthog.com` here and `https://eu.i.posthog.com` for the
public ingestion host. Leave the key and project ID empty to skip uploads. Never
prefix the private key with `VITE_`: Vite exposes prefixed values in browser code.
The Fly wrapper mounts upload credentials during the Webapp build and filters
all three upload values out of `app:secrets:<environment>` runtime imports.
Remove previously imported upload secrets manually with `fly secrets unset
POSTHOG_API_KEY POSTHOG_PROJECT_ID POSTHOG_HOST --app <app-name>` if needed.

Configured uploads use the exact emitted JavaScript and hidden maps; the plugin
removes maps after success. Upload failure aborts the build, keeping maps in the
failed builder for diagnosis. Builds without credentials emit no maps by default.
Direct Fly/Docker builds must change `VITE_CONFIG_HASH` when public or upload
configuration changes; unrelated runtime secrets do not affect this hash.
Each Deployment environment still builds its own bundle under ADR-0036.

The ingestion token/host must reach **both** environments: the Vite build and
server runtime. Keep `VITE_PUBLIC_POSTHOG_KEY`/`VITE_PUBLIC_POSTHOG_HOST` in the
same environment file used by both `app:secrets:<environment>` and
`app:deploy:<environment>`. For a local Development deployment:

```sh
pnpm app:secrets:development
pnpm app:deploy:development
```

The generated deployment workflow already performs both operations for its
selected environment. Setting a Vite build value alone does not configure an
existing server process; import the runtime secrets and deploy/restart it too.
Only `POSTHOG_API_KEY`, `POSTHOG_PROJECT_ID`, and `POSTHOG_HOST` are filtered from
runtime imports; the public ingestion configuration must remain available there.

With a real configured project, provoke one deliberate backend 5xx and one failed
Workflow. Confirm exception cause/context and available identity in PostHog,
match `errorEventId` in logs, and verify the existing OTel error span. A 4xx should
produce a local warning without an exception event. Restart/shutdown must flush
pending events. Automated tests use an external network stub, not live credentials.

The Webapp source map test builds a real Vite fixture, substitutes only the
external PostHog CLI, and checks artifact bytes, chunk IDs, private key exclusion,
map deletion, missing/partial credentials, and upload failure. CLI tests inspect
actual scaffolds across all Deployment environments. To verify a live deployment,
check PostHog symbol sets and confirm a deliberate browser error resolves to the
original source. Live upload verification needs your own credentials.

For a separate generated-app smoke check, configure **disposable local or
Development PostgreSQL** connections in `DATABASE_URL` and
`DATABASE_DIRECT_URL`, with the required app migrations/seed permissions. The
smoke test performs `drizzle:migrate` and `drizzle:seed`; never target Staging,
Canary, or Production. It installs released packages, so run this against the
published **0.45.0** release (or the repository's existing packed-package test
setup), not before that release is available:

```sh
pnpm --filter create-m5kdev test:smoke --runInBand
```

This script sets `CLI_SMOKE=1`. Expect a freshly generated app to install, pass
its doctor, type checks and lint, migrate/seed the disposable database, and build
server plus Webapp. Ordinary `create-m5kdev test` intentionally skips this test;
its success alone is not evidence that the separate smoke ran.

## Rollback

Revert application wiring, catalog, lockfile, and log-field queries together to
the previous release. Restore your previous Sentry integration if needed. There
is no database rollback or historical-event import. Disable PostHog by clearing
its public project token if you need to stop capture independently of OTel.

## Troubleshooting

| Symptom | Check |
| --- | --- |
| No backend exceptions | Ensure `initPosthog` runs and the ingestion token is neither empty nor `demo` |
| Logs use a missing Sentry ID | Update consumers to `errorEventId` |
| Missing identity | Ensure the request or job supplies User/Organization identifiers; anonymous failures remain reportable |
| Missing OTel correlation | Load OTel before error/logger modules and verify existing OTLP configuration |
| Lost buffered events on stop | Await `shutdownPosthog` in Kernel `onShutdown` |
| No source maps uploaded | Set both private key and project ID; ensure Turbo forwards env and the build layer is invalidated |
| Build fails during upload | Check personal key permissions, project, host, and CLI/network availability; do not publish that failed output |
| Minified browser frames | Confirm symbol sets match deployed chunk IDs and that each environment built with its own values |
| Private key present in Fly runtime | Remove previously imported upload secrets; use the updated secrets wrapper |
