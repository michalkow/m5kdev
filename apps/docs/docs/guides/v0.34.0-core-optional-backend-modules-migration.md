# Core Modules and Optional Backend Module packages in 0.34.0

:::note Open question
Confirm the published release number before linking this guide from release
notes. Packages in the monorepo currently report `0.33.0`; rename the file and
`migration.id` / `target_version` if the ship version differs from `0.34.0`.
:::

## Summary

Clay, Docx, Pdf, Social, and Video no longer ship inside `@m5kdev/backend`.
Each is an Optional Backend Module package (`@m5kdev/module-<name>`). The Kernel
keeps Kernel infrastructure and Core Modules. `AccessModule` and `CryptoModule`
are deleted. List/match Drizzle helpers move with Base; `@m5kdev/backend/modules/utils/*`
is gone.

`createBackendApp(config, modules[])` is unchanged. `create-m5kdev` never adds
Optional packages. If an app needs one, add the Managed-catalog pin by hand.
`doctor` treats a present Optional pin as lockstep (`CATALOG_VERSION_MISMATCH`)
the same as drizzle.

There is **no** `create-m5kdev` registry transform. Catalog merge is the existing
updater. Import rewrites and Optional-package installs are **Manual** or
**Conditional**.

## Who needs this migration

- **Every app** that upgrades `@m5kdev/backend` across this split.
- Apps that import `PdfModule`, `DocxModule`, `VideoModule`, `SocialModule`, or
  `ClayModule` from `@m5kdev/backend/modules/...` — those paths fail after the
  upgrade until they switch to `@m5kdev/module-*`.
- Apps that register `AccessModule` or `CryptoModule`, or import
  `@m5kdev/commons/modules/crypto/*`.
- Apps that import query helpers from `@m5kdev/backend/modules/utils/*`.
- Managed apps whose `.m5kdev.json` `template.features` does **not** include
  `workflows` or `notifications` — Starter 0.33 always composed Workflow tables
  (and registered `WorkflowModule`) and always exported Notification tables.
  Update can strip those blocks unless the feature ids are present.

Apps that only boot Auth and Email, never imported the removed Kernel paths, and
already use `createBackendApp` still need the Kernel bump and a dry-run of
`m5kdev update` so feature markers do not drop Workflow/Notification schema.

New apps scaffolded on this release never receive Optional packages from
`create-m5kdev`.

## Prerequisites and upgrade order

1. Finish [Catalog lockstep](/guides/v0.33.0-catalog-lockstep-migration.md) if
   the app is still on nested Kernel drizzle.
2. Complete same-release
   [Kernel Database commands](/guides/v0.34.0-kernel-database-commands-migration.md)
   and [Docker, Fly.io, and Node 24](/guides/v0.34.0-fly-deploy-migration.md)
   if those files still match 0.33 Starter.
3. Commit or stash application changes.
4. Inspect `.m5kdev.json` `template.features` **before** `m5kdev update` (see
   step 2 below).
5. Upgrade `create-m5kdev` and `@m5kdev/*` together. Do not mix an older Kernel
   with a newer `@m5kdev/module-pdf`.

Always invoke an exact CLI release once the number is confirmed.

## What changed

| Layer | Change |
| --- | --- |
| Kernel infrastructure | `BaseModule`, Grants, procedures, actors, repositories, and list/match helpers live under `@m5kdev/backend/base/*`. `@m5kdev/backend/modules/base/*` still re-exports the same types. Do not pass Base to `createBackendApp`. |
| Core Modules (still in the Kernel) | AI, Auth, Billing, Connection (`id` `connect`), Email (`EmailModule`), File, Notification, Recurrence, Tag, Inbound callback (`id` `webhook`), Workflow. Optional **registration** is unchanged: omit them from the modules array to skip boot. |
| Optional Backend Modules | Clay, Docx, Pdf, Social, Video — published as `@m5kdev/module-<name>`. |
| Deleted | `AccessModule` (Better Auth `createAccessControl` wrapper). Grants and Access width stay on Kernel infrastructure. `CryptoModule`, `crypto_payments`, and `@m5kdev/commons/modules/crypto/*`. |
| CLI catalog | No `clay`, `social`, `documents`, `access`, or `crypto` create flags. Core flags remain: `files`, `workflows`, `billing`, `ai`, plus experimental `notifications`, `tags`, `recurrence`, `connect`, `webhook`. |
| Starter | Notification tables and `NotificationModule` follow the `notifications` feature flag. Workflow and File registration follow `workflows` / `files`. |
| Taxonomy | Docs use Kernel infrastructure / Core Module / Optional Backend Module. Table, App shell, and Schemas stay Shared-contract / UI. `@m5kdev/email` stays React Email chrome, not `EmailModule`. |

Domain nouns: **Connection** (code id `connect`); **Inbound callback** (code id
`webhook`). Do not rename those ids. Connection is not Better Auth login OAuth.
Inbound callback is not Stripe Billing `POST /webhook`.

Kernel API does **not** grow a core-versus-optional registry. Register Optional
packages in the same `createBackendApp` modules array.

## Dependency and catalog changes

Bump `@m5kdev/backend`, `@m5kdev/commons`, and `create-m5kdev` together on the
Managed catalog. Do **not** run `pnpm update --latest`.

Removed from `@m5kdev/backend` `dependencies` (they move with Optional packages
or are deleted with Crypto):

| Package | Where it lives now |
| --- | --- |
| `pdf-parse` | `@m5kdev/module-pdf` |
| `mammoth`, `turndown` | `@m5kdev/module-docx` |
| `ffmpeg-ffprobe-static` | `@m5kdev/module-video` |
| `bip32`, `bip39`, `bitcoinjs-lib`, `tiny-secp256k1` | Deleted with CryptoModule |

`@m5kdev/backend/modules/pdf/*` (and docx, video, social, clay, access, crypto,
utils) are **removed exports**. `@m5kdev/backend/utils/*` (Kernel HTTP helpers)
is unrelated and stays.

Optional packages this monorepo currently reports at `0.33.0` (lockstep with
the Kernel when published). Each depends on `@m5kdev/backend` and peers:

| Package | Peers the app must already provide |
| --- | --- |
| `@m5kdev/module-pdf` | `neverthrow` |
| `@m5kdev/module-docx` | `neverthrow` |
| `@m5kdev/module-video` | `neverthrow` |
| `@m5kdev/module-social` | `neverthrow`, `zod` |
| `@m5kdev/module-clay` | `neverthrow`, `zod` |

`create-m5kdev` does **not** add these to Starter `package.json`. When an app
depends on one, the pin belongs in `catalogs.m5kdev` as `catalog:m5kdev`.
`m5kdev update` writes those managed keys even when Starter does not depend on
them. A mixed Kernel / `module-clay` version is `CATALOG_VERSION_MISMATCH`.

Node.js, pnpm (`pnpm@10.13.1`), and `catalogMode: strict` are unchanged by this
split (Node `>=24` is the Fly/Node guide).

## Starter and template file changes

| Path | Existing app |
| --- | --- |
| `pnpm-workspace.yaml` | **Automatic** catalog merge adds `@m5kdev/module-*` managed pins. Do not copy Optional packages into Starter manifests unless the app uses them. |
| `apps/<app>/server/src/app.ts` | **Conditional**. 0.33 Starter always registered `WorkflowModule`. This release wraps it in `// m5k:workflows` markers. If `workflows` is missing from managed features, dry-run may drop that registration. Keep or restore it if the app still queues jobs. File and Notification modules appear only when those features are on. |
| `apps/<app>/server/src/schema.ts` | **Conditional**. 0.33 Starter always exported `notificationDevices` / `notificationSendLogs` and `workflows`. This release gates them on `notifications` / `workflows` / `files`. Do not let update drop tables you still have in the database. |
| `apps/<app>/server/AGENTS.md` | **Automatic** / merge. Notification claims are inside `m5k:notifications` markers so they match registration. |
| `apps/<app>/server/package.json` | Add `@m5kdev/module-<name>: catalog:m5kdev` only if you register that Optional module. |
| `packages/cli/scripts/prepare-templates.ts` | Scaffolding only. Existing apps do not copy it. |

Do not overwrite a customized `app.ts` or `schema.ts` wholesale. Product Files /
Workflows UI routes (`apps/webapp/src/modules/files/`, `workflows/`) are Starter
screens behind those Core flags — add them only if you want that UI.

## Migration steps

### 1. Upgrade CLI and Kernel — Manual

Install the same release line of `create-m5kdev` and `@m5kdev/backend` /
`@m5kdev/commons`. Invoke an exact CLI release, not a floating tag.

### 2. Preserve Workflow and Notification composition — Conditional (before update)

Read `.m5kdev.json` `template.features`.

- If the app still registers `WorkflowModule` or exports `workflows` from App
  schema, add `"workflows"` to `template.features` (keep the array sorted) so
  `m5kdev update` does not strip the `m5k:workflows` blocks.
- If App schema still exports `notificationDevices` / `notificationSendLogs`,
  add `"notifications"` the same way **or** keep those exports by hand when
  dry-run would delete them. 0.33 Starter composed those tables even when
  `NotificationModule` was not registered.
- Add `"files"` only if you want File module registration and the Starter Files
  UI.

Then:

```sh
pnpm dlx create-m5kdev@0.34.0 update --dry-run
pnpm dlx create-m5kdev@0.34.0 update
```

Replace `0.34.0` with the confirmed CLI version. Catalog merge is **Automatic**
(`m5kdev update` apply). Feature-block stripping is **Automatic** for
unmodified template files once features are set.

### 3. Point Base and query helpers at Kernel infrastructure — Conditional

Prefer `@m5kdev/backend/base/*`. The compatibility path
`@m5kdev/backend/modules/base/*` still works.

Replace removed Utils-module imports:

```ts
// before (fails)
import { applyPagination } from "@m5kdev/backend/modules/utils/applyPagination";

// after
import { applyPagination } from "@m5kdev/backend/base/applyPagination";
```

The same move applies to `applySorting`, `getConditionsFromFilters`,
`getConditionsFromMatch`, `getGlobalSearchCondition`, and `escapeLikeUserInput`
(`@m5kdev/backend/base/getGlobalSearchCondition`).

### 4. Remove AccessModule and CryptoModule — Conditional

Delete `AccessModule` from the `createBackendApp` modules array and drop
`@m5kdev/backend/modules/access/*` imports. Keep `<module>.grants.ts` and
`accessGuard` — that is Grant Access width, not AccessModule.

Delete `CryptoModule` and `@m5kdev/commons/modules/crypto/*`. If App schema
exported `cryptoPayments` / table `crypto_payments`, remove that export, then
run the project's `drizzle:generate` (do **not** hand-write SQL) and migrate.

### 5. Add Optional packages you actually register — Conditional

`create-m5kdev` will not add these. For each module the app still boots:

1. Add `"@m5kdev/module-<name>": "catalog:m5kdev"` on the server package.
2. Keep the Managed catalog pin that `m5kdev update` wrote (do not exact-pin a
   different version).
3. Rewrite the import and keep `createBackendApp` (no `backendApp.use`).

**Pdf**

```ts
import { createBackendApp } from "@m5kdev/backend/app";
import { PdfModule } from "@m5kdev/module-pdf";

createBackendApp(config, [new PdfModule()]);
```

**Docx** — `@m5kdev/module-docx`, `new DocxModule()`.

**Video** — `@m5kdev/module-video`, `new VideoModule()`. Set `FFMPEG_PATH` if
ffmpeg is not on `PATH`. `uuid` and `ffmpeg-ffprobe-static` install with that
package.

**Social** — `@m5kdev/module-social`. `dependsOn` Connection (`id` `connect`)
and File in the Kernel:

```ts
import { createBackendApp } from "@m5kdev/backend/app";
import { ConnectModule } from "@m5kdev/backend/modules/connect/connect.module";
import { FileModule } from "@m5kdev/backend/modules/file/file.module";
import { createLinkedInProvider } from "@m5kdev/backend/modules/connect/connect.linkedin";
import { SocialModule } from "@m5kdev/module-social";
import { createLinkedInSocialProvider } from "@m5kdev/module-social/social.linkedin";

createBackendApp(config, [
  new SocialModule([createLinkedInSocialProvider()]),
  new ConnectModule([createLinkedInProvider()]),
  new FileModule(),
]);
```

File still `dependsOn` Auth. Missing `connect` or `file` throws the existing
`Backend module "social" is missing required dependency "..."` error.

**Clay** — `@m5kdev/module-clay`. `dependsOn` Inbound callback (`id` `webhook`):

```ts
import { createBackendApp } from "@m5kdev/backend/app";
import { WebhookModule } from "@m5kdev/backend/modules/webhook/webhook.module";
import { ClayModule } from "@m5kdev/module-clay";

createBackendApp(config, [
  new ClayModule({
    tables: {
      enrichment: { webhookUrl: "https://api.clay.com/v3/sources/webhook/..." },
    },
  }),
  new WebhookModule(),
]);
```

Missing `webhook` throws `Backend module "clay" is missing required dependency "webhook"`.

### 6. Install — Manual

```sh
pnpm install
```

Do not follow with `pnpm update --latest`.

## Database migration

No Kernel-merged schema. App schema remains the composition root.

- **Crypto:** if `crypto_payments` was in App schema, generate and apply a drop
  migration with the project command (Starter: `pnpm --filter ./apps/server drizzle:generate` then `drizzle:migrate`).
- **Notifications / Workflows / Files:** only if you **removed** those table
  exports from App schema. Generate after the schema edit. If you still boot
  those Core Modules, keep the exports — do not drop live tables.
- Do not hand-edit SQL.

## Environment and deployment changes

No new required env for the split itself.

| Variable | When |
| --- | --- |
| `FFMPEG_PATH` | Video Optional package, if ffmpeg is not on `PATH` |
| `CLAY_WEBHOOK_AUTH_TOKEN` | Clay, optional `x-clay-webhook-auth` header |
| `REDIS_URL` | Still required when `WorkflowModule` is registered |
| Push / VAPID / APNs / FCM | Only when `NotificationModule` is registered |

Deploy Kernel and any `@m5kdev/module-*` dependencies together so doctor
lockstep holds in production installs.

## Verification

- `pnpm install` succeeds with `catalogMode: strict`.
- `pnpm check-types` on the server: no imports from
  `@m5kdev/backend/modules/{pdf,docx,video,social,clay,access,crypto,utils}/*`.
- `createBackendApp` still boots. Optional modules you added appear in
  `built.modules`.
- `m5kdev doctor` has no `CATALOG_VERSION_MISMATCH` for Kernel or Optional pins.
- Apps that kept Workflow: Redis still required; jobs enqueue.
- Apps that dropped Crypto: `crypto_payments` gone after migrate.

```sh
pnpm install
pnpm check-types
pnpm dlx create-m5kdev@0.34.0 doctor
```

In this repo, Kernel seam tests cover Pdf/Docx/Video/Social/Clay registration
and missing-dep errors (`packages/backend/src/kernel-infrastructure.test.ts`).

## Rollback

- **Packages:** pin the previous `@m5kdev/backend` line. Optional packages will
  not resolve; restore Kernel imports of `./modules/pdf/*` and the rest.
- **Catalog:** restore the previous `catalogs.m5kdev` snapshot. Leftover
  `@m5kdev/module-*` keys are unused on an older Kernel.
- **Schema:** Crypto drop migrations are forward-only; restore from backup if
  you need `crypto_payments` data.
- **Features:** restoring `.m5kdev.json` features without restoring file
  content does not put Workflow registration back — restore `app.ts` / `schema.ts`
  from git.

## Troubleshooting

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| Cannot find module `@m5kdev/backend/modules/pdf/pdf.module` (or docx/video/social/clay) | Kernel export removed | Install `@m5kdev/module-<name>` and import from that package |
| `Backend module "social" is missing required dependency "connect"` / `"file"` | Social without Connection or File | Register `ConnectModule` (`id` `connect`) and `FileModule` (File still needs Auth) |
| `Backend module "clay" is missing required dependency "webhook"` | Clay without Inbound callback | Register `WebhookModule` (`id` `webhook`) |
| `CATALOG_VERSION_MISMATCH` on `@m5kdev/module-clay` | Optional pin ≠ Kernel release | `m5kdev update`; use `catalog:m5kdev`, not an exact different version |
| `create-m5kdev` prompt has no clay/social/pdf | Intended | Add Optional packages by hand |
| Workflow disappeared from `app.ts` after update | `workflows` not in managed features | Add the feature id, restore registration, re-run update |
| Notification tables queued for drop | `notifications` not in features and schema lost the exports | Restore exports or add the feature **before** generating a drop migration |
| ffmpeg / `pdf-parse` missing on the server | Vendor libs left the Kernel | Depend on `@m5kdev/module-video` / `@m5kdev/module-pdf` |
| AccessModule import fails | Deleted | Use Grants / `accessGuard`; do not reintroduce Better Auth `createAccessControl` |

## Complete upgrade checklist

- [ ] `create-m5kdev` and `@m5kdev/backend` / `@m5kdev/commons` on the same release line
- [ ] `.m5kdev.json` features include `workflows` / `notifications` / `files` if those Core Modules or tables must stay
- [ ] `m5kdev update --dry-run` reviewed; then `m5kdev update`
- [ ] No imports from removed Kernel `./modules/{pdf,docx,video,social,clay,access,crypto,utils}/*`
- [ ] Base / query helpers use `@m5kdev/backend/base/*` (or the `modules/base` re-export)
- [ ] AccessModule and CryptoModule gone; `crypto_payments` dropped only via generated SQL if it existed
- [ ] Each still-used Optional module is `catalog:m5kdev` on the server and registered in `createBackendApp`
- [ ] Social has Connection + File; Clay has Inbound callback (`webhook`)
- [ ] `pnpm install` + `pnpm check-types` pass
- [ ] `m5kdev doctor` is clean for managed catalog keys
- [ ] No `pnpm update --latest` for stack libraries
