# N Prices, frozen Organization currency, and Trial Price at start in 0.38.9

## Summary

A Plan lists 1..N Prices under a Stripe Product per currency. Organization
currency is frozen at create. The catalog names a Trial Plan per currency. When
Trial does not require a card, Kernel starts Trial on that Product's
`defaultPriceId` at Organization create. When it does, Checkout starts Trial
and collects the payment method. Convert bills the Price chosen at start.

There is **no** `create-m5kdev` registry transform. Schema generation is
**Manual**. Capability docs: [Billing module](/modules/billing). Decision:
ADR-0019 (`docs/adr/0019-billing-prices-per-currency-product.md`) and
ADR-0020 (`docs/adr/0020-trial-price-at-start-card-catalog-switch.md`).

## Who needs this migration

- **Every app that registers `BillingModule`.** Catalog types,
  `getEnvironmentPlans`, constructor rules, Trial start, and Plan UI all
  change.
- **Apps whose catalog still uses `priceId` / `annualDiscountPriceId` /
  `StripePlansConfig.currency` / a string `trialPlanName`.** Boot fails until
  those fields match 0.38.9.
- **Apps that pass `BillingPlanSelect` / `BillingSinglePlanSelect`.** Amounts
  come from Organization currency Prices, not a single catalog `priceUnitAmount`.

No action if the app never registered Billing. `create-m5kdev` `billing` still
records the feature id only and does **not** scaffold `BillingModule`.

## Prerequisites and upgrade order

Complete the [0.38.0 upgrades](/#upgrade-0-38-0) first, including
[Organization Stripe paywall](/guides/v0.38.0-billing-org-paywall-migration).

1. Commit or stash application changes.
2. Upgrade `@m5kdev/commons`, `@m5kdev/backend`, `@m5kdev/frontend`,
   `@m5kdev/web-ui`, and `create-m5kdev` together (Managed catalog lockstep).
3. Rewrite the Plan catalog and pass `getEnvironmentPlans(...)` to
   `BillingModule`.
4. Generate and apply Drizzle migrations.
5. Pass Organization currency (and Trial Plan props when a card is required) to
   Plan UI.

Always invoke an exact CLI release:

```sh
pnpm dlx create-m5kdev@0.38.9 update --dry-run
```

## What changed

### Catalog

`StripePlansConfig.currency` becomes required `defaultCurrency`.
`trialPlanName` is `Record<currency, Plan name>` (omit or `{}` for no Trial).
Optional `trialRequiresPaymentMethod` defaults **false**. `StripePlan` drops
`priceId` / `annualDiscountPriceId` / `priceUnitAmount` /
`annualPriceUnitAmount`. Each Plan has
`products: Record<currency, { id, prices[], defaultPriceId? }>`. A Price is
`{ priceId, interval, intervalCount, unitAmount? }`.

Constructor: every Plan still needs a Product for `defaultCurrency`. For each
currency in `trialPlanName`, that Plan must exist and have a Product for that
currency. When `trialRequiresPaymentMethod` is false, that Product must set
`defaultPriceId` to a Price on it. Seat billing still throws without positive
`freeTrial.seats` on each Trial Plan.

`getEnvironmentPlans` returns `ResolvedStripePlans` (`plans`, `trialPlanName`,
`trialRequiresPaymentMethod`, `defaultCurrency`, `seatBilling`,
`nonBillableRoleKeys`). It does not flatten a single `trial` Plan.

### Trial start

- Card off: `createOrganizationHook` creates the Customer and, when a Trial
  Plan and default Price exist for Organization currency, Stripe
  `subscriptions.create` with `trial_period_days`. Access immediately. Convert
  bills that Price. Fail-open if Stripe is down or the currency is absent from
  the Trial Plan map.
- Card on: Organization create may still create the Customer; it does **not**
  create a Trial. Checkout is Owner-only and still 409 while an open
  Subscription exists. Checkout line item is the default Price when set,
  otherwise the requested Price id on the Trial Plan Product. Checkout sets
  `trial_period_days` and `payment_method_collection: always`.

### Organization currency

- `organizations.currency` is frozen at create (payload, `User-Currency` header
  on signup, or `defaultCurrency`). It is never switched. A User may only own
  live Organizations in one currency: omit copies; mismatch is `BAD_REQUEST`;
  after those Organizations are deleted, a new one may pick again.

### HTTP and UI

Checkout, success, Billing Portal, and the webhook stay under `/stripe`. There
is no Interval-pick route. After convert, interval change is Billing Portal.

`BillingPlanSelect` / `BillingSinglePlanSelect` list Prices on the Organization
currency Product. When Trial requires a payment method, pass
`trialRequiresPaymentMethod` and the Trial Plan name: a default Price is a
single Checkout CTA; otherwise each Trial Price is Checkout.

## Dependency and catalog changes

No new third-party dependencies. `stripe` stays an app dependency. Pin
`@m5kdev/commons`, `@m5kdev/backend`, `@m5kdev/frontend`, `@m5kdev/web-ui`, and
`create-m5kdev` to **0.38.9** together on the Managed catalog. Do not
`pnpm update --latest`. Root `pnpm-workspace.yaml` catalog and
`packages/cli/root-templates/pnpm-workspace.yaml.tpl` gain no Billing-specific
pins.

Node.js and pnpm engines are unchanged from 0.38.0.

## Migration steps

1. **Manual** — Upgrade catalog pins for `@m5kdev/commons`,
   `@m5kdev/backend`, `@m5kdev/frontend`, `@m5kdev/web-ui`, and
   `create-m5kdev` to `0.38.9`. `pnpm install`.

2. **Automatic** (`m5kdev update` apply, after `--dry-run`) — no registry
   `id` `0.38.9-billing-trial-price-catalog`. Review the dry-run for unrelated
   file policies only.

3. **Manual** — Rewrite the catalog:

```ts
const plansConfig: StripePlansConfig = {
  defaultCurrency: "usd",
  trialPlanName: { usd: "pro", pln: "pro" },
  trialRequiresPaymentMethod: false,
  production: [
    {
      name: "pro",
      products: {
        usd: {
          id: "prod_usd",
          defaultPriceId: "price_usd_month",
          prices: [
            { priceId: "price_usd_month", interval: "month", intervalCount: 1, unitAmount: 3900 },
            { priceId: "price_usd_quarter", interval: "month", intervalCount: 3, unitAmount: 9900 },
            { priceId: "price_usd_year", interval: "year", intervalCount: 1, unitAmount: 34800 },
          ],
        },
        pln: {
          id: "prod_pln",
          defaultPriceId: "price_pln_month",
          prices: [
            { priceId: "price_pln_month", interval: "month", intervalCount: 1, unitAmount: 14900 },
          ],
        },
      },
      freeTrial: { days: 14 },
    },
  ],
  sandbox: [
    /* sandbox Price ids per currency Product */
  ],
};

const resolved = getEnvironmentPlans(plansConfig, process.env.NODE_ENV);
```

   To require a card before access, set `trialRequiresPaymentMethod: true` and
   omit `defaultPriceId` when the Owner should pick a Price before Checkout.

4. **Manual** — Plan UI:

```tsx
<BillingPlanSelect
  plans={resolved.plans}
  currency={organization.currency}
  trialRequiresPaymentMethod={resolved.trialRequiresPaymentMethod}
  trialPlanName={resolved.trialPlanName[organization.currency]}
/>
```

## Database migration

Generate and apply Drizzle migrations with the project's usual command (do not
hand-write SQL):

```sh
pnpm --filter ./apps/server drizzle:generate
pnpm --filter ./apps/server drizzle:migrate
```

Expected schema:

- Add nullable `organizations.currency`
- Add `subscriptions.interval_count`
- Add `subscriptions.interval_picked` (Kernel no longer writes it; you may drop
  it in a later generate)

Apply the migration before serving traffic on the new Billing code.

## Environment and deployment changes

No new required env. `STRIPE_SECRET_KEY` still constructs the Stripe client in
app code. `STRIPE_WEBHOOK_SECRET` still verifies Billing webhooks.

Roll schema first in each environment, then the new `@m5kdev/*` processes.

## Verification

- App boot succeeds. Constructor throws
  `Trial Plan <name> requires a default Price for <currency>` when card is off
  and a Trial Product has no `defaultPriceId`.
- Creating an Organization writes `organizations.currency` and, when the Trial
  Plan map includes that currency and a card is not required, a local
  Subscription with status `trialing` on the default Price.
- Card-on catalogs create no Trial at Organization create;
  `getActiveSubscription` is `null` until Checkout.
- Owner Checkout of a Trial Price sets `trial_period_days` and collects a card
  when `trialRequiresPaymentMethod` is true.
- Plan UI amounts use Organization currency.

In this repo: `packages/backend/src/modules/billing/tests/billing.service.test.ts`.

Consumer checks after generate/migrate: `pnpm install`, package `check-types` /
`lint` / `test` / `build` as you already run them.

## Rollback

Pin the previous `@m5kdev/*` line **only** if you have not applied the Drizzle
migration, or after restoring a backup that still lacks `organizations.currency`.
Keep the rewritten catalog if you stay on 0.38.9 UI; older `BillingPlanSelect`
expected `plan.priceId` / `plan.priceUnitAmount`.

## Troubleshooting

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| `Trial Plan … requires a default Price` | Card-off Trial Product omitted `defaultPriceId` | Set `defaultPriceId` or turn `trialRequiresPaymentMethod` on |
| `Plan … is missing Product for defaultCurrency` | Catalog has no Product for `defaultCurrency` | Add that Product (and Prices) on every Plan |
| `Trial Plan … not found` | `trialPlanName` map names a Plan that is not in `plans` | Match names or drop that currency from the map |
| Plan page after Organization create (card off) | Currency missing from `trialPlanName`, Stripe down, or no default Price at runtime | Fail-open: fix the catalog or retry Trial after Stripe recovers |
| Checkout 409 | An open Subscription already exists | Use Billing Portal after convert; do not start a second Subscription |
| Invite fails with Trial cap | Seat billing on and live billable Memberships already equal `freeTrial.seats` | Convert in Billing Portal or raise the Trial cap in the catalog |
