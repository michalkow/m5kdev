# listUserOrganizations closedAt in 0.40.3

## Summary

0.40.1 added `organizations.closedAt` to the simple organization DTO. The live
list query filtered `closed_at IS NULL` but omitted the column from its
explicit select, so Drizzle returned `closedAt: undefined` and tRPC output
validation failed (`expected date, received undefined`). Setup screens that
call `auth.listUserOrganizations` die after boot.

0.40.3 selects `closedAt`. Live rows still have `closedAt: null`. Do not drop
the field from `output.simple`. No constructor, schema, or bootstrap source
change.

There is **no** `create-m5kdev` registry transform. Close/Restore/Purge remains
[0.40.1](/guides/v0.40.1-close-restore-purge-migration). Drop any
`@m5kdev/backend@0.40.2` pnpm patch for this select.

## Who needs this migration

- **Every app on 0.40.1 or 0.40.2 that calls `auth.listUserOrganizations`.**
  Setup and org switchers fail until the pins move to 0.40.3.
- **Apps that patched `@m5kdev/backend@0.40.2` locally** to add `closedAt` to
  that select. Remove the patch after the 0.40.3 pin.

No action if the app never installed 0.40.1.

## Prerequisites and upgrade order

Complete [Close, Restore, and Purge in 0.40.1](/guides/v0.40.1-close-restore-purge-migration)
and [Auth and Workflow boot cycle in 0.40.2](/guides/v0.40.2-auth-workflow-cycle-migration)
first if those still apply.

1. Commit or stash application changes.
2. Upgrade every `@m5kdev/*` package and `create-m5kdev` together to **0.40.3**.
3. Remove any `patchedDependencies` entry for `@m5kdev/backend@0.40.2`.
4. Redeploy backend.

Always invoke an exact CLI release:

```sh
pnpm dlx create-m5kdev@0.40.3 update --dry-run
```

## What changed

- `AuthOrganizationRepository.listUserOrganizations` selects
  `organizations.closedAt` with the other simple DTO columns.
- `organizationSchemas.output.simple` still requires `closedAt`
  (`z.date().nullable()`). Hiding Closed rows with `WHERE closed_at IS NULL`
  is not the same as omitting the field.

`new AuthModule()` is unchanged.

## Migration steps

1. **Manual** — Upgrade catalog pins for `@m5kdev/commons`, `@m5kdev/backend`,
   `@m5kdev/frontend`, `@m5kdev/web-ui` to `0.40.3`. `pnpm install`.
