# Kernel Database commands in 0.34.0

:::note Open question
Confirm the published release number before linking this guide from release
notes. Packages in the monorepo currently report `0.33.0`; rename the file and
`migration.id` / `target_version` if the ship version differs from `0.34.0`.
:::

## Summary

Database command implementations (reset, sync, seed runner, script client, guard)
used to ship as Starter Template copies. They now live in the Kernel as `runDb`.
The app owns Database config (`db.ts`) that passes App schema and optional seed.
drizzle-kit generate/migrate/studio and migration SQL stay in the app.
`defineDrizzleKitConfig` owns Turso vs sqlite kit defaults.

`createBackendApp` is **not** used for these commands — no HTTP, Redis, or queues.

There is **no** `create-m5kdev` registry transform. File add/delete is the existing
`m5kdev update` reconciler (`ensure` for Database config and kit helper).

## Who needs this migration

- New apps scaffolded on this release already have Database config.
- Existing apps that copied `drizzle/reset.ts`, `sync.ts`, `seed.ts`, `guard.ts`,
  or `drizzle/db.ts` must switch to Kernel `runDb`.
- Apps that only use drizzle-kit generate/migrate/studio still replace kit config
  with the Kernel helper.

## Prerequisites and upgrade order

1. Commit or stash application changes.
2. Upgrade `@m5kdev/backend` and `create-m5kdev` together (Managed catalog lockstep).
3. Run `m5kdev update --dry-run`, then `m5kdev update`.
4. Port any customized ops-script behavior onto `runDb` knobs or the seed callback.
5. Run `drizzle:migrate` and `drizzle:seed` to verify.

Always invoke an exact CLI release once the number is confirmed.

## What changed

- Kernel exports `runDb` and `defineDrizzleKitConfig` from `@m5kdev/backend/db`.
- Starter Database config is `apps/server/db.ts`. Test-harness e2e seed is
  `apps/server/db.e2e.ts`.
- Named scripts `drizzle:reset` / `drizzle:sync` / `drizzle:seed` invoke Database
  config with a command argument. generate/migrate/studio still call drizzle-kit.
- Template policy `ensure` for Database config and kit helper. Migration SQL/meta
  stay `ignore`.
- Unmodified old ops files are deleted on update. Customized copies conflict.

## Dependency and catalog changes

No new third-party dependencies. `@m5kdev/backend` and `create-m5kdev` move
together on the Managed catalog. `drizzle-kit` remains an app devDependency.

## Starter and template file changes

| Path | Action |
| --- | --- |
| `apps/server/db.ts` | Add (ensure). App schema + raw demo seed + `runDb`. |
| `apps/server/db.e2e.ts` | Add when test-harness is enabled (ensure). Strip when disabled. |
| `apps/server/drizzle.config.ts` | Replace with `defineDrizzleKitConfig({ schema: "./src/schema.ts" })` (ensure). |
| `apps/server/package.json` | Point `drizzle:reset` / `sync` / `seed` at `db.ts <command>`. |
| `apps/server/drizzle/db.ts` | Delete if unmodified. |
| `apps/server/drizzle/guard.ts` | Delete if unmodified. |
| `apps/server/drizzle/reset.ts` | Delete if unmodified. |
| `apps/server/drizzle/sync.ts` | Delete if unmodified. |
| `apps/server/drizzle/seed.ts` | Delete if unmodified; move demo inserts into `db.ts` seed. |
| `apps/server/drizzle/seed.e2e.ts` | Delete; replaced by `db.e2e.ts`. |
| `apps/server/src/schema.ts` | Keep as the App schema composition root. |

## Migration steps

1. **Automatic** — `m5kdev update` adds `db.ts` / kit helper when missing, updates
   untouched kit config, deletes unmodified ops files.
2. **Manual** — If update conflicts on a customized ops file, keep the extra
   behavior by passing `runDb` knobs (`emailOutputDirectory`, `skipGuard`, `port`)
   or by putting inserts in the seed callback, then drop the old file.
3. **Manual** — Replace kit config:

```ts
import { defineDrizzleKitConfig } from "@m5kdev/backend/db";

export default defineDrizzleKitConfig({ schema: "./src/schema.ts" });
```

4. **Manual** — If `db.ts` was added empty of your seed, copy your previous
   `drizzle/seed.ts` inserts into the `seed` callback. Kernel already runs guard
   and remote sync.
5. **Conditional** — Test-harness apps use `tsx db.e2e.ts seed` instead of
   `drizzle/seed.e2e.ts`.

## Database migration

None. Table definitions are unchanged. Do not hand-write SQL. Run
`drizzle:generate` only if App schema TypeScript changed.

## Environment and deployment changes

Same variables: `DATABASE_URL`, `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN`,
`PORT`, `SKIP_DB_GUARD`, `EMAIL_OUTPUT_DIRECTORY`, `DRIZZLE_ENV_PATH`.
No new required env.

## Verification

- `pnpm --filter @m5kdev/backend test src/db.test.ts` in this repo.
- In the app: `pnpm --filter ./apps/server drizzle:reset` then `drizzle:migrate`
  then `drizzle:seed` with the HTTP Kernel **stopped**.
- `drizzle:reset` must fail while the server holds a `file:` database unless
  `SKIP_DB_GUARD=true`.
- `drizzle-kit generate` still writes SQL under `apps/server/drizzle/`.

## Rollback

Revert the `@m5kdev/backend` bump and restore the previous ops scripts from git.
Do not restore deleted sqlite files from this command; restore from backup.

## Troubleshooting

- **Unknown Database command** — scripts must pass `reset`, `sync`, or `seed` as
  a positional argument to `db.ts`.
- **seed requires a seed callback** — Database config called `seed` without a
  `seed` function.
- **Update conflict on `drizzle/reset.ts`** — the file was customized; port knobs
  then delete it.
- **Redis required for seed** — Database commands must not import `app.ts`.
