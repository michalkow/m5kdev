# Kernel Fly deploy commands in 0.35.0

## Summary

Fly deploy and secrets wrappers used to ship as identical Starter copies under
`apps/shared/scripts` and `apps/landing/scripts`. They now live in the Kernel as
`runFlyDeploy` / `runFlySecrets`, exposed as `m5kdev-fly-deploy` /
`m5kdev-fly-secrets`. Root `app:deploy` / `app:secrets` / `landing:deploy` /
`landing:secrets` stay the operator entrypoints and only pass path args.

Dockerfiles, `fly.toml`, and `.env.production` remain app-owned. The `fly` CLI
must still be on PATH.

There is **no** `create-m5kdev` registry transform. File delete and root
`package.json` merge are the existing `m5kdev update` reconciler.

## Who needs this migration

- New apps scaffolded on this release already use Kernel bins.
- Existing apps that still have `apps/*/scripts/fly-deploy.mjs` or
  `fly-secrets.mjs` must switch root scripts to the bins and drop unmodified
  copies.
- Apps that deploy elsewhere and never used these scripts can ignore this
  guide.

## Prerequisites and upgrade order

Complete [Docker, Fly.io, and Node 24 in 0.34.0](./v0.34.0-fly-deploy-migration.md)
first if you are still on Node 22 or lack Deploy home / Landing files.

1. Commit or stash application changes.
2. Upgrade `@m5kdev/backend` and `create-m5kdev` together (Managed catalog
   lockstep).
3. Run `m5kdev update --dry-run`, then `m5kdev update`.
4. Confirm root scripts call `m5kdev-fly-deploy` / `m5kdev-fly-secrets` and that
   root `devDependencies` includes `@m5kdev/backend`.
5. Run `pnpm app:secrets` / `pnpm landing:secrets` only if you are changing
   runtime secrets; otherwise `pnpm app:deploy` / `pnpm landing:deploy` is
   enough to verify.

Always invoke an exact CLI release:

```sh
pnpm dlx create-m5kdev@0.35.0 update --dry-run
```

## What changed

- Kernel exports Fly helpers from `@m5kdev/backend/fly` and publishes bins
  `m5kdev-fly-deploy` and `m5kdev-fly-secrets`.
- Root `package.json` depends on `@m5kdev/backend` as a **devDependency** so
  those bins resolve from repo-root scripts. Landing does not depend on the
  Kernel.
- Starter no longer ships `apps/shared/scripts/fly-*.mjs` or
  `apps/landing/scripts/fly-*.mjs`. Unmodified copies are deleted on update.
  Customized copies conflict.

## Dependency and catalog changes

No new third-party catalog entries. `@m5kdev/backend` and `create-m5kdev` move
together on the Managed catalog. Root `devDependencies` gains
`"@m5kdev/backend": "catalog:m5kdev"` (deploy tool only; production images still
deploy the server package via `pnpm --filter …/server deploy --prod`).

## Starter and template file changes

| Path | Action |
| --- | --- |
| Root `package.json` scripts | Point `app:deploy` / `app:secrets` / `landing:*` at Kernel bins. |
| Root `package.json` `devDependencies` | Add `@m5kdev/backend` (`catalog:m5kdev`). |
| `apps/shared/scripts/fly-deploy.mjs` | Delete if unmodified. |
| `apps/shared/scripts/fly-secrets.mjs` | Delete if unmodified. |
| `apps/landing/scripts/fly-deploy.mjs` | Delete if unmodified. |
| `apps/landing/scripts/fly-secrets.mjs` | Delete if unmodified. |
| `apps/shared/Dockerfile`, `fly.toml`, `.env.production.example` | Unchanged ownership. |
| `apps/landing/Dockerfile`, `fly.toml`, `.env.production.example` | Unchanged ownership. |

## Migration steps

1. **Automatic** (`m5kdev update` apply, after `--dry-run`) — merges root
   `package.json` when unmodified enough for a clean three-way merge; deletes
   unmodified Fly wrapper scripts.
2. **Manual** — If update conflicts on a customized wrapper, port any extra
   behavior into a local script that still calls `m5kdev-fly-deploy` /
   `m5kdev-fly-secrets`, or call `runFlyDeploy` / `runFlySecrets` from
   `@m5kdev/backend/fly`, then delete the old file.
3. **Manual** — If root `package.json` did not pick up the Kernel
   `devDependency` or bin scripts, set:

```json
"scripts": {
  "app:deploy": "m5kdev-fly-deploy --config apps/shared/fly.toml --dockerfile apps/shared/Dockerfile --env apps/shared/.env.production",
  "app:secrets": "m5kdev-fly-secrets --config apps/shared/fly.toml --env apps/shared/.env.production",
  "landing:deploy": "m5kdev-fly-deploy --config apps/landing/fly.toml --dockerfile apps/landing/Dockerfile --env apps/landing/.env.production",
  "landing:secrets": "m5kdev-fly-secrets --config apps/landing/fly.toml --env apps/landing/.env.production"
},
"devDependencies": {
  "@m5kdev/backend": "catalog:m5kdev"
}
```

4. **Manual** — `pnpm install` so the bins link, then verify deploy.

## Database migration

None. Table definitions are unchanged. Do not hand-write SQL.

## Environment and deployment changes

Same `.env.production` contract as 0.34.0. No new required env. Operator still
needs the `fly` CLI on PATH.

## Verification

- `pnpm --filter @m5kdev/backend test src/fly.test.ts` in this repo.
- In the app: root `package.json` scripts contain `m5kdev-fly-deploy` /
  `m5kdev-fly-secrets`; `apps/*/scripts/fly-*.mjs` are gone.
- A missing `.env.production` still errors with the copy-the-example message.
- `pnpm app:deploy` / `pnpm landing:deploy` succeed when Fly credentials and
  env files are present.

## Rollback

Revert the `@m5kdev/backend` / `create-m5kdev` bump and restore the previous
wrapper scripts and root scripts from git. Fly apps and volumes are unchanged.

## Troubleshooting

- **`m5kdev-fly-deploy: command not found`** — ensure root
  `devDependencies` includes `@m5kdev/backend` and run `pnpm install`.
- **Update conflict on `fly-deploy.mjs`** — the file was customized; port
  behavior then delete it.
- **Missing `.env.production`** — copy the sibling `.env.production.example`.

## Complete upgrade checklist

- [ ] Upgrade `@m5kdev/backend` and `create-m5kdev` together

- [ ] Root scripts use Kernel bins; root has `@m5kdev/backend` as a
