# Inventoried File 1.0 in 0.40.0

## Summary

File 1.0 is always a `files` row plus the S3 object at `(bucket, key)`. Clients
initiate (insert `PENDING`, receive a presigned PUT URL), PUT bytes to S3, then
finalize (`UPLOADED`). Cookie UIs download with `GET /files/:id` (Grant `read`,
then 302). Cookieless Actors call tRPC `getDownloadUrl`. Other entities store
File id, not keys or presigned URLs.

Removed: Multer `POST /upload/file/:type`, unauthenticated S3-by-key GET/DELETE,
`POST /upload/s3-presigned-url`, and `useS3Upload` that returned an S3 URL.
`FileModule`'s first argument is a config object, not a mount path.
`files.teamId` is dropped.

There is **no** `create-m5kdev` registry transform. Schema generation is
**Manual**. Capability docs: [File](/modules/file). Decision: ADR-0030
(`docs/adr/0030-file-is-inventoried-s3-object.md`).

## Who needs this migration

- **Every app that registers `FileModule`.** Upload HTTP, File tRPC, and
  frontend hooks change. Typecheck fails until callers move to Procedures and
  File id.
- **Apps that stored a presigned URL or S3 key** on another table. Store File
  id and construct `/files/${id}`.
- **Apps that called `useS3Upload(serverUrl)`**, `useUpload`, or
  `AvatarUpload` / `FileDropzone` expecting an S3 URL from `onUploadComplete`.
- **Apps that constructed `new FileModule("/upload")`.** The first argument is
  now `FileModuleConfig`.

No action if the app never registered File. New apps scaffolded on this release
already use initiate → PUT → finalize.

## Prerequisites and upgrade order

Complete [0.39.0 MCP as tRPC](/guides/v0.39.0-mcp-trpc-catalog-migration) first
if you use MCP. On the 0.40.0 bump, File schema (`DROP team_id`) shares **one**
Drizzle generate with any other 0.40.0 schema work.

1. Commit or stash application changes.
2. Upgrade every `@m5kdev/*` package and `create-m5kdev` together to **0.40.0**
   (Managed catalog lockstep). Do not mix 0.39.x and 0.40.0.
3. Replace File HTTP and hook callers with Procedures.
4. Generate and apply Drizzle migrations (`files.team_id` drop).
5. Point stored avatar / attachment columns at File id.

Always invoke an exact CLI release:

```sh
pnpm dlx create-m5kdev@0.40.0 update --dry-run
```

## What changed

- `FileModule` constructor is `new FileModule({ buckets, deleteAfterDays, fileTypes, grants, downloadPath })`. `new FileModule()` with defaults still boots. `new FileModule("/upload")` is invalid.
- File optional-depends on Workflow. When Workflow is registered, daily cron `file.purge` (`0 0 * * *`) deletes S3 for `DELETED` older than `deleteAfterDays` (default 30, min 1) and marks `PENDING` older than one day `FAILED`. Without Workflow, `delete` removes the S3 object in the same request.
- tRPC: `file.*` (organization) and `file.user.*` (personal). Procedures: `list`, `get`, `initiate`, `finalize`, `getDownloadUrl`, `update` (`originalName` / `metadata` only), `delete`. `list` / `get` return only `UPLOADED` rows. `get` does not return a download URL.
- Express File HTTP is only `GET /files/:id` (cookie session, Actor from the File's Organization, Grant `read`, 302). Gone: `POST /upload/file/:type`, `GET /upload/file/:filename`, `GET /upload/files/:path`, `DELETE /upload/files/by-id/:fileId`, `POST /upload/s3-presigned-url`, `DELETE /upload/files/:path`.
- `useS3Upload({ scope: "organization" | "user" })` runs initiate → PUT → finalize and returns **File id**. It no longer takes a server URL positional argument or a key prefix. `uploadedUrl` is gone. Cookieless download: `useFileDownloadUrl`. Cookie display: `fileCookieDownloadUrl` / `fileDisplayUrl`.
- `AvatarUpload` and `FileDropzone` `onUploadComplete` receive File id. Store that id; display with `fileDisplayUrl` (HTTP(S) OAuth avatars still pass through).
- Other Services use unguarded `putObject` / `getObject` (still invent or load a row). Routers must not call them. `recordLocalUpload` is gone.
- `files.team_id` is dropped. Unique `(bucket, key)` stays.

## Migration steps

1. **Manual** — Upgrade catalog pins for `@m5kdev/commons`, `@m5kdev/backend`,
   `@m5kdev/frontend`, `@m5kdev/web-ui` to `0.40.0`. `pnpm install`.
2. **Automatic** (`m5kdev update` apply, after `--dry-run`) — may merge Starter
   Files UI and `app.ts` File registration if those paths are merge-clean. There
   is no registry `id` `0.40.0-inventoried-file`.
3. **Manual** — Register File with a config object if you need buckets or
   retention:

   ```ts
   new FileModule({
     buckets: [process.env.AWS_S3_BUCKET!],
     deleteAfterDays: 30,
   })
   ```

   Register `WorkflowModule` when you want delayed S3 purge. `deleteAfterDays`
   below 1 throws at boot when Workflow is present.
4. **Manual** — Stop mounting or calling `/upload/*`. Replace client uploads:

   ```ts
   const { upload } = useS3Upload({ scope: "organization" });
   const fileId = await upload(file);
   ```

   Personal Files (user avatar) use `scope: "user"` (`file.user.*`).
5. **Manual** — Replace stored S3 URLs with File id. Cookie UIs:

   ```ts
   fileCookieDownloadUrl(serverUrl, fileId)
   ```

   Cookieless Actors call `useFileDownloadUrl` / tRPC `getDownloadUrl`.
6. **Conditional** (other Services wrote S3 or disk bytes) — call
   `services.file.putObject` / `getObject` with ownership stamps. Do not call
   them from routers or tRPC.
7. **Conditional** (`AvatarUpload` / `FileDropzone`) — `onUploadComplete`
   now receives File id. Persist that column; `fileDisplayUrl` treats leftover
   `https://` OAuth avatars as pass-through.
8. **Manual** — Generate Drizzle migrations with the project's usual command
   (`pnpm --filter <server> drizzle:generate`). Do not hand-write SQL. Apply
   before serving 0.40.0 File code. Expected File schema: `files` without
   `team_id`.
9. **Conditional** (custom CORS) — keep `PUT` in `methods` and `Content-Type`
   in `allowedHeaders` so browser PUT to `/file-s3-mock` (dev) works. Production
   also needs S3 bucket CORS for the web origin.

## Database migration

Schema change. **Do not** create Drizzle migration files by hand. Run:

```sh
pnpm --filter <server-package> drizzle:generate
pnpm --filter <server-package> drizzle:migrate
```

Expected change: drop `files.team_id`. Unique index `files_bucket_key_unique`
stays. There is **no data backfill**. Existing `UPLOADED` rows remain valid.
Rows that only existed as local Multer disk files without an S3 object will not
download until re-uploaded through initiate → PUT → finalize.

## Environment and deployment changes

No new required variable names. Production File still needs:

```sh
AWS_REGION=...
AWS_ACCESS_KEY_ID=...
AWS_SECRET_ACCESS_KEY=...
AWS_S3_BUCKET=...
AWS_S3_ENDPOINT=...   # optional, S3-compatible
VITE_SERVER_URL=...   # API origin for `/files/:id` and mock S3
```

- **`NODE_ENV=production`** uses AWS S3 and does not mount `/file-s3-mock`.
  `pnpm dev` uses `LocalFileObjectStore` plus mock S3 HTTP.
- **S3 bucket CORS** must allow browser `PUT` (and `GET` after 302) from the
  web origin, including `Content-Type`.
- **Rollout order** — apply the Drizzle migration, then deploy backend (so
  `GET /files/:id` exists), then web (hooks that PUT to presigns). Old web
  against new backend will 404 on `/upload/*`.
- **Workers** — when Workflow is registered, the `file.purge` cron runs on the
  worker. Without Workflow, delete is in-request; stale `PENDING` rows may
  linger until Workflow exists.

## Verification

In this repo:

```sh
pnpm --filter @m5kdev/backend exec jest -c jest.config.ts src/modules/file --no-coverage
pnpm --filter @m5kdev/frontend exec jest -c jest.config.ts src/modules/file --no-coverage
```

In the app:

- Typecheck fails on `new FileModule("/upload")`, `useUpload`,
  `/upload/s3-presigned-url`, and `onUploadComplete` expecting an S3 URL.
- Starter (or equivalent) `/files`: upload a PNG, row appears, open href is
  `/files/<uuid>` on the API origin, delete hides the row.
- `GET /files/:id` with a cookie 302s; logged-out GET is denied.
- `pnpm check-types` / `pnpm lint` succeed.

## Rollback

Revert the `@m5kdev/*` / `create-m5kdev` pins to 0.39.0 and restore previous
File callers from git. After `files.team_id` is dropped, 0.39.0 File schema
expects that column: restore it only from backup or a forward additive
migration. Prefer staying on 0.40.0 and re-uploading files that never had an
S3 object.

Do **not** remount Multer `/upload` against 0.40.0 FileModule; that router is
gone.

## Troubleshooting

| Symptom | Cause and fix |
| --- | --- |
| `FileModule` type error on a string argument | First argument is `FileModuleConfig`. Use `new FileModule()` or `{ buckets, deleteAfterDays }`. |
| Browser PUT fails CORS | App CORS dropped `PUT` / `Content-Type`, or the S3 bucket has no CORS for the web origin. |
| Finalize `BAD_REQUEST` / File `FAILED` | PUT never landed (wrong `Content-Type` or CORS). Retry PUT then finalize; do not treat `PENDING` as downloadable. |
| `GET /files/:id` 404 | Row is not `UPLOADED`, or you stored a key/URL instead of File id. |
| Image preview broken with credentials | Remove `crossOrigin="use-credentials"` from `<img src="/files/:id">`; the 302 target is S3. |
| `useS3Upload` no longer returns `uploadedUrl` | Persist `fileId` from `upload()`; display with `fileCookieDownloadUrl` / `fileDisplayUrl`. |
| Delete does not free S3 immediately | Workflow is registered; wait for `file.purge` or lower `deleteAfterDays` (min 1). |
| Drizzle wants to drop `files.team_id` | Expected. Generate and apply; do not hand-edit SQL. |
