# Kernel Express HTTP shell in 0.33.0

:::note Open question
Confirm the published release number before linking this guide from release
notes. Packages in the monorepo currently report `0.32.9`; rename the file and
`migration.id` / `target_version` if the ship version differs from `0.33.0`.
:::

## Summary

`createBackendApp` (the Kernel) now owns the Express HTTP shell:

- Creates Express unless you pass `config.express`.
- Always applies `express.json()` then CORS onto that instance (pass-in included).
- CORS origin is `[app.urls.web]` when set, otherwise `false` (does not reflect
  `Origin`). Library `allowedHeaders` include `Content-Type`, `Authorization`,
  `Waitlist-Invitation-Code`, `Organization-Invitation-Code`,
  `Admin-Create-Verified-User`, and `User-Locale`.
- `start()` listens on `PORT` (fallback `8080`) at `0.0.0.0` unless
  `start({ listen: false })`.
- When listening, SIGINT/SIGTERM closes HTTP, then Kernel shutdown, then
  `onShutdown`, then `process.exit(0)`.

JSON and CORS are maps over defaults: `cors?: (defaults) => next`. Omitting a
default drops it. There is no post-map union of library headers.

Extra HTTP belongs on a Backend Module `express` hook. Extra shutdown work
(telemetry) is `onShutdown` on Kernel config. OTEL init stays
`import "./instrumentation"` first — the Kernel does not own OTEL.

Passing an Express instance that already has json/CORS is unsupported (double
CORS is the caller’s bug).

There is **no** `create-m5kdev` registry transform. Every application step is
**Manual**.

## Who needs this migration

- **Every existing app** that creates Express, calls `express.json()` / `cors()`,
  listens, or registers SIGINT/SIGTERM in `index.ts`.
- Apps that listed library CORS headers in `app.ts` so new headers would not
  require an app edit after this release.

Tests that call `built.start()` must pass `{ listen: false }` or they will bind
`PORT` (fallback `8080`). `NODE_ENV=test` does **not** skip listen.

## Required changes

### 1. Drop Express json/CORS from `app.ts`

Remove `express()`, `express.json()`, `cors()`, and `express: app` unless you
need a pass-in for extra middleware (Helmet, request logging). If you pass
Express, do **not** apply json/CORS first.

Set `app.urls.web` (or `VITE_APP_URL`) so CORS origin matches the web app.

Optional maps:

```ts
export const builtBackendApp = createBackendApp({
  db: connection,
  schema,
  onShutdown: shutdownTelemetry,
  cors: (defaults) => ({
    ...defaults,
    origin: ["https://admin.example.com", appUrl],
  }),
  json: (defaults) => ({ ...defaults, limit: "1mb" }),
  app: {
    urls: { web: appUrl, api: serverUrl },
  },
});
```

To drop a default header, return `allowedHeaders` without it. Spread
`defaults.allowedHeaders` if you are adding headers.

### 2. Shrink `index.ts`

Keep `import "./instrumentation"` first. Call `start()` and log. Do not listen,
do not register SIGINT/SIGTERM, do not call `shutdownTelemetry` from a local
signal handler.

```ts
import "./instrumentation";
import { builtBackendApp } from "./app";

const port = process.env.PORT ? Number.parseInt(process.env.PORT, 10) : 8080;

void (async () => {
  try {
    await builtBackendApp.start();
    console.info(
      `Server running at ${process.env.VITE_SERVER_URL ?? `http://localhost:${port}`}`
    );
  } catch (e) {
    console.error("[server] Fatal: builtBackendApp.start() failed", e);
    process.exit(1);
  }
})();
```

Pass `onShutdown: shutdownTelemetry` in `createBackendApp` (see step 1).

### 3. Extra HTTP and shutdown

Mount extra routes on a module `express` hook, not ad hoc starter middleware.

```ts
express: ({ infra }) => {
  infra.express.get("/health", (_req, res) => {
    res.json({ ok: true });
  });
},
```

Programmatic `shutdown()` uses the same close order as signals but does **not**
`process.exit`. A second `start({ listen: true })` while already listening
throws. A second `shutdown()` is a no-op.

### 4. Remove unused `cors` dependency

If the server package no longer imports `cors`, drop `cors` and `@types/cors`
from `apps/<app>/server/package.json`.

## Upgrade checklist

1. Upgrade `@m5kdev/backend` to the `0.33.0` line.
2. Remove `express.json()` / `cors()` / `express: app` from `app.ts` (or pass
   Express without json/CORS).
3. Move `shutdownTelemetry` to `onShutdown`.
4. Shrink `index.ts` to instrumentation + `start()`.
5. Change tests that call `start()` to `start({ listen: false })` unless they
   intend to bind a port.
6. Drop unused `cors` dependencies.
7. Smoke-test credentialed CORS from the web origin, including admin create-user
   and `User-Locale` preflight.

## Troubleshooting

| Symptom | Likely cause |
| --- | --- |
| Double CORS / missing headers | Pass-in Express already had `cors()`; Kernel applied CORS again. |
| Browser reflects unknown `Access-Control-Request-Headers` | App still uses default `cors()` instead of the Kernel allowlist. |
| Preflight fails for `Admin-Create-Verified-User` or `User-Locale` | CORS map omitted those defaults, or `app.urls.web` does not match the page origin. |
| `start()` binds 8080 in tests | Missing `listen: false`. |
| `EADDRINUSE` after upgrade | `index.ts` still calls `app.listen` after Kernel `start()`. |
| Process does not exit on Ctrl+C | Starter still owns signals and skipped Kernel listen, or `start({ listen: false })` in production. |
