# Organization allowCardlessTrial overlay in 0.38.21

## Summary

Organizations gain `allowCardlessTrial` (column `organizations.allow_cardless_trial`)
and a per-environment consume record (`organizations.cardless_trial_consumed`).
When the catalog requires a card for Trial, AdminActor can waive that for one
Organization: Kernel starts at most one cardless Trial in the current Stripe
environment (picked-at-sign-up Price else default Trial Price). Access still
requires that Trial (or `billingExempt`). New Organizations start false.
Children do not inherit. Kernel does not backfill.

There is **no** `create-m5kdev` registry transform. Schema generation is
**Manual**. Capability docs: [Billing module](/modules/billing). Decision:
ADR-0026 (`docs/adr/0026-organization-allow-cardless-trial.md`).

## Who needs this migration

- **Every app.** `organizations` is an Auth table; the new columns must exist or
  Organization reads fail.
- **Apps that register `BillingModule` with `trialRequiresPaymentMethod: true`.**
  Billing Module admin gains Disable credit card check. Pass
  `trialRequiresPaymentMethod` into `BillingAdminRouter`. `BillingPaywallProvider`
  gates the Owner to Billing Portal when `ownerMustAddPaymentMethod` is true.
- **Apps that already compose `BillingAdminRouter({ plans })` on a card-on
  catalog.** Add `trialRequiresPaymentMethod: resolved.trialRequiresPaymentMethod`
  or the Switch stays hidden.

No action beyond the schema generate if the app never registered Billing, other
than the columns existing so Organization reads succeed.

## Prerequisites and upgrade order

Complete the [0.38.20 upgrade](/#upgrade-0-38-20) first.

1. Commit or stash application changes.
2. Upgrade `@m5kdev/commons`, `@m5kdev/backend`, `@m5kdev/frontend`,
   `@m5kdev/web-ui`, and `create-m5kdev` together to `0.38.21`.
3. Generate and apply the Drizzle migration.
4. If the app registers Billing on a card-on catalog, pass
   `trialRequiresPaymentMethod` into `BillingAdminRouter`.

```sh
pnpm dlx create-m5kdev@0.38.21 update --dry-run
```

## What changed

`allowCardlessTrial` is a dedicated Organization boolean (not `billingExempt`,
not Organization `flags`). Default false. AdminActor `write` Procedure
`billing.setAdminAllowCardlessTrial` (`{ organizationId, allowCardlessTrial }`).
Turning it on without an open Subscription starts Trial and records consume for
this Stripe environment. Turning it on after consume, without resolvable trial
days, or on a card-off catalog is refused. Clearing it keeps the Trial;
`getActiveSubscription` returns `ownerMustAddPaymentMethod` for the Owner when
the catalog requires a card, this environment already consumed a cardless Trial,
the switch is off, status is `trialing`, and there is no default payment method.
Turning the switch on again drops that gate. After Trial ends they Checkout with
a card. Admin Create Subscription with `trialDays` still works.

`cardlessTrialConsumed` is omitted from the public Organization DTO. Sandbox
consume does not consume production.

Grant action names stay `read` / `write`. Custom Billing grants need no edit.

## Dependency and catalog changes

No new dependencies. Pin `@m5kdev/commons`, `@m5kdev/backend`,

## Migration steps

1. **Manual** — Upgrade the packages to `0.38.21`; `pnpm install`.
2. **Automatic** (`m5kdev update` apply, after `--dry-run`) — nothing for this
   id (registry empty).
3. **Manual** — Generate and apply the Drizzle migration (see below).
4. **Conditional** — Card-on Billing apps: pass `trialRequiresPaymentMethod`
   into `BillingAdminRouter`.

```tsx
BillingAdminRouter({
  plans: resolved.plans,
  trialRequiresPaymentMethod: resolved.trialRequiresPaymentMethod,
})
```

## Database migration

Generate and apply with the project's command (do not hand-write migration
files):

```sh
pnpm --filter ./apps/server drizzle:generate
pnpm --filter ./apps/server drizzle:migrate
```

Expected schema:

- `organizations.allow_cardless_trial` integer not null default `0` (boolean)
- `organizations.cardless_trial_consumed` text default `'{}'` (JSON map of
  `production` / `sandbox` to boolean)

Kernel does not UPDATE existing rows. Do not grandfather this flag.

## Environment and deployment changes

No new env vars. Roll the schema first, then processes. The column default is
false, so existing Organizations still require a card for Trial until AdminActor
opts them in.

## Verification

- App boot succeeds; Organization reads do not error on `allow_cardless_trial`
  or `cardless_trial_consumed`.
- A newly created Organization has `allowCardlessTrial` false.
- On a card-on catalog, Billing Module admin shows Disable credit card check.
  Turning it on starts Trial; the paywall stays until that Trial exists.
- Clearing the switch keeps `trialing` access. The Owner sees a full-page
  Billing Portal prompt until they add a card or Admin turns the switch on
  again. Members keep access.
- After that Trial is canceled, turning the switch on again is refused. Admin
  Create with `trialDays` still works.
- A sandbox consume does not block a production cardless Trial.
- `billingExempt` still skips the paywall; this switch does not.

In this repo: `packages/backend/src/modules/billing/tests/billing.service.test.ts`.

## Rollback

The columns are additive; older packages ignore them. Dropping them is a
forward schema change, not a rollback of this release.

## Troubleshooting

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| `no such column: allow_cardless_trial` | Migration not applied | Generate and migrate |
| Switch missing on Billing admin | Catalog is card-off, or `trialRequiresPaymentMethod` was not passed into `BillingAdminRouter` | Pass the resolved catalog flag |
| Owner still in the app after clearing the switch | `BillingPaywallProvider` not wrapping the route, or subscription query stale | Wrap routes; wait for `getActiveSubscription` refetch |
| Second cardless Trial after cancel | App is not on this BillingModule | Confirm `@m5kdev/backend` is 0.38.21 |
| `CONFLICT` turning the switch on | This environment already consumed its cardless Trial | Use Admin Create with `trialDays`, or Checkout with a card |
