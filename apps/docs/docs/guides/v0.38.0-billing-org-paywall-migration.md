# Organization Stripe paywall and opt-in Seat billing in 0.38.0

## Summary

Billing is an opinionated Stripe paywall. The Customer is the
**Organization**, not the User. Auth starts Trial on Organization create
(`createOrganizationHook`), not User signup. Seat billing is a catalog switch
on `StripePlansConfig` and defaults **off**: Trial is `freeTrial.days` only,
Stripe quantity is one, and Membership count is never billed. Access continues
while status is `active`, `trialing`, or `past_due`.

`BillingModule` mounts Checkout, Interval pick, success, Billing Portal, and
the Stripe webhook at `/stripe`. Kernel Plan pages are acquisition; during Trial
they record an Interval pick (including monthly) instead of Checkout. After
paid convert, change Plan or interval in Billing Portal. A Plan lists 1..N
Prices per currency Product; Portal products stay in the Stripe Dashboard.

There is **no** `create-m5kdev` registry transform. Schema generation is
**Manual**. Capability docs: [Billing module](/modules/billing). Decision:
ADR-0017 (`docs/adr/0017-billing-org-paywall-seat-billing-opt-in.md`) and
ADR-0019 (`docs/adr/0019-billing-prices-per-currency-product.md`).

## Who needs this migration

- **Every app that registers `BillingModule`.** Constructor, catalog types,
  Auth Customer column, Subscription `referenceId`, HTTP mount, and tRPC
  procedures all change.
- **Apps that called `createUserHook` / `createUserCustomer`**, keyed
  `getActiveSubscription` by UserId, or stored `users.stripeCustomerId`.
- **Apps that hand-wired `createBillingRouter`.** The module now mounts
  `/stripe` itself.
- **Apps that pass `BillingPlanSelect` / `BillingRouter` / `BillingSinglePlanSelect`.**
  `currency` is required. N-Plan selection is implemented.

No action if the app never registered Billing. `create-m5kdev` `billing` still
records the feature id only and does **not** scaffold `BillingModule`. New apps
that register Billing on this release already use the Organization Customer.

## What changed

### Catalog

`StripePlansConfig` gains required `defaultCurrency`, optional `seatBilling`
(default `false`), and optional `nonBillableRoleKeys`. `StripePlan` drops
unused `limits` / `group` and the old `priceId` / `annualDiscountPriceId`
fields. Each Plan has `products: Record<currency, { id, prices[] }>`; a Price
is `{ priceId, interval, intervalCount, unitAmount? }`. Monthly stand-in is
`interval: "month"` and `intervalCount: 1` on the Organization currency's
Product. `freeTrial.seats` exists only when Seat billing is on and a trial Plan
is selected; the module constructor throws if Seat billing is on and the trial
Plan omits a positive `freeTrial.seats`, or if any Plan is missing a Product
for `defaultCurrency`, or if the trial Plan has no monthly stand-in Price for
`defaultCurrency`.

`getEnvironmentPlans` returns `ResolvedStripePlans` (`plans`, `trial`,
`defaultCurrency`, `seatBilling`, `nonBillableRoleKeys`), not `{ plans, trial }`.
`formatPlanAmount({ unitAmount, currency })` formats catalog cents.
`formatBillingInterval({ interval, intervalCount })` labels month / quarter /
year Prices.

### Organization Customer

- `organizations.stripe_customer_id` (unique). Better Auth extra field on
  Organization, `input: false`. Public Auth organization DTOs omit it.
- `organizations.currency` is frozen at create (payload, `User-Currency`
  header on signup, or `defaultCurrency`). It is never switched. A User may
  only own live Organizations in one currency: omit copies; mismatch is
  `BAD_REQUEST`; after those Organizations are deleted, a new one may pick
  again.
- `users.stripe_customer_id` is removed. Frontend `auth.client` no longer
  infers User `stripeCustomerId`.
- Subscription `referenceId` is `organizationId`. New nullable
  `subscriptions.member_id` is attribution for who created Trial or Checkout.
- Stripe metadata carries `organizationId` and `memberId`. Checkout also sets
  `subscription_data.metadata`.
- Existing User-keyed Customers and `subscriptions.reference_id` User ids are
  **not** mapped. Local paywall reads the Organization row; old User rows look
  like no Subscription.

### Auth and access

- Signup that creates an Organization, `createOrganization`, and account-claim
  accept call `createOrganizationHook`. Organization create succeeds if Stripe
  is down; missing Subscription shows the Plan page.
- Access for `BillingProvider` / `getActiveSubscription` is status in
  `active` | `trialing` | `past_due` (was `active` | `trialing` only).
- tRPC uses `organizationProcedure`. Default grants: Owner `read`/`write` org;
  Admin and Member `read` org, `write` none. User-level own billing is not the
  product path.
- Checkout, Interval pick, and Billing Portal are Owner-only. Checkout
  refuses while a local **or** Stripe open Subscription exists (including
  Trial). During Trial, `GET /stripe/pick/:priceId` updates the Trial item
  (last pick wins, including monthly). Unpicked Trial that converts is
  canceled and access ends. After paid, interval change is Billing Portal.
- Organization delete (`beforeDeleteOrganization`) cancels the Stripe
  Subscription and keeps the Customer.
- Invite, remove, leave, and Role change call Billing seat methods when Seat
  billing is on. Quantity writes are a system call. Role changes that stay
  billable do not touch Stripe. Missing Subscription is a no-op so
  `skipPlanCheck` still allows Membership edits.

### HTTP

`BillingModule.express` mounts `createBillingRouter` at `/stripe`:

| Route | Purpose |
| --- | --- |
| `GET /stripe/checkout/:priceId` | Checkout (Owner) |
| `GET /stripe/pick/:priceId` | Interval pick during Trial (Owner); updates the Trial item |
| `GET /stripe/portal` | Billing Portal (Owner) |
| `GET /stripe/success` | Sync then redirect to `/billing` |
| `POST /stripe/webhook` | Stripe webhook (`STRIPE_WEBHOOK_SECRET`) |

This is Billing, not [Inbound callback](/modules/webhook). Checkout conflict is
HTTP 409.

### UI

`BillingPlanSelect` and `BillingSinglePlanSelect` take Organization
`currency` (frozen at create), not a catalog-wide code. They list every Price
on that currency's Product. During Trial, actions call `/stripe/pick/:priceId`
instead of Checkout. `skipPlanCheck` is unchanged.

## Migration steps

1. **Manual** — Upgrade catalog pins for `@m5kdev/commons`,
   `@m5kdev/backend`, `@m5kdev/frontend`, `@m5kdev/web-ui`, and
   `create-m5kdev` to `0.38.0`. `pnpm install`.

2. **Automatic** (`m5kdev update` apply, after `--dry-run`) — no registry
   `id` `0.38.0-billing-org-paywall`. Review the dry-run for unrelated file
   policies only.

3. **Manual** — Resolve the catalog and pass it to `BillingModule`:

```ts
import Stripe from "stripe";
import { createBackendApp } from "@m5kdev/backend/app";
import { BillingModule } from "@m5kdev/backend/modules/billing/billing.module";
import { EmailModule } from "@m5kdev/backend/modules/email/email.module";
import type { StripePlansConfig } from "@m5kdev/commons/modules/billing/billing.types";
import { getEnvironmentPlans } from "@m5kdev/commons/modules/billing/billing.utils";

const plansConfig: StripePlansConfig = {
  defaultCurrency: "usd",
  trialPlanName: "pro",
  production: [
    {
      name: "pro",
      products: {
        usd: {
          id: "prod_usd",
          prices: [
            { priceId: "price_usd_month", interval: "month", intervalCount: 1, unitAmount: 3900 },
            { priceId: "price_usd_quarter", interval: "month", intervalCount: 3, unitAmount: 9900 },
            { priceId: "price_usd_year", interval: "year", intervalCount: 1, unitAmount: 34800 },
          ],
        },
        pln: {
          id: "prod_pln",
          prices: [
            { priceId: "price_pln_month", interval: "month", intervalCount: 1, unitAmount: 14900 },
          ],
        },
      },
      freeTrial: { days: 14 },
    },
  ],
  sandbox: [
    /* sandbox Price ids per currency Product */
  ],
};

const resolved = getEnvironmentPlans(plansConfig, process.env.NODE_ENV);

createBackendApp(config, [
  new EmailModule(templates),
  new BillingModule({ stripe: new Stripe(process.env.STRIPE_SECRET_KEY!) }, resolved),
]);
```

   Seat billing off (the default) is valid without `freeTrial.seats`. To bill
   Memberships:

```ts
const plansConfig: StripePlansConfig = {
  defaultCurrency: "usd",
  seatBilling: true,
  nonBillableRoleKeys: ["guest"],
  trialPlanName: "pro",
  production: [
    {
      name: "pro",
      products: {
        usd: {
          id: "prod_usd",
          prices: [
            { priceId: "price_usd_month", interval: "month", intervalCount: 1, unitAmount: 3900 },
          ],
        },
      },
      freeTrial: { days: 14, seats: 5 },
    },
  ],
  sandbox: [
    /* sandbox Price ids */
  ],
};
```

   Owner is always billable even if listed in `nonBillableRoleKeys`. Changing
   that list in a later deploy does not rewrite live Stripe quantities.

## Database migration

Generate and apply Drizzle migrations with the project's usual command (do not
hand-write SQL):

```sh
pnpm --filter ./apps/server drizzle:generate
pnpm --filter ./apps/server drizzle:migrate
```

Expected schema:

- Drop `users.stripe_customer_id`
- Add unique `organizations.stripe_customer_id`
- Add nullable `organizations.currency`
- Add nullable `subscriptions.member_id`
- Add `subscriptions.interval_count` and `subscriptions.interval_picked`

There is **no** backfill from User Customer to Organization Customer. After
migrate, existing `subscriptions.reference_id` User ids will not match
`ctx.actor.organizationId`, so Members see the Plan page until each
Organization gets a new Customer and Subscription (create hook, Checkout, or
a later Billing read that creates the Customer). Cancel the old User-keyed
Stripe Subscriptions in the Dashboard so they do not keep charging.

Apply the migration before serving traffic on the new Billing code.

## Environment and deployment changes

No new required env. `STRIPE_SECRET_KEY` still constructs the Stripe client in
app code. `STRIPE_WEBHOOK_SECRET` still verifies Billing webhooks.

Point the Dashboard endpoint that used the Billing router at
`POST {apiUrl}/stripe/webhook`. Include
`customer.subscription.trial_will_end` if you want the Trial warning. The
0.34.0 guide's `POST /webhook` was the router-relative path; with the module
mount it is `POST /stripe/webhook`. Do not send Stripe events to Inbound
callback (`WebhookModule`).

Trial-ending email now uses the Stripe Customer email, not the User row.

Roll schema first in each environment, then the new `@m5kdev/*` processes.
Webhook URL must match before Checkout can complete.

## Verification

- App boot succeeds with `EmailModule` and `BillingModule`. Constructor throws
  `Seat billing Trial requires freeTrial.seats` if Seat billing is on and the
  trial Plan has no seats.
- Creating an Organization writes `organizations.stripe_customer_id` and, when
  `trialPlanName` is set, a local Subscription with `referenceId` equal to that
  Organization id and status `trialing`.
- Stripe down during Organization create does not fail Auth; `getActiveSubscription`
  is `null` and `BillingProvider` shows `planPage`.
- Creating an Organization persists `organizations.currency` from payload,
  `User-Currency`, or `defaultCurrency`, and rejects a mismatch with a live
  owned Organization.
- Auto-Trial uses the monthly stand-in Price for that currency; skip Trial
  (fail-open) when that Product has no monthly Price.
- Owner `GET /stripe/checkout/:priceId` redirects to Stripe; a non-Owner gets
  403; an open Trial gets 409. Price must belong to Organization currency.
- Owner `GET /stripe/pick/:priceId` during Trial updates the Trial item;
  a non-Owner gets 403. Unpicked convert cancels; Interval-picked convert
  keeps the Subscription.
- `GET /stripe/portal` is Owner-only.
- `past_due` does not show the Plan page. `canceled` / missing row does.
- Seat billing off: invite does not call Stripe `subscriptions.update`.
- Seat billing on + paid: invite updates Stripe quantity then creates the
  Membership; `past_due` refuses increases; Interval-picked Trial convert snaps
  quantity down to live billable Memberships.
- Plan UI lists Prices for Organization currency, not a hardcoded `$`.

In this repo: `packages/backend/src/modules/billing/tests/billing.service.test.ts`.

Consumer checks after generate/migrate: `pnpm install`, package `check-types` /
`lint` / `test` / `build` as you already run them.

## Rollback

Pin the previous `@m5kdev/*` line **only** if you have not applied the Drizzle
migration, or after restoring a database backup that still has
`users.stripe_customer_id`. The column move is not reversible from Kernel
code: a forward fix or backup restore is required once User Customer ids are
dropped. Keep Plan catalog `defaultCurrency` and `products` if you stay on
0.38.0 UI; older `BillingPlanSelect` expected a single catalog currency.

Do not re-create User-keyed Customers on a rolled-back Kernel — that is the
retired model.

## Troubleshooting

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| `Seat billing Trial requires freeTrial.seats` | `seatBilling: true` without trial seats | Set `freeTrial.seats` or turn Seat billing off |
| Plan page after upgrade though Stripe still bills | `referenceId` still a User id; no Organization Customer | Create/Checkout for the Organization; cancel the User Subscription in Dashboard |
| `users.stripe_customer_id` / `user.stripeCustomerId` type errors | Code still reads the User column | Use Organization Customer / Billing procedures |
| Duplicate Checkout or webhook 404 | App still mounts `createBillingRouter` at another path | Remove the hand mount; Dashboard → `POST /stripe/webhook` |
| Checkout 403 for the Owner | No active Organization on the session | Set active Organization before `/stripe/checkout` |
| Invite fails with Trial cap | Seat billing on and live billable Memberships already equal `freeTrial.seats` | Convert in Billing Portal or raise the Trial cap in the catalog (does not rewrite live quantity) |
| Trial-ending email skipped | Customer has no email, a default PM exists, or `trialEnding` is unregistered | Same rules as 0.34.0; email now comes from the Customer |
