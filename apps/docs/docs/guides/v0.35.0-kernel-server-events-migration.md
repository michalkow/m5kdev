# Kernel Server events in 0.35.0

## Summary

The Kernel owns a one-way HTTP SSE bus so the UI can refresh after background
work the User did not wait on (typically a Workflow job). `GET /events` is
cookie-authenticated and mounts only when Auth is registered. Services emit
through Auth (`userEmit`, `batchUserEmit`, `organizationEmit`,
`emitServerEvent`). The web client is `ServerEventProvider` in
`@m5kdev/frontend`.

This is **additive**. tRPC mutations that already return the entity must not
emit. Expo has no provider. There is **no** `create-m5kdev` registry transform.
File add and three-way merge are the existing `m5kdev update` reconciler;
composing the provider in a customized `App.tsx` is **Manual**.

Capability docs: [Server events](/modules/server-events).

## Who needs this migration

- **Every Auth app** that bumps `@m5kdev/backend` to 0.35.0 gets `GET /events`
  automatically. No opt-in flag.
- **Web apps that want live UI** must compose `ServerEventProvider` inside
  `AuthProvider` + `AppTrpcQueryProvider` and register handlers.
- **Apps with Workflow jobs** (or other off-request work) must emit from the
  job `.handle` through Auth. Conditional on the `workflows` feature and on
  any custom jobs you added.
- **Apps without Auth** never mount the route. No action.
- **Expo-only apps** skip the frontend provider. The HTTP route still mounts
  if Auth is registered.
- **Apps that only want the bus and never subscribe** need no frontend change.
- New apps scaffolded on this release already wrap
  `StarterServerEventProvider`.

## Prerequisites and upgrade order

Complete the [0.34.0 upgrades](/#upgrade-0-34-0) first (HTTP shell, catalog
lockstep, Auth on the Kernel). If you still copy Starter Fly wrappers, do
[Kernel Fly deploy commands](/guides/v0.35.0-kernel-fly-commands-migration)
in the same catalog bump; it is independent of Server events.

1. Commit or stash application changes.
2. Upgrade `@m5kdev/commons`, `@m5kdev/backend`, `@m5kdev/frontend`, and
   `create-m5kdev` together (Managed catalog lockstep).
3. Run `m5kdev update --dry-run`, then `m5kdev update`.
4. Wrap the webapp in `ServerEventProvider` if `App.tsx` did not pick up the
   Starter composition.
5. Emit from job handlers that finish work the triggering mutation did not
   return.

Always invoke an exact CLI release:

```sh
pnpm dlx create-m5kdev@0.35.0 update --dry-run
```

## What changed

- Kernel HTTP shell mounts `GET /events` (`SERVER_EVENT_SUBSCRIBE_PATH`) after
  module `express` hooks when Auth middleware exists. Unauthenticated → `401`.
  After `close()` → `503`. Signal shutdown ends SSE streams, then HTTP.
- Kernel bus (`infra.serverEvents`): `emit` / `batchEmit` of untyped JSON to
  UserIds. Redis pub/sub when Redis exists, else in-process. No replay.
  Duplicate UserIds collapse; empty list is a no-op.
- Auth validates the Shared envelope and exposes `userEmit`,
  `batchUserEmit`, `organizationEmit`, and `emitServerEvent` (void,
  fire-and-forget). `organizationId` is a client tag, not the bus audience.
- `@m5kdev/frontend` exports `ServerEventProvider` and
  `useServerEventHandler`. The client filters by `activeOrganizationId`;
  `organizationId: null` always runs.
- Starter: `StarterServerEventProvider` (always on; Workflow handlers behind
  `// m5k:workflows:`), `DemoWorkflowService` `demo.ping` `userEmit`s,
  cursor rule `.cursor/rules/server-event-emit.mdc`.
- Posts does **not** emit. Do not add SSE to tRPC CRUD that already returns
  the entity.

### New file: `StarterServerEventProvider.tsx`

Without `workflows`, the marker blocks are stripped and the component only
wraps `ServerEventProvider`. With `workflows`, use this shape (named exports
only):

```tsx
// biome-ignore-all assist/source/organizeImports: feature-gated Server event imports stay in marker blocks
import { ServerEventProvider } from "@m5kdev/frontend/modules/app/components/ServerEventProvider";
import type { QueryClient } from "@tanstack/react-query";
import { DEMO_WORKFLOW_SERVER_EVENT_RESOURCE } from "@starter-app/shared/modules/demo-workflow/demo-workflow.constants";
import type { ReactNode } from "react";
import { useTRPC } from "./utils/trpc";

type Props = {
  children: ReactNode;
};

/** Kernel SSE for the authenticated session. Workflow handlers are feature-gated. */
export function StarterServerEventProvider({ children }: Props): ReactNode {
  const trpc = useTRPC();
  const invalidateWorkflowList = (queryClient: QueryClient): void => {
    void queryClient.invalidateQueries(trpc.workflow.list.queryFilter());
  };
  return (
    <ServerEventProvider
      handlers={{
        [DEMO_WORKFLOW_SERVER_EVENT_RESOURCE]: (_event, queryClient) => {
          invalidateWorkflowList(queryClient);
        },
      }}
      onReconnect={invalidateWorkflowList}
    >
      {children}
    </ServerEventProvider>
  );
}
```

Adjust the `@starter-app/shared/...` import to your shared package name.

### `App.tsx` wrap

Inside `AuthProvider` → `AppTrpcQueryProvider`:

```tsx
<AppTrpcQueryProvider>
  <StarterServerEventProvider>
    <DialogProvider>
      <Router />
    </DialogProvider>
    {/* toasters */}
  </StarterServerEventProvider>
</AppTrpcQueryProvider>
```

You may call `ServerEventProvider` directly instead of a local wrapper.

## Migration steps

1. **Manual** — Upgrade catalog pins for `@m5kdev/commons`,
   `@m5kdev/backend`, `@m5kdev/frontend` to `0.35.0`. `pnpm install`.
2. **Automatic** (`m5kdev update` apply, after `--dry-run`) — adds
   `StarterServerEventProvider.tsx` and `.cursor/rules/server-event-emit.mdc`
   when those paths are absent or merge-clean; may merge `App.tsx`,
   `AGENTS.md`, `CLAUDE.md`, and `frontend-data-guide.mdc`.
3. **Manual** — If `App.tsx` conflicted or never wrapped the provider, nest
   `ServerEventProvider` (or `StarterServerEventProvider`) inside
   `AuthProvider` + `AppTrpcQueryProvider`. Do not mount it ad hoc on a route.
4. **Conditional** (`workflows` or custom jobs) — From the service that owns
   the job, call Auth emit after the work finishes. Add `auth` to
   `dependsOn` if the module does not already depend on it. Do not emit from
   the tRPC trigger that only returns `jobId`, and do not emit from CRUD that
   already returns the entity.
5. **Conditional** (custom resources) — Register a `handlers` entry (or
   `useServerEventHandler`) that invalidates the matching `queryFilter()`.
   Set `onReconnect` to the same invalidations.
6. **Manual** — Confirm no module `express` hook already serves `GET /events`.

There is no registry `id` `0.35.0-kernel-server-events`. Do not invent a
no-op transform.

## Environment and deployment changes

No new required env. Cookie session and `app.urls.web` CORS origin stay as in
0.33.0 / 0.34.0.

- **Redis** — required for emits from a worker process or a second HTTP
  instance (same as Workflow). A single in-process server without Redis still
  delivers to connections on that process.
- **Proxies** — do not buffer `GET /events`. The Kernel sets
  `X-Accel-Buffering: no` and a 15s keepalive. Cookies must be sent
  (`EventSource` uses `withCredentials: true`).
- **Shutdown** — SSE streams close before HTTP. Clients that subscribe during
  shutdown receive `503`.

- With Workflows: trigger `demo.ping` (or your job). After completion, the
  list query refetches from the handler, not only from a long poll. Keep
  polling for queued → running if you emit only on finish.

## Rollback

Revert the `@m5kdev/*` / `create-m5kdev` bump and restore previous `App.tsx`
/ provider files from git. `GET /events` disappears with the old Kernel. No
schema or data backfill to undo.

## Troubleshooting

- **`GET /events` 404** — Auth is not registered, or a reverse proxy is not
  forwarding that path.
- **`GET /events` 401** — no session cookie, or CORS origin does not allow
  credentials from the web app URL.
- **`GET /events` 503** — Kernel is shutting down (or already closed).
- **Route hits a module handler instead of SSE** — a module `express` hook
  registered `GET /events` first. Remove it.
- **Events never arrive from a worker / second instance** — Redis is missing
  or the worker uses a different Redis than HTTP.
- **UI does not update** — missing `handlers` / `onReconnect`, wrong
  `resource` string, or you emitted from a mutation the client already
  applied. Org-tagged events are dropped when `organizationId` does not match
  `activeOrganizationId`.
- **Expo client never connects** — expected; no provider in this release.
