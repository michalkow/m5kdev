# Migrate the MCP catalog to tRPC procedures

## Summary

0.39.0 removes the second MCP catalog. MCP tools are tRPC procedures opted in with `.meta({ mcp: { name, description } })`, served by a thin `McpModule` adapter. Organization-scoped Procedures and tRPC procedures take an optional `organizationId` that names the Organization (input wins over the session active Organization), so MCP clients and API keys can call org-scoped work without a webapp session. There is no automatic transform: every step below is Manual or Conditional, and the CLI migrations registry stays empty for this release.

## Who needs this migration

- Apps with a custom `<module>.mcp.ts` file, an `override mcp()` / `override mcpUser()` hook, or imports of `defineMcpCall` / `ModuleMcpContext` — your catalog no longer loads. Follow the Conditional app-MCP-calls steps.
- Apps calling Auth `setOrganizationFlags`, `setMemberFlags`, `setOrganizationOnboarding`, or `setMemberOnboarding` over tRPC (or re-exporting their inputs) — the wire shapes changed to objects. Follow the Conditional Auth-inputs step.
- Apps that build `createTRPCMethods()` outside `createBackendApp`, or read `ctx.session.activeOrganizationId` in services — follow the Conditional wiring steps.
- Apps with no custom MCP calls, no callers of those four Auth procedures, and no direct session reads: no action required beyond the package bump. Webapp callers that omit `organizationId` keep working through the session fallback.

## Prerequisites and upgrade order

1. Complete the 0.37.0 MCP OAuth migration first if MCP is in use: the allowlist table, consent flow, and OAuth tables are unchanged in 0.39.0 and the new adapter relies on them.
2. Upgrade every `@m5kdev/*` package to 0.39.0 together (lockstep). Do not mix 0.38.x and 0.39.0 framework packages.
3. Apply the Conditional steps below that match your app, then run Verification.

## What changed

- MCP tools come from tRPC procedures carrying `meta.mcp` (`name` plus instruction-style `description`, both required). Tool names are flat; duplicates fail boot. `list-organizations` is now a user-scoped tRPC procedure on `McpModule`.
- Deleted: module `mcp()` / `mcpUser()` hooks, `defineMcpCall`, `ModuleMcpContext` / `BackendModuleMcpContext`, and Starter `posts.mcp.ts`. Anything importing them fails typecheck until migrated.
- Grant checks always run on MCP calls now — the tool IS the procedure. Unregulated MCP handles no longer exist.
- `organizationProcedure` / `requireAuth("organization")` add optional `organizationId` to caller-facing input and strip it before the handle. Resolution: input `organizationId` wins, else the session active Organization, else an OrganizationActor already on the call (jobs/internal), else bad request. A live Membership rebuilds the Actor in the input/session cases. `userProcedure` and `adminProcedure` do not gain the field.
- API keys now receive a session (`enableSessionForAPIKeys`), so `x-api-key` callers can name an Organization with `organizationId`. API keys are still not MCP credentials and skip the allowlist.
- New `userProcedure` for user-scoped procedures callable without a session. `TRPCMethods` gains `userProcedure` and `createCallerFactory`; `createTRPCMethods` accepts an optional Membership lookup (wired by `createBackendApp`).
- `RequestContext.session`, `OrganizationContext.session`, and `AdminContext.session` are now optional. Services must use `ctx.actor`, not `ctx.session.activeOrganization*`.
- Child-organization checks (`assertCanCreateChildOrganizations`, `assertCanManageChildOrganizations`) authorize from the Actor's Organization instead of the session.
- Starter Posts marks `list-posts` / `create-post` with `meta.mcp`; update/publish/delete stay unmarked. The `create-m5kdev` `mcp` flag scaffolds that marking instead of `posts.mcp.ts`.

## Dependency and catalog changes

None. No dependency is added, removed, or re-pinned, and the `catalogs.m5kdev` pins are unchanged. Keep all `@m5kdev/*` packages on 0.39.0. Node.js, pnpm, and peer requirements are unchanged.

## Migration steps

### Conditional (app has custom MCP calls)

1. Delete every `<module>.mcp.ts` file.
2. Remove `override mcp()` / `override mcpUser()` from module files and drop `defineMcpCall` / `ModuleMcpContext` imports (the modules no longer exist).
3. Mark the tRPC procedures to expose: `.meta({ mcp: { name: "<flat-tool-name>", description: "<instruction-style copy>" } })` on the procedure chain (before `.query()` / `.mutation()`). Keep names flat and unique across modules; reuse the old tool names (for example `list-posts`) so MCP clients see no rename.
4. Write descriptions as agent instructions (when and how to call, including asking for `organizationId` first via `list-organizations`), not user-facing OpenAPI copy.
5. Do not add `organizationId` to shared Zod schemas: org-scoped procedures gain it automatically, and it is stripped before the handle. User and admin procedures never take it.
6. Audit every newly marked procedure's Grants: MCP clients now pass the same Grant checks as the webapp, and previously unguarded handles cannot be reproduced.

### Conditional (app calls the four Auth settings procedures)

7. Update callers to the new object inputs: `setOrganizationFlags` / `setMemberFlags` take `{ flags }`; `setOrganizationOnboarding` / `setMemberOnboarding` take `{ onboarding }`. Example: `setOrganizationFlags(["a"])` becomes `setOrganizationFlags({ flags: ["a"] })`.

### Conditional (app wires tRPC or reads sessions directly)

8. If the app builds `createTRPCMethods()` outside `createBackendApp`, pass the Membership lookup (`AuthOrganizationRepository`) as `{ memberships }`. Without it, calls that name an Organization fail as internal errors instead of resolving an Actor. Apps using only `createBackendApp` skip this.
9. Replace direct `ctx.session.activeOrganizationId` (and sibling session fields) in services with `ctx.actor` (`organizationId`, `organizationRole`, `memberId`). Session is now optional and may be absent for API-key and in-process callers; code that assumes it is present will fail typecheck — treat each error as a pointer to this step.

### Manual (all migrated apps)

10. If the app defines its own org-scoped procedures with non-object inputs (bare arrays, numbers), wrap them in objects the way core did for the four Auth procedures: tRPC input chaining requires the `organizationId` object input to compose with an object domain input.
11. Re-check child-organization flows: creation/listing/management now authorize from the Actor's Organization and role, and cookieless callers with a live Membership are allowed where they were previously always forbidden.

## Database migration

None. No tables are added, removed, or altered: `mcp_allowlist_entries` and the Auth OAuth/JWKS tables are unchanged, so there is nothing to generate and no migration to apply. Do not hand-edit SQL migrations in this repo.

## Environment and deployment changes

None. No new environment variables. The MCP OAuth resource URL, consent pages, and `POST /mcp` mounting are unchanged, and omitting `McpModule` still disables MCP HTTP and MCP OAuth.

## Verification

- `pnpm --filter @m5kdev/backend test` — full backend suite green (covers the Procedure seam and the MCP HTTP seam).
- `pnpm --filter @m5kdev/backend check-types` and `lint` — clean, including apps' services after step 9.
- `pnpm --filter create-m5kdev test` — scaffold tests green for both `mcp` flag positions.
- Behavior checks against a booted app with MCP on: tool listing includes the marked procedures with flat names; an org-scoped tool without `organizationId` fails; a non-allowlisted `organizationId` fails distinctly from a missing Membership; `list-organizations` returns the consent allowlist; booting with two procedures sharing one `meta.mcp.name` fails fast.
- Starter MCP Playwright spec (`mcp.spec.ts`) passes when the `mcp` flag and the test harness are both on.

## Rollback

Revert the `@m5kdev/*` pins to 0.38.22 and restore the deleted `*.mcp.ts` files and `mcp()` hooks from version control. No data or schema migration needs reversing (there was none), so a 0.38.22 app runs fine against a database last touched by 0.39.0. MCP clients pinned to renamed tools need their tool names restored — prefer keeping the old tool names in step 3 so rollback is a pure version revert.

## Troubleshooting

| Symptom | Cause and fix |
| --- | --- |
| Boot fails with a duplicate MCP tool name | Two procedures share one `meta.mcp.name`. Tool names are flat across modules: rename one. |
| Org-scoped tRPC call fails as bad request | No `organizationId` was passed and the session has no active Organization (cookieless caller). Pass `organizationId`. |
| MCP call fails allowlist vs Membership | Allowlist miss means that OAuth client never got consent for the org (re-consent); Membership miss means the User is not a live Member (invite/accept first). |
| Session-named org call fails as internal error | `createTRPCMethods()` was built without `{ memberships }` outside `createBackendApp`. Pass Auth's organization repository (step 8). |
| Typecheck fails on `ctx.session.activeOrganizationId` | Session is optional now. Use `ctx.actor` (step 9). |
| tRPC input chaining error on an org-scoped procedure with a bare array/number input | Non-object domain inputs cannot compose with the `organizationId` helper. Wrap them in objects (steps 7, 10). |
| MCP client sees no tools / `POST /mcp` missing | `McpModule` is not registered. Register it (and its tables) as before; the adapter only mounts when the module is present. |
