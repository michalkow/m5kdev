# PostgreSQL and pgvector migration

## Summary

Version **0.42.0** removes Turso/libSQL support. PostgreSQL is the only app SQL
dialect; pgvector replaces the libSQL vector adapter. This is a breaking source,
configuration, and data migration even though the release uses a minor bump.
Installing the packages does not transfer existing data or initialize storage.

## Who needs this migration

Existing server applications using `@m5kdev/backend` before 0.42.0 must migrate
their framework **and application-owned** tables. Apps with custom repositories,
injected libSQL clients, Mastra storage, or vectors need the corresponding steps.
Frontend-only applications have no SQL migration; keep their framework catalog
versions aligned. Freshly generated server apps already have PostgreSQL source
configuration but still need database provisioning and reviewed migrations.

Older apps must first complete the applicable ownership and app-owned Mastra
changes in [MemberId ownership](./v0.32.0-memberid-ownership-migration.md) and
[app-owned agents](./v0.34.0-mastra-app-owned-agents-migration.md).

## Prerequisites and upgrade order

1. **Manual** — back up the source database and prove a restore before changing
   production. Inventory every retained table, custom column, attachment reference,
   Mastra thread/message, and embedding. Agree on write freeze and rollback owners.
2. **Manual** — provision one PostgreSQL database per app/environment, a
   transaction-mode PgBouncer endpoint, and a direct administrative endpoint.
   Local reference configuration uses PostgreSQL 17 with pgvector; no provider is
   required. Provision `CREATE EXTENSION IF NOT EXISTS vector WITH SCHEMA public;`
   using an authorized administrator before AI initialization.
3. **Manual** — update dependencies, then schemas/repositories, then bootstrap,
   environment/deployment, and finally data transfer. Rehearse on a disposable copy.

These are **manual** migration steps: `packages/cli/src/migrations/registry.ts`
has no PostgreSQL semantic transform. `m5kdev update` catalog/template phases do
not convert custom source or data. Its reconciliation policy only ensures missing
database entrypoints and ignores migration history; it does not safely overwrite
customized existing files. No automatic SQL conversion is claimed here.

## What changed

- `createBackendApp` uses node-postgres `Pool` and Drizzle's node-postgres ORM;
  injected pools remain caller-owned. Kernel-owned pools close on shutdown.
- Framework tables live in the app schema (`app` by default), with JSONB,
  PostgreSQL scalar arrays, booleans, and timezone-aware timestamps. Text IDs and
  association tables remain text-based; do not force UUID conversion.
- UI/global text search uses `ILIKE`; explicit QueryMatch `$like` remains
  case-sensitive. Collection containment/overlap is structural, not serialized
  text matching or scalar SQL `IN`. `helpers.arrayContains` and libSQL retry
  utilities are removed; use native Drizzle operators.
- Database commands are `migrate`, `seed`, and guarded disposable `reset`.
  `sync`, replica synchronization, file deletion, and Turso credentials are gone.
- Mastra owns its storage schema and supported `mastra_` tables; vectors have
  their own schema. Runtime checks readiness rather than initializing structures.
  Starter Conversation now uses durable, app-owned Memory. Personal resources
  remain UserId-scoped; no new shared Conversation tenancy is introduced.

## Dependency and catalog changes

**Manual — dependency/catalog phase.** Set installed `@m5kdev/*` packages and
`create-m5kdev` to **0.42.0** in the Managed catalog. Preserve feature selection
and existing package-manager protocols; generated apps use `catalog:m5kdev`.
Remove `@libsql/client` **0.17.4** and `@mastra/libsql` **1.16.0** from manifests
and catalogs after replacing all imports. Add these tested catalog pins:

```yaml
catalogs:
  m5kdev:
    "@m5kdev/backend": 0.42.0
    "@m5kdev/commons": 0.42.0
    "@m5kdev/config": 0.42.0
    pg: 8.23.1
    "@types/pg": 8.23.1
    "@mastra/pg": 1.16.0
    "@mastra/memory": 1.9.0
```

Merge rather than replace this fragment: retain all other used framework pins at
0.42.0. Every SQL server needs `pg`; custom typed pool code needs `@types/pg`.
AI apps using PostgreSQL Mastra storage add `@mastra/pg`; Memory users also add
`@mastra/memory`. Starter adds the latter two and `pg` as server dependencies and
`@types/pg` as a dev dependency. Backend adds `pg`, `@types/pg`, and `@mastra/pg`.
The compatible existing pins remain `@mastra/core` **1.51.0**,
`@mastra/ai-sdk` **1.9.0**, `@mastra/rag` **2.4.1**, `drizzle-orm` **0.45.2**,
and `drizzle-kit` **0.31.10**. Do not blanket-upgrade Mastra independently.
Node **>=24** and pnpm **10.13.1** requirements are unchanged.

The root template's catalog is intentionally empty; template preparation derives
the published consumer catalog from Starter usage and the tested root catalog.
Add this root manifest override to exclude Drizzle's unused libSQL optional peer,
preserving other overrides, then run `pnpm install` and review the lockfile:

```json
{ "pnpm": { "overrides": { "drizzle-orm>@libsql/client": "-" } } }
```

## Migration steps

1. **Manual — source phase.** Convert **every** app-owned SQLite table, not just
   Posts. Import `appDatabaseSchema` from
   `@m5kdev/backend/base/database.schema` and builders from
   `drizzle-orm/pg-core`. Replace `sqliteTable(...)` with
   `appDatabaseSchema.table(...)`; use `boolean`, `jsonb`, scalar `.array()`, and
   `timestamp(..., { withTimezone: true, mode: "date" })` as warranted. Preserve
   IDs, foreign keys, indexes, uniqueness, and null/default meanings. Use exported
   `jsonbValue` for arbitrary JSON scalar payloads, including scalar strings.
2. **Manual — repository phase.** Replace `LibSQLDatabase` with `NodePgDatabase`
   from `drizzle-orm/node-postgres` and SQLite table/column types with Pg types.
   Remove serialized JSON/array `LIKE` helpers and use Drizzle `arrayContains`,
   `arrayOverlaps`, and parameterized native JSONB predicates. Remove double
   `JSON.stringify` on native values. Keep all transactional queries on `tx`.
   Verify existing QueryFilter/QueryMatch wildcard/null/empty behavior.
3. **Manual — bootstrap phase.** Replace libSQL URL/token/replica settings with:

   ```ts
   const databaseUrl = process.env.DATABASE_URL;
   if (!databaseUrl) throw new Error("DATABASE_URL is required");
   // Pass alongside the existing app config and composed schema.
   const db = { connectionString: databaseUrl };
   ```

   Pass `db` to `createBackendApp`. If injecting a `pg.Pool` as `{ client }`, the
   app must close that pool itself. Custom Better Auth wiring must select the
   Drizzle provider `pg`; preserve credential transactions and schema mappings.
4. **Manual — DDL configuration phase.** Add this complete small file at
   `apps/server/src/drizzle.schema.ts`:

   ```ts
   export { appDatabaseSchema } from "@m5kdev/backend/base/database.schema";
   export * from "./schema";
   ```

   Use `defineDrizzleKitConfig({ schema: "./src/drizzle.schema.ts" })` from
   `@m5kdev/backend/db` in `drizzle.config.ts`. Keep the composed runtime table
   map in `schema.ts`; do not import the DDL metadata module into the Kernel.
   Change `drizzle:migrate` to
   `tsx --env-file=../shared/.env db.ts migrate`; keep analogous `seed` and
   `reset` commands and remove `sync`. Custom `runDb` options now use
   `databaseDirectUrl`, `databaseSchema`, `disposable`, and `migrationsFolder`;
   old Turso/file/port/sync options and seed `isRemote` are removed. Seed `client`
   is a `Pool`, not a libSQL client.
5. **Conditional — AI bootstrap phase.** Replace `LibSQLVector` with `PgVector`
   from `@mastra/pg`; `AIModule` accepts a PgVector or
   `{ connectionString, schemaName, id }` configuration. Runtime adapters use
   `disableInit: true`. Compose `PostgresStore` in the app and pass it to Mastra
   and `new Memory({ storage, options: { semanticRecall: false } })` on the
   Conversation Agent. Follow Starter's three persistence files for readiness,
   initialization, and pool cleanup rather than initializing during import/start.
   Starter provisions `mastra_embeddings`, 1536 dimensions, cosine metric for
   `openai/text-embedding-3-small`; custom models need matching dimensions and
   metadata. Existing data may require a different index; do not silently rebuild.
6. **Manual — cleanup phase.** Remove unused libSQL imports, retry helpers, file
   defaults, replica settings, and Turso secrets. Frontend providers, routes,
   roles, and grants do not change. Preserve UserId resource checks for personal
   Conversation history; do not revive `chats.conversation` or broaden tenancy.

## Database migration

**Manual — administrative phase; production cutover requires explicit approval.**
Schema generation is a maintainer step, not an agent-authored SQL migration.
From the generated-app root, have the maintainer run:

```sh
pnpm --filter ./apps/server drizzle:generate
# Review the new drizzle-postgresql SQL, snapshot, and journal before applying.
pnpm --filter ./apps/server drizzle:migrate
# AI apps only, after pgvector is provisioned in public:
pnpm --filter ./apps/server mastra:init
```

Add the AI script as `tsx --env-file=../shared/.env mastra.ts`. Commands use
direct URLs and must not start HTTP, Redis, or Workflow workers. Migrate app
structures before initializing Mastra/vector structures. Seed only a disposable
test environment after setup; demo seed is not production data transfer.

The default history directory is `./drizzle-postgresql`; the old SQLite history
cannot run against PostgreSQL. Do not delete it to disguise missing conversion.
App migrations own only the app schema. Mastra owns its storage structures;
vectors own theirs. Do not generate Drizzle DDL for either adapter's structures.

Build an explicit, resumable source-to-target transfer for your actual datasets:
copy parents before children, retain text IDs, parse serialized JSON and arrays,
convert integer booleans, and convert timestamp units/timezones deliberately.
Reject/report malformed rows instead of replacing them with empty values. Compare
row counts, foreign-key orphans, uniqueness, domain totals, and representative
values. Transfer retained Mastra threads/messages and compatible embeddings
separately; obtain approval to regenerate incompatible embeddings. Never treat
package upgrade or `drizzle:migrate` as data backfill.

`reset` requires `DATABASE_DISPOSABLE=true` and truncates only app-owned tables
with `RESTART IDENTITY RESTRICT`. It preserves Mastra/vector schemas and may
refuse cross-schema dependencies. Never enable it in production or substitute
`CASCADE` to bypass ownership checks.

## Environment and deployment changes

**Manual — environment phase.** Use distinct endpoints, even when both address
the same database:

```dotenv
DATABASE_URL=postgresql://app:replace-me@pool.example:6432/product
DATABASE_DIRECT_URL=postgresql://admin:replace-me@db.example:5432/product
DATABASE_SCHEMA=app
DATABASE_DISPOSABLE=false
MASTRA_DATABASE_SCHEMA=mastra
VECTOR_DATABASE_SCHEMA=vectors
```

Optional `MASTRA_DATABASE_URL` / `MASTRA_DATABASE_DIRECT_URL` and
`VECTOR_DATABASE_URL` / `VECTOR_DATABASE_DIRECT_URL` override the respective
adapter endpoints. Direct initialization never falls back to runtime URLs.
Keep app, Mastra, and vector schemas distinct. Configure provider TLS, runtime
privileges, and pool limits explicitly; do not make runtime roles administrators.

For local development, Starter's four Compose/PgBouncer files provide the direct
5432 and pooled 6432 endpoints. Redis is still required for selected Workflow
features and is not replaced by PostgreSQL. On Fly, remove `libsql_data` mounts
only after verified transfer and preserve the source volume for rollback.
Run migration and `mastra:init` through direct connections before launching new
HTTP/worker processes. Missing tables/indexes should fail readiness rather than
create structures at runtime. See [Fly deployment](./fly-deploy.md).

## Verification

**Manual — verification phase.** In this framework checkout run `pnpm install`,
`pnpm --filter @m5kdev/backend check-types`,
`pnpm --filter @m5kdev/backend test -- --runInBand`,
`pnpm --filter create-m5kdev test`, `pnpm build`, and `pnpm test:e2e` with real
PostgreSQL/pgvector, transaction pooling, and required test environment settings.
In a consumer app run its server/webapp typecheck, lint, build, and E2E scripts;
review configured lint diagnostics instead of suppressing migration errors.

Verify login/signup, organization/member access, list/filter/match searches,
transaction rollback, Workflow ordering, JSON scalars/objects/null, exact array
membership with quotes/backslashes/wildcards, dates/timezones, and numeric totals.
Verify empty first Conversation history, restart durability, and cross-user
read/write rejection. Check vector upserts/dimension errors and shutdown cleanup.
Check missing direct URL, rejected `sync`, guarded reset, and survival of
Mastra/vector data after a disposable app reset. Compare converted production-copy
data before authorizing cutover. `pnpm why -r @libsql/client @mastra/libsql`
should show no resolved legacy adapters.

## Rollback

**Manual.** Keep the prior application image, source database, environment, and
tested backups throughout the rollback window. A code revert alone cannot undo
PostgreSQL writes. Freeze writes before switching back; reconcile post-cutover
writes explicitly or use an approved forward fix. Do not drop the PostgreSQL
schemas, old SQLite history, or source volume as part of package rollback.

## Troubleshooting

| Symptom | Check |
| --- | --- |
| Missing `DATABASE_DIRECT_URL` | Supply a direct endpoint; a runtime pool is not an administrative fallback. |
| Missing PostgreSQL history | Maintainer generates/reviews an app baseline in `drizzle-postgresql`. |
| Missing Mastra tables/index | Run the direct initialization before runtime startup. |
| pgvector readiness failure | Install the extension in `public` and verify runtime privileges. |
| Vector dimension/metric mismatch | Align model/index metadata; do not discard embeddings implicitly. |
| Array operator/type error | Convert serialized source columns and remove text `LIKE` emulation. |
| Invalid JSON scalar handling | Use native values and `jsonbValue` for arbitrary scalar payloads. |
| Reset refuses dependencies | Preserve ownership boundaries; do not use `CASCADE`. |
