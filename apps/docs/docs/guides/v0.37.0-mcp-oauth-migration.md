# McpModule and MCP OAuth in 0.37.0

## Summary

**McpModule** is a Core Module that serves MCP clients over `POST /mcp`.
Clients authenticate as a **User** with **Better Auth MCP OAuth** (resource
`{apiUrl}/mcp`). They do **not** use API keys and they do not use the webapp
cookie session as the MCP credential.

Consent is `/consent` (`AuthPublicConsentRoute`). The User picks which
Organizations that OAuth client may pass as `organizationId` (the **MCP
allowlist**, per `(oauthClientId, userId)`). Empty selection is valid.
Changing the list requires re-consent.

Apps **omit** `new McpModule()` to disable MCP. The Kernel then does not merge
module `mcp()` / `mcpUser()` catalogs and does not register jwt / MCP / CIMD
plugins. `create-m5kdev` `mcp` defaults **off**. Starter still registers
McpModule and contributes Posts `list-posts` / `create-post`.

There is **no** `create-m5kdev` registry transform. Schema generation is
**Manual**. Capability docs: [McpModule](/modules/mcp). Complete
[Better Auth 1.7.2](/guides/v0.37.0-better-auth-1.7.2-migration) first.

## Who needs this migration

- **Apps that want MCP clients** (Cursor, Claude Desktop, and the like) to
  call app MCP tools. Register McpModule, export OAuth/JWKS/allowlist tables,
  pass `mcp` through `createBetterAuth`, and bump `@m5kdev/web-ui` for
  `/consent`.
- **Apps that already declared MCP-like tools** by scraping Service
  properties (`mcpCall` / `.mcp.`). Replace those with `<module>.mcp.ts` and
  `override mcp()` / `mcpUser()`.
- **Forked auth public routers** that must add `/consent`.
- **Org-scoped Procedures used from MCP** whose `write: "org"` create
  access has no entity — Starter Posts `create` now passes
  `{ organizationId: ctx.actor.organizationId }`.

No action if the app will not register McpModule. New apps scaffolded with
`--yes` stay off MCP. Interactive create can select `mcp`.


## What changed

- **McpModule** — `mcp_allowlist_entries`, `McpService`, `POST /mcp` (protocol
  `2026-07-28`, legacy rejected), origin well-known OAuth discovery, consent
  tRPC (`listConsentOrganizations`, `replaceConsentAllowlist`). Builtin
  User-scoped `list-organizations`.
- **Auth plugins when McpModule is registered** — `jwt` (`jwk` model name so
  `usePlural` yields table `jwks`), `@better-auth/mcp`, CIMD profile
  `mcp-2026-07-28`. Resource `{apiUrl}/mcp`. Login page remains `/login`.
  Consent page is `{webUrl}/consent`.
- **Auth factory context** — `mcp?: { resource: string }` is set only when
  McpModule is in the modules array and `app.urls.api` is set. Pass it through
  to `createBetterAuth({ mcp })`.
- **Module hooks** — `mcp()` (OrganizationActor) and `mcpUser()` (UserActor).
  Map key is the tool name. Duplicate names and `list-organizations` collisions
  fail at boot. Do not scrape Service properties. Do not wrap tRPC.
- **organizationId** — required on organization-scoped MCP calls. McpModule
  checks the allowlist, resolves a live Membership, builds OrganizationActor,
  and **strips** `organizationId` from handle input. Attribute writes from
  `ctx.actor`, not `session.activeOrganizationId`.
- **Grants** — optional. Handles may delegate to a Procedure (Grant runs) or
  call unguarded service methods.
- **Web UI** — `AuthPublicRouter` includes `/consent`. Allow/deny POSTs
  `/oauth2/consent` with `accept` and **`oauth_query`** (the signed query
  string on the consent URL). Better Auth keeps OAuth state per request, not
  in a cookie.
- **Discovery** — `/.well-known/oauth-protected-resource/mcp`. Authorization
  server metadata is at
  `/.well-known/oauth-authorization-server/api/auth` because Better Auth's
  issuer path is `/api/auth`. CIMD is advertised; DCR
  (`registration_endpoint`) is also enabled so Cursor can register.
- **CIMD** — production client ids are HTTPS metadata URLs. Better Auth 1.7.2
  rejects loopback `client_id` URLs. Starter e2e sets `M5K_MCP_E2E_CIMD=1`
  (ignored when `NODE_ENV === "production"`).
- **HTTP MCP clients** — send `MCP-Protocol-Version: 2026-07-28`,
  `Mcp-Method`, `Mcp-Name` on `tools/call`, and `params._meta` with
  `io.modelcontextprotocol/protocolVersion` and
  `io.modelcontextprotocol/clientCapabilities`.

## Migration steps

1. **Manual** — Finish
   [Better Auth 1.7.2](/guides/v0.37.0-better-auth-1.7.2-migration).
2. **Manual** — Upgrade catalog pins listed above to `0.37.0`. `pnpm install`.
3. **Automatic** (`m5kdev update` apply, after `--dry-run`) — no
   MCP-specific AST transform. There is no registry `id` `0.37.0-mcp-oauth`.
   With `mcp` in `.m5kdev.json` features, update can merge Starter MCP files.
4. **Conditional** (enable MCP) — register the module and forward `mcp`:

   ```ts
   import { McpModule } from "@m5kdev/backend/modules/mcp/mcp.module";

   auth: {
     factory({ db, services, appConfig, i18n, mcp }) {
       return createBetterAuth({
         orm: db.orm,
         schema: db.schema,
         services: { email: services.email.email },
         app: appConfig,
         i18n,
         mcp,
         // ...
       });
     },
   },
   // modules array:
   new McpModule(),
   ```

   Omitting `mcp` from `createBetterAuth` leaves jwt/MCP/CIMD off even if
   McpModule is registered.
5. **Conditional** (enable MCP) — compose App schema:

   ```ts
   export {
     jwks,
     oauthAccessTokens,
     oauthClientAssertions,
     oauthClientResources,
     oauthClients,
     oauthConsents,
     oauthRefreshTokens,
     oauthResources,
   } from "@m5kdev/backend/modules/auth/auth.oauth.db";
   export { mcpAllowlistEntries } from "@m5kdev/backend/modules/mcp/mcp.db";
   ```

6. **Manual** — Generate and apply Drizzle migrations (Starter:
   `pnpm --filter ./apps/server drizzle:generate` then `drizzle:migrate`).
   **Do not** hand-write SQL. Generate from **current** Kernel schema so OAuth
   join tables reference `oauth_clients.client_id` and
   `oauth_resources.identifier` (public identifiers), not internal UUIDs.
7. **Conditional** (app MCP calls) — add `<module>.mcp.ts` and `override mcp()`:

   ```ts
   export function createPostsMcp(posts: PostsService) {
     return {
       "list-posts": defineMcpCall()
         .description("List posts in the selected Organization")
         .input(postSchemas.input.list)
         .handle(async (input, actor) =>
           posts.list(input, { actor, user: { id: actor.userId } })
         ),
       "create-post": defineMcpCall()
         .description("Create a draft post in the selected Organization")
         .input(postSchemas.input.create)
         .handle(async (input, actor) =>
           posts.create(input, { actor, user: { id: actor.userId } })
         ),
     };
   }
   ```

   Organization-scoped create Procedures with `write: "org"` need a synthetic
   entity:

   ```ts
   .access({
     action: "write",
     entities: ({ ctx }) => ({
       organizationId: ctx.actor.organizationId,
     }),
   })
   ```

8. **Conditional** (forked public auth UI) — mount `/consent` and send
   `oauth_query`:

   ```ts
   body: {
     accept,
     oauth_query: window.location.search.startsWith("?")
       ? window.location.search.slice(1)
       : window.location.search,
   }
   ```

9. **Conditional** (MCP HTTP client / e2e) — include protocol envelope
   headers. Do not send API keys as `Authorization` for `/mcp`.

## Database migration

Schema change when McpModule is enabled. **Do not** create Drizzle migration
files by hand.

Tables to expect from generate (names from Kernel `auth.oauth.db` /
`mcp.db`):

- `jwks`
- `oauth_clients`, `oauth_resources`, `oauth_client_resources`,
  `oauth_client_assertions`
- `oauth_access_tokens`, `oauth_refresh_tokens`, `oauth_consents`
- `mcp_allowlist_entries` (unique on `oauth_client_id`, `user_id`,
  `organization_id`)

Join FKs on token/consent/client-resource rows use **public** `client_id` and
resource `identifier` values. If you generated OAuth tables from an
intermediate Kernel snapshot that pointed those FKs at internal UUIDs,
generate again from 0.37.0 and apply the rebuilt migration — do not patch the
SQL by hand.

Apps that omit McpModule must **not** export these tables; generate would
otherwise create unused OAuth/JWKS/allowlist schema.

## Verification

In this repo:

```sh
pnpm --filter @m5kdev/backend test -- src/modules/mcp
pnpm --filter @m5kdev/backend test -- src/modules/auth/tests/auth.mcp-plugins.test.ts
pnpm --filter @starter-app/e2e exec playwright test tests/mcp.spec.ts --project=standard
```

In the app:

- Without McpModule: `POST /mcp` is a Kernel miss; no OAuth well-known MCP
  routes.
- With McpModule: unauthenticated `POST /mcp` is `401` with `WWW-Authenticate`
  Bearer. `GET /.well-known/oauth-protected-resource/mcp` and
  `GET /.well-known/oauth-authorization-server/api/auth` return JSON.
- Authorize an MCP client, land on `/consent`, allow an Organization, then
  `list-organizations` returns that Organization.
- `pnpm check-types` / `pnpm lint` succeed.

## Rollback

Remove `McpModule` from `createBackendApp`, stop exporting OAuth/allowlist
tables, and omit `mcp` from `createBetterAuth`. Existing OAuth/allowlist rows
can remain unused. Reverting `@m5kdev/backend` without reverting `better-auth`
1.7.2 is unsafe — keep the Better Auth guide's pin.

## Troubleshooting

- **Signup broken after the bump** — `accounts.issuer` missing. Finish
  [Better Auth 1.7.2](/guides/v0.37.0-better-auth-1.7.2-migration).
- **Login: model `jwkss` was not found** — jwt plugin is on but `jwks` table
  / model name is wrong. Export Kernel `jwks` and apply migrations. Kernel
  0.37.0 sets `schema: { jwks: { modelName: "jwk" } }`.
- **`/.well-known/oauth-authorization-server` 404** — fetch the
  issuer-suffixed path `/api/auth`.
- **Consent page is blank** — `@m5kdev/web-ui` dist/source has no `/consent`,
  or a forked `AuthPublicRouter` was not updated. Rebuild web-ui; add the
  route.
- **Allow on consent does nothing** — forked UI omitted `oauth_query`. Stock
  `AuthPublicConsentRoute` in 0.37.0 sends it.
- **CIMD registration fails on `http://127.0.0.1/...` client_id** — 1.7.2
  rejects loopback client ids. Production clients need an HTTPS metadata URL.
  E2e uses `M5K_MCP_E2E_CIMD=1`.
- **Cursor: `Incompatible auth server: does not support dynamic client
  registration`** — Cursor still requires RFC 7591 DCR
  (`registration_endpoint` on `/.well-known/oauth-authorization-server/api/auth`).
  Kernel MCP OAuth enables Better Auth’s optional DCR fallback next to CIMD.
  Redeploy a Kernel that includes that fallback. Do not put a bearer token in
  Cursor `mcp.json` `headers`; discovery still starts OAuth.
- **`create-post` `FORBIDDEN`** — Procedure `write: "org"` without an entity.
  Pass `organizationId` from `ctx.actor` as in Starter Posts create.
- **MCP `-32602` missing `_meta`** — protocol `2026-07-28` requires the
  per-request envelope. Add `_meta` plus `Mcp-Method` / `Mcp-Name`.
- **OAuth FK errors inserting `oauth_client_resources`** — FKs must target
  `oauth_clients.client_id` and `oauth_resources.identifier`. Regenerate
  migrations from current Kernel schema.
