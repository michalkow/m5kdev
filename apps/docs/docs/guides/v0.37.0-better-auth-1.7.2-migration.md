# Better Auth 1.7.2 in 0.37.0

## Summary

The Managed catalog pin for `better-auth` moves from **1.4.18** to **1.7.2**.
Better Auth 1.7.2 requires an `issuer` column on `accounts`. Without it,
credential signup fails with `The field "issuer" does not exist in the
"accounts" Drizzle schema`.

The Kernel also nests `@better-auth/api-key`, `@better-auth/mcp`,
`@better-auth/cimd`, and `@modelcontextprotocol/server` on
`@m5kdev/backend`. **jwt / MCP / CIMD plugins stay off** until
[McpModule](/modules/mcp) is registered. Do not add those packages to
`create-m5kdev` prompts or to App `package.json`.

There is **no** `create-m5kdev` registry transform. Schema generation is
**Manual**. Capability docs: [Auth](/modules/auth). Enable MCP HTTP in
[McpModule and MCP OAuth in 0.37.0](/guides/v0.37.0-mcp-oauth-migration).

## Who needs this migration

- **Every Auth app** that bumps `@m5kdev/backend` to 0.37.0. The catalog pin
  and `accounts.issuer` apply even if the app never registers McpModule.
- **Apps that insert `accounts` rows in seeds** should set
  `issuer: "local:credential"` for credential passwords (the column default
  matches that value if the insert omits it).

No action if the app never registered Auth. New apps scaffolded on this
release already pin 1.7.2 and include `issuer`.

## Prerequisites and upgrade order

Complete the [0.36.0 upgrades](/#upgrade-0-36-0) first. Then bump to 0.37.0
and apply this guide **before** turning on McpModule.

1. Commit or stash application changes.
2. Upgrade `@m5kdev/backend` (and lockstep `@m5kdev/*`) to 0.37.0.
3. Pin `better-auth` to `1.7.2` on the Managed catalog.
4. Generate and apply Drizzle migrations for `accounts.issuer`.
5. Optionally enable MCP OAuth
   ([McpModule and MCP OAuth](/guides/v0.37.0-mcp-oauth-migration)).

Always invoke an exact CLI release:

```sh
pnpm dlx create-m5kdev@0.37.0 update --dry-run
```

## What changed

- **Catalog** — `better-auth: 1.7.2` (was `1.4.18`) and `zod: 4.4.3`
  (was `4.2.1`; Better Auth 1.7.2 requires `zod` `^4.3.6`).
- **`accounts.issuer`** — `text`, `notNull`, default `"local:credential"`.
- **Unique index** — `accounts_issuer_account_id_unique` on
  `(issuer, accountId)`.
- **Kernel Auth** — `createApiKeyPlugin` imports from `@better-auth/api-key`
  **1.7.2** (nested Kernel dependency, not an App catalog pin).
- **MCP-capable packages** — Kernel depends on `@better-auth/mcp@1.7.2`,
  `@better-auth/cimd@1.7.2`, and `@modelcontextprotocol/server@2.0.0`. They
  are not peers. Plugins register only when `createBetterAuth({ mcp })` receives
  a resource from McpModule.

## Dependency and catalog changes

Pin these together on the Managed catalog to **0.37.0**:

- `@m5kdev/backend`
- `@m5kdev/frontend` (Better Auth client lockstep)
- `@m5kdev/commons` (lockstep)
- `@m5kdev/web-ui` (lockstep)
- `create-m5kdev` (invoke with `pnpm dlx create-m5kdev@0.37.0`)

Edit the generated-app Managed catalog (`catalogs.m5kdev` in
`pnpm-workspace.yaml`):

```yaml

zod: 4.4.3
```

Better Auth 1.7.2 depends on `zod` `^4.3.6`. Keep the Managed catalog `zod` pin
at `4.4.3` so the Auth client and Better Auth share one copy. Do **not** add
`@better-auth/mcp`, `@better-auth/cimd`, `@better-auth/core`, `better-call`, or
`@modelcontextprotocol/server` to the App catalog. Do not run
`pnpm update --latest`. Node and pnpm engines are unchanged from 0.36.0.

## Migration steps

1. **Manual** — Upgrade catalog pins listed above to `0.37.0`. Set
   `better-auth: 1.7.2` and `zod: 4.4.3`. `pnpm install`.
2. **Automatic** (`m5kdev update` apply, after `--dry-run`) — no
   Better Auth-specific transform. There is no registry `id`
   `0.37.0-better-auth-1.7.2`.
3. **Manual** — Generate and apply Drizzle migrations with the project's
   usual command (Starter: `pnpm --filter ./apps/server drizzle:generate`
   then `drizzle:migrate`). Review the SQL. Expect `accounts.issuer` and
   `accounts_issuer_account_id_unique`. **Do not** hand-write the SQL file.
4. **Conditional** (custom account seeds) — set `issuer: "local:credential"`
   on credential rows:

   ```ts
   await orm.insert(schema.accounts).values({
     id: uuidv4(),
     accountId: user.id,
     issuer: "local:credential",
     providerId: "credential",
     userId: user.id,
     password: await hashPassword(password),
     createdAt: new Date(),
     updatedAt: new Date(),
   });
   ```

## Database migration

Schema change. **Do not** create Drizzle migration files by hand. Run the
project's migration generation command, review the SQL, then apply.

- `ALTER TABLE accounts ADD issuer text DEFAULT 'local:credential' NOT NULL`
- unique index on `(issuer, account_id)`

Existing rows receive the default. If two rows already share the same
`account_id` and would collide under `local:credential`, generate/apply
fails — resolve duplicates before applying.

## Environment and deployment changes

No new required env for this guide. `BETTER_AUTH_SECRET` is unchanged.

- **Rollout order** — apply the Drizzle migration, then deploy backend, then
  web. Signup is broken until `issuer` exists.
- **Workers** — none.
- **`M5K_MCP_E2E_CIMD`** — e2e-only; belongs to the MCP OAuth guide. Do not
  set it in production.

## Rollback

Revert the `@m5kdev/backend` bump and the `better-auth` pin together.
Dropping `issuer` after Better Auth 1.7.2 is deployed breaks signup again.
Prefer a forward fix: keep 1.7.2 and the column.

## Troubleshooting

- **Signup: `issuer` does not exist on accounts** — migration not applied, or
  App schema is not the Kernel `accounts` table.
- **Unique index create fails** — duplicate `(issuer, account_id)` after the
  default fill. Inspect `accounts` and fix duplicates, then generate again.
- **Boot still on Better Auth 1.4.x** — Managed catalog pin or lockfile was
  not updated. Check `catalogs.m5kdev.better-auth`.
- **App added `@better-auth/mcp` to `package.json`** — remove it. The Kernel
  already nests it; registering plugins is McpModule's job.
