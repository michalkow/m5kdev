# Team drop and unused User payment columns in 0.36.0

## Summary

Auth 1.0 tenancy is **Organization** and **Membership** only. Signup and
Organization create no longer insert a **Team**. Better Auth teams are off.
Auth drops `teams`, `teammembers`, `invitations.teamId`, and session
`active_team_id` / `active_team_role`. Auth does not stamp team on the session.

**Kernel `TeamActor` and Grant level `team` stay.** `AuthRolesConfig` still
requires a `team` block. Product tables may keep leftover `team_id` columns
without a FK to `teams`. Do not invent Team rows to fill them.

The same catalog bump also drops unused User payment columns
(`payment_customer_id`, `payment_plan_tier`, `payment_plan_expires_at`).
`users.stripe_customer_id` stays for Billing.

There is **no** `create-m5kdev` registry transform. Schema generation is
**Manual**. Capability docs: [Auth](/modules/auth),
[Organizations and members](/guides/organizations-and-members). Decision:
ADR-0011 (`docs/adr/0011-no-team-at-1.0.md`).

## Who needs this migration

- **Every Auth app** that bumps `@m5kdev/backend` to 0.36.0. Schema exports
  and Drizzle must drop Auth team tables.
- **Apps that called Better Auth team APIs**, listed `teams` / `teamMembers` in
  App schema, seeded Team rows, or read `session.activeTeamId`.
- **Apps that read `users.paymentCustomerId` / `paymentPlanTier` /
  `paymentPlanExpiresAt`** (or the matching Better Auth additional fields).
  Billing continues to use `stripeCustomerId`.

No action if the app never registered Auth. New apps scaffolded on this
release already omit team tables and payment columns.

## Prerequisites and upgrade order

Complete the [0.35.0 upgrades](/#upgrade-0-35-0) first. On the 0.36.0 bump,
run [Membership at invite](/guides/v0.36.0-membership-at-invite-migration)
and [Account claim and Waitlist](/guides/v0.36.0-account-claim-waitlist-migration)
before or with this guide. Auth schema steps can share **one** Drizzle
generate after the catalog bump.

1. Commit or stash application changes.
2. Upgrade `@m5kdev/commons`, `@m5kdev/backend`, `@m5kdev/frontend`,
   `@m5kdev/web-ui`, and `create-m5kdev` together (Managed catalog lockstep).
3. Drop `teams` / `teamMembers` from App schema exports. Stop seeding Team.
4. Generate and apply Drizzle migrations.
5. Remove Better Auth team HTTP and `activeTeam*` session reads.

Always invoke an exact CLI release:

```sh
pnpm dlx create-m5kdev@0.36.0 update --dry-run
```

## What changed

### Team

- Better Auth `organization({ teams: { enabled: true } })` is gone. Auth does
  not mint Team rows on signup or Organization create.
- Tables `teams` and `teammembers` are removed from Auth schema.
- `invitations.teamId` is removed (Invitation is org + `memberId` only).
- `sessions.active_team_id` and `sessions.active_team_role` are removed. Auth
  does not stamp them.
- Starter seed / e2e harness no longer insert Team rows.
- Kernel `TeamActor`, Grant level `team`, and `AuthRolesConfig.team` remain
  until a later Kernel freeze. Starter still passes a `team` block
  (`roles: ["owner"]`).
- File, AI usage, Recurrence, Tag, and Starter posts may still have a
  nullable `team_id` column with **no** FK to `teams`. Existing values stay;
  new writes should leave them null.

### Unused User payment columns

- Dropped: `users.payment_customer_id`, `users.payment_plan_tier`,
  `users.payment_plan_expires_at`, and the matching Better Auth
  `additionalFields`.
- Kept: `users.stripe_customer_id` (Billing).

| Path | Action |
| --- | --- |
| `apps/<app>/server/src/schema.ts` | Edit: remove `teams` and `teamMembers` from the Auth export. |
| App seed / e2e harness that inserted `teams` / `teammembers` | Edit: stop inserting Team rows. |
| `apps/<app>/shared/src/modules/app/app.constants.ts` | Validate: `defineAuthRoles` still has a `team` block (type requires it). Do not treat that as creating Teams. |
| Call sites of Better Auth `organization.createTeam` / team session fields | Edit or delete. |

path is merge-clean. Customized schema exports are **Manual**.

invent a no-op transform.

## Migration steps

1. **Manual** — Upgrade catalog pins for `@m5kdev/commons`,
   `@m5kdev/backend`, `@m5kdev/frontend`, and `@m5kdev/web-ui` to `0.36.0`.
   `pnpm install`.
2. **Automatic** (`m5kdev update` apply, after `--dry-run`) — may merge
   Starter `schema.ts` if that path is merge-clean. There is no registry
   `id` `0.36.0-team-drop`.
3. **Manual** — Stop exporting Auth team tables:

   ```ts
   export {
     accountClaimMagicLinks,
     accountClaims,
     accounts,
     apikeys,
     invitations,
     members,
     organizations,
     sessions,
     users,
     verifications,
     waitlist,
   } from "@m5kdev/backend/modules/auth/auth.db";
   ```

   Do **not** re-export `teams` or `teamMembers`.
4. **Conditional** (duplicate Team rows you still need) — snapshot `teams` /
   `teammembers` before migrate. The framework does not backfill them into
   Organization Membership. 1.0 has no Team product surface.
5. **Manual** — Generate Drizzle migrations with the project's usual command
   (do not hand-write SQL). Apply them before serving traffic on the new Auth
   code. Expected Auth schema:
   - `DROP TABLE teammembers` then `DROP TABLE teams` (order matters for FKs)
   - `invitations` rebuilt without `team_id`
   - `sessions` without `active_team_id` / `active_team_role`
   - `users` without `payment_customer_id`, `payment_plan_tier`,
     `payment_plan_expires_at` (unique index on `payment_customer_id` dropped)
   - Product tables that still have `team_id` may rebuild only to drop the FK
     to `teams`; the column can remain
6. **Manual** — Delete Better Auth team HTTP and `session.activeTeamId` /
   `activeTeamRole` reads. Organization session fields stay
   (`activeOrganizationId`, `activeOrganizationRole`,
   `activeOrganizationMemberId`).
7. **Conditional** (custom grants with level `team`) — they still typecheck
   against Kernel Grant level `team`, but Auth will not populate
   `ctx.actor.teamId`. Prefer organization Grants.

## Database migration

Schema change. **Do not** create Drizzle migration files by hand. Run the
project's migration generation command, review the SQL, then apply.

There is **no data backfill** of Teams into Membership. Dropping `teams` /
`teammembers` deletes those rows. Leftover `team_id` on File / AI / posts is
not rewritten.

Payment columns are unused by Billing; dropping them does not touch
`stripe_customer_id` or Stripe customer records.

## Environment and deployment changes

No new required env.

- **Rollout order** — apply the Drizzle migration, then deploy backend, then
  web. New Auth code will not write Team rows; old code after a drop will
  fail inserts into `teams`.
- **Workers** — none specific to this change.

## Verification

In this repo:

```sh
pnpm --filter @m5kdev/backend test -- src/modules/auth/tests/auth.organization-create.test.ts
```

In the app:

- Signup / create Organization: one Organization + Owner Membership; no
  `teams` row.
- App schema typecheck fails if it still imports `teams` / `teamMembers`.
- Session objects have no `activeTeamId` / `activeTeamRole`.
- Billing checkout still sees `users.stripe_customer_id`.
- `pnpm check-types` / `pnpm lint` succeed.

## Rollback

Revert the `@m5kdev/*` / `create-m5kdev` bump and restore previous schema
exports from git. Tables already dropped need a restore from backup; the
framework does not recreate Team rows. Prefer a forward fix: stop using Team
and keep Organization Membership.

Do **not** re-enable Better Auth `teams.enabled` against 0.36.0 Auth schema.

## Troubleshooting

- **Drizzle generate wants to drop `teams` but the app still exports them** —
  remove the export first, then generate.
- **FK error dropping `teams`** — drop `teammembers` and invitation/product
  FKs first (generated SQL should order this; do not hand-edit).
- **`activeTeamId` type error** — Auth session no longer has the field. Use
  organization session fields.
- **`TeamActor` still exists** — expected. Kernel freeze has not removed it.
  Auth will not populate `teamId` on the session.
- **`defineAuthRoles` requires `team`** — expected. Keep a block; it does not
  create Teams.
- **Payment fields missing on User** — use Billing Subscription / Stripe
  customer, not Auth User columns.
