# Organization billingExempt overlay in 0.38.13

## Summary

Organizations gain `billingExempt` (column `organizations.billing_exempt`).
When true, that Organization skips the paywall and all Seat billing. New
Organizations start false. AdminActor toggles it on Billing Module admin
(Skip subscription check). Kernel does not backfill. `skipPlanCheck` on
`BillingProvider` still skips the whole app and ignores the Organization
field.

There is **no** `create-m5kdev` registry transform. Schema generation is
**Manual**. Capability docs: [Billing module](/modules/billing). Decision:
ADR-0023 (`docs/adr/0023-organization-billing-exempt.md`).

## Who needs this migration

- **Every app.** `organizations` is an Auth table; the new column must exist or
  Organization reads fail with `no such column: billing_exempt`.
- **Apps migrating existing Organizations onto paid billing.** After the
  column exists, run the grandfather SQL below once. Do **not** run it on
  products already charging — Kernel default is false (paywall on).

## Prerequisites and upgrade order

Complete the [0.38.11 upgrade](/#upgrade-0-38-11) first.

1. Commit or stash application changes.
2. Upgrade `@m5kdev/commons`, `@m5kdev/backend`, `@m5kdev/frontend`, and
   `@m5kdev/web-ui` together to `0.38.13`.
3. Generate and apply the Drizzle migration.
4. Only if this app is turning on paid billing for Organizations that already
   exist, run the grandfather SQL.

## Grandfather SQL (optional)

Kernel does not set existing rows. A migrating app that wants current
Organizations to keep using the product while AdminActor sets up Customer,
Plan, Coupon, or Trial can mark them exempt once:

```sql
UPDATE organizations SET billing_exempt = 1;
```

Organizations created after that statement stay `billing_exempt = 0`.
AdminActor clears the flag per Organization on Billing Module admin when
setup is done. Clearing with no `active` / `trialing` / `past_due`
Subscription sends Members to the Plan page.

## What changed

- `billingExempt` is on the Organization payload (not omitted like Stripe
  Customer ids) so `BillingProvider` can skip `getActiveSubscription` for
  that org.
- Seat billing invite/quantity updates no-op while the Organization is exempt.
- AdminActor `setAdminBillingExempt`; Billing admin Switch. Not Owner, not
  Organization Role admin, not Organization `flags`.
