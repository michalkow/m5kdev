# Organization billingExempt overlay in 0.38.13

## Summary

Organizations gain `billingExempt` (column `organizations.billing_exempt`).
When true, that Organization skips the paywall and all Seat billing. New
Organizations start false. AdminActor toggles it on Billing Module admin
(Skip subscription check). Kernel does not backfill. `skipPlanCheck` on
`BillingProvider` still skips the whole app and ignores the Organization
field.

There is **no** `create-m5kdev` registry transform. Schema generation is
**Manual**. Capability docs: [Billing module](/modules/billing). Decision:
ADR-0023 (`docs/adr/0023-organization-billing-exempt.md`).

## Who needs this migration

- **Every app.** `organizations` is an Auth table; the new column must exist or
  Organization reads fail with `no such column: billing_exempt`.
- **Apps that register `BillingModule`.** Billing Module admin gains the Switch;
  `BillingProvider` skips `getActiveSubscription` when the active Organization
  is exempt. No app source change is required if you already compose those.
- **Apps migrating existing Organizations onto paid billing.** After the
  column exists, run the grandfather SQL below once. Do **not** run it on
  products already charging — Kernel default is false (paywall on).

No action beyond the schema generate if the app never registered Billing, other
than the column existing so Organization reads succeed.

## Prerequisites and upgrade order

Complete the [0.38.11 upgrade](/#upgrade-0-38-11) first.

1. Commit or stash application changes.
2. Upgrade `@m5kdev/commons`, `@m5kdev/backend`, `@m5kdev/frontend`,
   `@m5kdev/web-ui`, and `create-m5kdev` together to `0.38.13`.
3. Generate and apply the Drizzle migration.
4. Only if this app is turning on paid billing for Organizations that already
   exist, run the grandfather SQL.

```sh
pnpm dlx create-m5kdev@0.38.13 update --dry-run
```

## What changed

`billingExempt` is a dedicated Organization boolean (not Organization `flags`,
not Coupon, not `skipPlanCheck`). Default false. AdminActor `write` Procedure
`billing.setAdminBillingExempt` (`{ organizationId, billingExempt }`).
`billing.listAdminOrganizationBilling` rows include `billingExempt`. The
Organization payload includes `billingExempt` (unlike Stripe Customer ids) so
`BillingProvider` can skip `getActiveSubscription` for that org.

While exempt: paywall is skipped; Seat billing invite/quantity updates and
Trial-convert quantity snap no-op; Billing admin, Checkout, Portal, and
webhooks still work. Clearing `billingExempt` does not require an
`active` / `trialing` / `past_due` Subscription; the admin UI warns, then
Members hit the Plan page. Children do not inherit. Kernel does not UPDATE
existing rows.

Grant action names stay `read` / `write`. Custom Billing grants need no edit.

## Dependency and catalog changes

No new dependencies. Pin `@m5kdev/commons`, `@m5kdev/backend`,
`@m5kdev/frontend`, `@m5kdev/web-ui`, and `create-m5kdev` to **0.38.13**
together. Root `pnpm-workspace.yaml` and
`packages/cli/root-templates/pnpm-workspace.yaml.tpl` gain no pins. Node.js and
pnpm engines are unchanged.

## Migration steps

1. **Manual** — Upgrade the packages to `0.38.13`; `pnpm install`.
2. **Automatic** (`m5kdev update` apply, after `--dry-run`) — nothing for this
   id (registry empty).
3. **Manual** — Generate and apply the Drizzle migration (see below).
4. **Conditional** — Only when adding paid billing to Organizations that
   already exist in the product, grandfather current rows:

```sql
UPDATE organizations SET billing_exempt = 1;
```

   Do **not** run this on a product already charging. Organizations created
   after this statement stay `billing_exempt = 0`. AdminActor clears the flag
   per Organization on Billing Module admin after Customer / Plan / Coupon /
   Trial setup.

## Database migration

Generate and apply with the project's command (do not hand-write migration
files):

```sh
pnpm --filter ./apps/server drizzle:generate
pnpm --filter ./apps/server drizzle:migrate
```

Expected schema: `organizations.billing_exempt` integer not null default `0`
(boolean). The grandfather `UPDATE` in step 4 is a data change, not a schema
migration; run it only after the column exists, and only when migrating
existing Organizations onto paid billing.

## Environment and deployment changes

No new env vars. Roll the schema first, then processes, then (if applicable)
the grandfather SQL. The column default is false, so existing Organizations
keep the paywall until you opt them out.

## Verification

- App boot succeeds; Organization reads do not error on `billing_exempt`.
- A newly created Organization has `billingExempt` false and still hits the
  Plan page when there is no ACCESS_STATUS Subscription.
- On Billing Module admin, Skip subscription check can be turned on for a
  paying Organization and off without a Subscription (warn, then Plan page).
- While exempt, Members are not sent to the Plan page; Seat invites do not
  fail a Trial cap; Stripe quantity does not update.
- `skipPlanCheck={true}` still skips the paywall for the whole app.

In this repo: `packages/backend/src/modules/billing/tests/billing.service.test.ts`.

## Rollback

The column is additive; older packages ignore it. If you grandfathered rows,
set them back before relying on the paywall on 0.38.12:

```sql
UPDATE organizations SET billing_exempt = 0;
```

Dropping the column is a forward schema change, not a rollback of this
release.

## Troubleshooting

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| `no such column: billing_exempt` | Migration not applied | Generate and migrate |
| Every existing org hit the Plan page after upgrade | Default is false; Kernel does not backfill | Run grandfather SQL only if that is intended |
| Paying orgs lost the paywall | Grandfather SQL ran on an already-paid product | `UPDATE organizations SET billing_exempt = 0` then toggle per org |
| Exempt org still blocked on invite | App is not on this BillingModule | Confirm `@m5kdev/backend` is 0.38.13 |
| Plan page still shows for an exempt org | `BillingProvider` not wrapping the route, or org list stale | Wrap routes; refresh session / `listUserOrganizations` |
