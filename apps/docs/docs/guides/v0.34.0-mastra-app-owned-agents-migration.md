# App-owned Mastra agents and Conversation in 0.34.0

## Summary

The Kernel no longer exports `createAgent` or `createMastra`. Apps construct
`Agent` and `Mastra` from `@mastra/core` and pass the instance into
`AIModule({ libs: { mastra } })`. Conversation UI uses Kernel HTTP at `/ai`
plus `useAiChat` and `AiConversation` — not Mastra's HTTP server and not
`chats.conversation`.

There is **no** `create-m5kdev` registry transform. Import rewrites are
**Manual**. Starter Conversation files follow the `ai` create flag.

## Who needs this migration

- Apps that import `createAgent` or `createMastra` from
  `@m5kdev/backend/modules/ai/ai.mastra` — those exports are gone.
- Apps that relied on `createMastra` defaulting LibSQL storage/vectors from
  `MASTRA_MAIN_DATABASE_URL` / `MASTRA_VECTOR_DATABASE_URL` must pass
  `storage` / `vectors` on their own `Mastra` instance if they still want that.
- Apps that want in-product chat adopt Conversation (**Conditional**). Existing
  `AIService.generateText` / `agentText` call sites keep working once Mastra is
  app-owned.

New apps get Conversation only when the interactive `ai` module is selected.
`--yes` does not enable it.

## Prerequisites and upgrade order

Complete [Core Modules and Optional Backend Module packages](./v0.34.0-core-optional-backend-modules-migration.md)
in the same release when those diffs apply.

1. Commit or stash application changes.
2. Upgrade `@m5kdev/backend`, `@m5kdev/frontend`, `@m5kdev/web-ui`, and
   `create-m5kdev` together (Managed catalog lockstep).
3. Replace Kernel Mastra helpers with app-owned `Agent` / `Mastra`.
4. Optionally add Conversation HTTP/UI.

Always invoke an exact CLI release:

```sh
pnpm dlx create-m5kdev@0.34.0 update --dry-run
```

## What changed

- Deleted `packages/backend/src/modules/ai/ai.mastra.ts`. The glob export
  `@m5kdev/backend/modules/ai/*` no longer includes those helpers.
- `createAgent` previously defaulted instructions/model/tools from Mastra
  `requestContext` (`agent-instructions`, `agent-model`, `agent-tools`). That
  wrapper is gone; copy it into the app if you still need it, or use a static
  `Agent` config like Starter.
- `createMastra` previously always attached `LibSQLStore` (`id: "mastra-main"`)
  and `LibSQLVector` (`id: "mastra-vector"`). Starter's Agent has **no** Memory;
  the Kernel does not own a Memory store.
- `AIModule.express` mounts authenticated Conversation at `/ai`.
- `@m5kdev/frontend` adds `hydrateConversation` and `useAiChat`.
- `@m5kdev/web-ui` adds `AiConversation` (compound Messages + Prompt;
  `showToolCalls` defaults to `true`).
- create-m5kdev `ai` flag gates Starter `conversation.mastra.ts`, schema
  `chats` / `ai_usage`, and webapp `/conversation`. Expo create does not add
  Conversation UI.

Do not persist new Conversations on `chats.conversation` (see ADR-0007). The
`chats` table stays until a maintainer-run Drizzle migration drops it.

## Dependency and catalog changes

No new required catalog entries for apps that already depend on `@mastra/core`
(and `@openrouter/ai-sdk-provider` if they use OpenRouter). Starter Conversation
uses `OPENROUTER_API_KEY`. `@mastra/libsql` is only needed if the app constructs
LibSQL Memory/vector stores itself.

`@m5kdev/backend`, `@m5kdev/frontend`, `@m5kdev/web-ui`, and `create-m5kdev`
move together on the Managed catalog.

| Path | Existing app |

| `apps/shared/src/modules/conversation/conversation.constants.ts` | Add with the `ai` flag. |
| `apps/webapp/src/modules/conversation/ConversationRoute.tsx` | Add with the `ai` flag. |
| `apps/webapp/src/Router.tsx` / `Layout.tsx` | **Conditional**. `// m5k:ai` markers wrap the `/conversation` route. |
| `apps/server/src/app.ts` | **Conditional**. Register `AIModule({ libs: { mastra, openrouter } })` inside `// m5k:ai` markers. |
| `apps/server/src/schema.ts` | **Conditional**. Export `chats` and `ai_usage` when `ai` is on. Generate Drizzle after adding tables; do not hand-edit SQL. |

| `apps/shared/.env.example` | Documents `OPENROUTER_API_KEY`. |

`create-m5kdev` does not add `@m5kdev/module-*`. Conversation is a Core AI
flag, not an Optional package.

## Migration steps

### 1. Replace Kernel Mastra helpers — Manual

```ts
// before (fails)
import { createAgent, createMastra } from "@m5kdev/backend/modules/ai/ai.mastra";

const assistant = createAgent({ id: "assistant", name: "Assistant" });
export const mastra = createMastra({ assistant });

// after
import { Mastra } from "@mastra/core";
import { Agent } from "@mastra/core/agent";
import { createOpenRouter } from "@openrouter/ai-sdk-provider";

const openrouter = createOpenRouter({
  apiKey: process.env.OPENROUTER_API_KEY ?? "",
});

const assistant = new Agent({
  id: "assistant",
  name: "Assistant",
  instructions: "You are a helpful assistant.",
  model: openrouter.chat("google/gemini-2.5-flash", { usage: { include: true } }),
});

export const mastra = new Mastra({
  agents: { assistant },
});
```

If you still need LibSQL Memory or vectors, construct `LibSQLStore` /
`LibSQLVector` from `@mastra/libsql` on that `Mastra` instance. The Kernel
does not read `MASTRA_MAIN_DATABASE_URL` / `MASTRA_VECTOR_DATABASE_URL`
anymore.

Pass the instance into `AIModule`:

```ts
new AIModule({
  libs: { mastra, openrouter },
});
```

`libs.mastra` remains optional. Direct OpenRouter `generateText` /
`generateObject` work without it.

### 2. Adopt Conversation — Conditional

Add `"ai"` to `.m5kdev.json` `template.features` (sorted) before
`m5kdev update` if you want Starter Conversation files. Then:

```sh
pnpm dlx create-m5kdev@0.34.0 update --dry-run
pnpm dlx create-m5kdev@0.34.0 update
```

Or wire it by hand:

- Mount `AIModule` (Auth is already required).
- Hydrate with `useAiChat` / render `AiConversation` with the same `agentId`
  the Mastra Agent uses.
- After exporting `chats` and `ai_usage`, run the project's
  `drizzle:generate` then `drizzle:migrate`.

HTTP (authenticated):

| Method | Path | Behavior |
| --- | --- | --- |
| GET | `/ai/chat/:agentId/threads/:threadId` | Hydrate. Without Memory: `{ messages: [], memory: false }`. |
| POST | `/ai/chat/:agentId` | Stream (`handleChatStream` v7). Without Memory the client sends full history. |

Do not use Mastra's own HTTP server for this UI.

### 3. Install — Manual

```sh
pnpm install
```

Do not follow with `pnpm update --latest`.

## Database migration

None for the helper removal. Conversation **adds** `chats` and `ai_usage` only
when App schema starts exporting them. Generate SQL with the project command;
do not hand-edit migrations. Do not drop `chats` in this upgrade.

## Environment and deployment changes

| Variable | When |
| --- | --- |
| `OPENROUTER_API_KEY` | Starter Conversation live replies; hydrate works without it |
| `MASTRA_MAIN_DATABASE_URL` / `MASTRA_VECTOR_DATABASE_URL` | No longer read by the Kernel. Keep them only if your app `Mastra` config still uses them |
| `IDEOGRAM_API_KEY` | Unchanged; `enableIdeogram` |

## Verification

- `pnpm check-types` has no imports from `@m5kdev/backend/modules/ai/ai.mastra`.
- `AIModule` boots with the app `Mastra` instance; `getMastra()` / `agentText`
  still work.
- Conversation: `GET /ai/chat/:agentId/threads/:threadId` returns 401
  unauthenticated, 404 unknown Agent. With a session and matching Agent id,
  hydrate returns `{ messages, memory }`.
- In this repo: `packages/backend/src/modules/ai/ai.chat.http.test.ts`,
  `packages/frontend/src/modules/ai/hooks/useAiChat.test.ts`,
  `packages/web-ui/src/modules/ai/components/AiConversation.test.tsx`.

## Rollback

Pin the previous `@m5kdev/backend` line to restore `ai.mastra`. Conversation
HTTP and UI packages will not exist on that line — drop those imports first.

## Troubleshooting

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| Cannot find module `.../ai/ai.mastra` | Helpers deleted | Construct `Agent` / `Mastra` in app code |
| 404 on `/ai/chat/...` | Agent id does not match `mastra.getAgent` | Use the same id as `new Agent({ id })` |
| Empty transcript after reload | Agent has no Memory | Expected for session-only; add Mastra Memory on the Agent if you want recall |
| Conversation route missing after update | `ai` not in managed features | Add the feature id, then update or copy Starter files |
| OpenRouter errors on send | Missing `OPENROUTER_API_KEY` | Set the key; hydrate still works without it |
