# Trial days per Price in 0.38.20

## Summary

Checkout, card-off Trial start, Admin Create Subscription prefill, and Plan UI
use the Price being billed, not `StripePlan.freeTrial.days` alone. Optional
`freeTrialDays` on `StripePlanPrice` overrides the Plan. `0` means no Trial for
that Price: Kernel omits Stripe `trial_period_days` and does not fall through
to 7. Catalogs that only set plan-level `freeTrial.days` keep today's behavior
for every Price. `freeTrial.seats` stays plan-level.

There is **no** `create-m5kdev` registry transform. No Drizzle generate. No
Stripe Product/Price metadata. Capability docs: [Billing module](/modules/billing).

## Who needs this migration

- **Apps that register `BillingModule`, set plan-level `freeTrial.days`, and
  list more than one Price on a Trial Plan.** A monthly Price can keep 14 days
  while quarterly/yearly on the same Plan have none. Set `freeTrialDays: 0` on
  those Prices.
- **Apps that already want the same Trial length on every Price.** No catalog
  edit. Plan-level `freeTrial.days` still applies to every Price that omits
  `freeTrialDays`.

No action if the app never registered Billing. `create-m5kdev` `billing` still
records the feature id only and does **not** scaffold `BillingModule`.

## Prerequisites and upgrade order

Complete the [0.38.15 upgrade](/#upgrade-0-38-15) first (which includes 0.38.9
N Prices).

1. Commit or stash application changes.
2. Upgrade `@m5kdev/commons`, `@m5kdev/backend`, `@m5kdev/frontend`,
   `@m5kdev/web-ui`, and `create-m5kdev` together to `0.38.20` (Managed catalog
   lockstep).
3. **Manual:** if quarterly or yearly must not trial, set `freeTrialDays: 0` on
   those Prices. Optionally set `freeTrialDays: 14` on month so the override is
   obvious next to plan-level `freeTrial: { days: 14 }`.


## What changed

### Catalog

`StripePlanPrice` gains optional `freeTrialDays?: number`. `StripePlan.freeTrial`
is unchanged (`days` and optional `seats`). Identity is Price id, not a
"quarter" key. Quarter is `{ interval: "month", intervalCount: 3 }`.

`resolveTrialDays({ plan, price, priceId, fallbackDays })` in
`@m5kdev/commons/modules/billing/billing.utils` is the only resolver:

1. `price.freeTrialDays != null` (or the Price found by `priceId`) → if `> 0`
   return it, else `undefined` (`0` means no trial).
2. Else `plan.freeTrial?.days` → same `> 0` rule.
3. Else, only on Trial-Plan start paths that already defaulted to 7
   (`createOrganizationHook` card-off, card-on Checkout when
   `trialRequiresPaymentMethod && trialPlan`): callers pass
   `fallbackDays: 7`. Commons does not hardcode Kernel 7.
4. Otherwise `undefined`.

`undefined` means omit `trial_period_days`. Do not write
`resolveTrialDays(...) ?? 7` after a Price sets `0`.

`findPlanPrice({ plan, priceId })` finds that Price on the Plan. Callers that
already have a Price pass `price`; callers with only an id pass `priceId`.

### Trial start and Checkout

- Card off: `createOrganizationHook` starts Trial only when resolved days for
  the picked or default Price are defined. If days are `undefined`, Kernel
  skips Trial (same fail-open as no Trial Plan) instead of creating a paid
  Subscription without a card.
- Card on: Checkout still collects a payment method. `trial_period_days` comes
  from `resolveTrialDays` for the Checkout Price **after** picked-at-sign-up
  substitution. Omit the field when days are `undefined`.
- Seat quantity stays `plan.freeTrial.seats`.

### Admin and Plan UI

- Admin list `defaultTrialDays` is resolved days of the Trial Plan default
  Price (or `null`).
- Create Subscription prefills Trial days from `resolveTrialDays` for the
  selected Price. Changing Price updates the field. `0` / `undefined` → empty
  input; start still defaults to none. Admin-typed days remain an override.
  Admin still cannot submit a 0-day Trial (`min 1`).
- Plan badge/CTA follow the displayed or selected Price. No trial days → no
  “N-day Trial” / “Start Trial”; CTA is Subscribe.

## Migration steps

1. **Manual** — Upgrade catalog pins for `@m5kdev/commons`,
   `@m5kdev/backend`, `@m5kdev/frontend`, `@m5kdev/web-ui`, and
   `create-m5kdev` to `0.38.20`. `pnpm install`.

2. **Automatic** (`m5kdev update` apply, after `--dry-run`) — no registry
   `id` `0.38.20-billing-trial-days-per-price`. Review the dry-run for unrelated
   file policies only.

3. **Manual** — If a quarterly or yearly Price must not trial, set
   `freeTrialDays: 0` on that Price. Example:

```ts
{
  name: "pro",
  products: {
    usd: {
      id: "prod_usd",
      defaultPriceId: "price_usd_month",
      prices: [
        { priceId: "price_usd_month", interval: "month", intervalCount: 1, unitAmount: 14900, freeTrialDays: 14 },
        { priceId: "price_usd_quarter", interval: "month", intervalCount: 3, unitAmount: 29800, freeTrialDays: 0 },
        { priceId: "price_usd_year", interval: "year", intervalCount: 1, unitAmount: 89400, freeTrialDays: 0 },
      ],
    },
  },
  freeTrial: { days: 14 },
}
```

   `freeTrialDays: 14` on month is redundant with plan-level 14; include it so
   the override is obvious. Omit per-Price days to keep plan-level days on every
   Price.

## Database migration

None. No schema change. Do not generate a Drizzle migration for this release.

## Environment and deployment changes

No new required env. `STRIPE_SECRET_KEY` still constructs the Stripe client in
app code. `STRIPE_WEBHOOK_SECRET` still verifies Billing webhooks. No worker or
telemetry change. Existing live Trials are unchanged; new Checkouts and org
creates use the catalog at request time.

## Verification

- A catalog with `freeTrialDays: 0` on a quarterly Price never sends
  `trial_period_days` for that Price (card-off org create skips
  `subscriptions.create`; card-on Checkout omits the field).
- Monthly default Price still sends plan or Price days (`trial_period_days: 14`
  in the example).
- Catalog with only plan-level `freeTrial.days` still sends those days for every
  Price.
- Picked sign-up Price is the one resolved, not `defaultPriceId`.
- Admin list `defaultTrialDays` is the Trial Plan default Price; changing Price
  in Create Subscription updates the prefill.
- Plan tabs update the “N-day Trial” badge; a Price with no days shows Subscribe.

In this repo: `packages/backend/src/modules/billing/tests/billing.utils.test.ts`
and `packages/backend/src/modules/billing/tests/billing.service.test.ts`.

Consumer checks: `pnpm install`, package `check-types` / `lint` / `test` /
`build` as you already run them.

## Rollback

Pin the previous `@m5kdev/*` line. Optional `freeTrialDays` fields in the app
catalog are ignored by 0.38.19. No database rollback.

## Troubleshooting

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| Quarterly Checkout still has a Trial | Price omitted `freeTrialDays`; plan `freeTrial.days` still applies | Set `freeTrialDays: 0` on that Price id |
| Card-off quarterly sign-up created a paid Subscription | 0.38.19 always sent plan days | Upgrade Kernel; `freeTrialDays: 0` now skips Trial start |
| Admin Trial days empty after picking a Price | That Price resolved to no trial | Expected; start stays none, or type days ≥ 1 to override |
| Plan page still says Start Trial on yearly | App has not upgraded `@m5kdev/web-ui` | Pin web-ui to 0.38.20 with commons and backend |
