# Inbound callback secrets in 0.37.0

## Summary

Inbound callback (module id `webhook`) no longer completes a waiting row with
the process-wide `WEBHOOK_SECRET` once that row has its own secret or a
**Named Inbound Callback**. Credentials are exclusive: row `secret`, else
constructor `secrets[name]`, else `WEBHOOK_SECRET`.

Minted callback URLs include `?token=`. The HTTP route accepts
`Authorization: Bearer` or the query `token`. `waitForRequest` returns a
`ServerResult` on every path, including mint failure (it no longer
`Promise.reject`s). Timeout still surfaces as `GATEWAY_TIMEOUT`.

Clay stays untyped in 1.0 and still uses `WEBHOOK_SECRET` for those waits.
This is **not** Stripe Billing `POST /webhook`.

There is **no** `create-m5kdev` registry transform. Schema generation is
**Manual**. Capability docs: [Inbound callback](/modules/webhook).

## Who needs this migration

- **Every app that registers `WebhookModule`** (including Clay). The `webhook`
  table gains `name` and `secret` columns.
- **Call sites of `waitForRequest`** that assumed `Promise.reject` on mint
  failure, or that POSTed to `/webhook/{id}` without a token.
- **Apps that completed arbitrary waiting ids with `WEBHOOK_SECRET`** after a
  named or per-wait secret was in play — that cascade is gone.

No action if the app never registered WebhookModule. New apps that opt into
the module on this release already have the columns and Result-returning
wait.

## Prerequisites and upgrade order

Complete the [0.36.0 upgrades](/#upgrade-0-36-0) first. Independent of
[Better Auth 1.7.2](/guides/v0.37.0-better-auth-1.7.2-migration) and
[McpModule](/guides/v0.37.0-mcp-oauth-migration); Auth schema and Inbound
callback schema can share **one** Drizzle generate after the catalog bump.

1. Commit or stash application changes.
2. Upgrade `@m5kdev/backend` (and `@m5kdev/module-clay` if pinned) to 0.37.0.
3. Generate and apply Drizzle migrations for `webhook.name` / `webhook.secret`.
4. Update `waitForRequest` callers to unwrap Results and to send the minted
   token.

Always invoke an exact CLI release:

```sh
pnpm dlx create-m5kdev@0.37.0 update --dry-run
```

## What changed

- **Table** — `webhook.name` and `webhook.secret` (nullable text).
- **`WebhookModule(mountPath, secrets?)`** — second argument is the name→secret
  map for Named Inbound Callbacks.
- **`waitForRequest(callback, timeoutSec?, { name?, secret? })`** — mints a
  URL `{origin}{mountPath}/{id}?token=...`. Origin is `NGROK_LOCALHOST_TUNNEL`
  if set, otherwise Kernel `app.urls.api`. Always `ServerResultAsync`.
- **Completion token** (exclusive; no cascade):

  | Row | Token must equal |
  | --- | --- |
  | `secret` set | that row secret |
  | `name` set, no secret | `secrets[name]` from the constructor (unknown name fails at mint) |
  | neither | `WEBHOOK_SECRET` (unset fails at mint) |

- **HTTP** — matching token on a non-`WAITING` row is **409**. Missing row or
  wrong token is **401**. In-process `completed(id, payload)` still skips the
  token and still requires `WAITING`.

## Starter and template file changes

| Path | Action |
| --- | --- |
| `apps/<app>/server/src/schema.ts` | Validate: keep exporting `webhook` if WebhookModule is registered. No extra export names. |
| `apps/<app>/server/src/app.ts` | Conditional: `new WebhookModule("/webhook", { adobe: process.env.ADOBE_CALLBACK_SECRET! })` when using Named Inbound Callbacks. |
| Services that call `waitForRequest` | Edit: unwrap `ServerResult`; pass the minted URL through unchanged (it already has `?token=`). |
| External systems that POST to the callback | Edit: send the token (query or Bearer). A token-less POST to `/webhook/{id}` no longer completes a secret-bearing row. |
| `packages/cli` root templates | No new files. |

CLI `packages/cli/src/migrations/registry.ts` stays empty for this id. Do not
invent a no-op transform.

## Migration steps

1. **Manual** — Upgrade catalog pins listed above to `0.37.0`. `pnpm install`.
2. **Automatic** (`m5kdev update` apply, after `--dry-run`) — no Inbound
   callback transform. There is no registry `id`
   `0.37.0-inbound-callback-secrets`.
3. **Manual** — Generate and apply Drizzle migrations (Starter:
   `pnpm --filter ./apps/server drizzle:generate` then `drizzle:migrate`).
   Expect nullable `name` and `secret` on `webhook`. **Do not** hand-write SQL.
4. **Manual** — Replace reject-style handling:

   ```ts
   const waited = await webhooks.waitForRequest<Payload>(
     async (url) => {
       await notifyVendor(url);
     },
     60
   );
   if (waited.isErr()) return err(waited.error);
   const payload = waited.value;
   ```

5. **Conditional** (Named Inbound Callbacks) — pass a constructor map and
   `waitForRequest(..., { name: "adobe" })`. Do not also set `secret` on that
   wait unless the row should ignore the named map.
6. **Conditional** (per-wait secret) — `waitForRequest(..., { secret })`.
   Completing that id with `WEBHOOK_SECRET` returns 401.

## Database migration

Schema change. **Do not** create Drizzle migration files by hand.

- `webhook.name` text (nullable)
- `webhook.secret` text (nullable)

Existing `WAITING` rows have neither set, so they still complete with
`WEBHOOK_SECRET` until new waits mint a row secret or name.

## Environment and deployment changes

| Variable | Role |
| --- | --- |
| `WEBHOOK_SECRET` | Fallback token when the row has neither `secret` nor `name`. Required to mint untyped waits (including Clay). |
| `NGROK_LOCALHOST_TUNNEL` | Optional public origin for minted URLs; else Kernel `app.urls.api`. |
| Named secrets | App env of your choosing, passed into `WebhookModule` — not a Kernel name. |

- **Rollout order** — apply Drizzle, then deploy backend. External callers
  must start sending the minted token.
- **Workers** — none specific.
- **Stripe** — unchanged (`STRIPE_WEBHOOK_SECRET` on Billing).

## Verification

In this repo:

```sh
pnpm --filter @m5kdev/backend test -- src/modules/webhook
```

In the app:

- Untyped `waitForRequest` still mints a URL with `?token=` and completes
  with `WEBHOOK_SECRET` when the row has no name/secret.
- A wait with `{ secret: "row-secret" }` returns 401 if completed with
  `WEBHOOK_SECRET`.
- Mint with `{ name: "missing" }` and no constructor map fails as a Result
  (not a thrown promise).
- `pnpm check-types` / `pnpm lint` succeed.

## Rollback

Revert `@m5kdev/backend`. Dropping `name` / `secret` after named waits exist
leaves those rows un-completable on the old process-secret path. Prefer a
forward fix.

## Troubleshooting

- **401 on a URL that worked on 0.36.0** — POST the minted `token` (query or
  Bearer). Completing with only `WEBHOOK_SECRET` fails once the row has
  `secret` or `name`.
- **409** — row is not `WAITING` (already completed, timed out, or error).
- **Mint `INTERNAL_SERVER_ERROR` / missing secret** — untyped wait without
  `WEBHOOK_SECRET`.
- **Mint `BAD_REQUEST` / unknown name** — `waitForRequest(..., { name })` whose
  constructor map lacks that name.
- **`waitForRequest` still looks like a rejected Promise** — create/mint
  errors are `err(...)` now. Check `isErr()` instead of `catch`.
- **Clay waits fail** — keep `WEBHOOK_SECRET` set; Clay remains the untyped
  fallback.
