# Email preview gate in 0.36.0

## Summary

`EmailPreviewModule` is a Kernel helper, not a Core Module. It mounts the
unauthenticated stored-mail UI **only** when EmailService mode is `store`
**and** `NODE_ENV` is not `production`. Registering it in production or in
`send` / `log` mode is a no-op (routes are not mounted). `GET` on the
mountPath is a normal Kernel miss. `allowDelete` is honored only when
preview actually mounted.

Required `EmailTemplates` keys shrink to the four Auth wrappers:
`verification`, `passwordReset`, `accountDeletion`, `organizationInvite`.
Waitlist templates and `trialEnding` are optional; extra string keys remain
for Notification kinds. Missing optional keys fail at **send** time, not at
boot.

Delivery modes stay exclusive `send` | `store` | `log`. Store is not a
dual-write on top of Resend. Preview HTML links honor `mountPath` (default
`/__emails`).

There is **no** `create-m5kdev` registry transform and **no** database
change. Starter still registers `EmailPreviewModule` and still ships waitlist
templates. Capability docs: [Email](/modules/email).

## Who needs this migration

- **Every app that registers `EmailPreviewModule`.** Production and
  send-mode boots no longer serve `/__emails` (or a custom `mountPath`) even
  if the module stays in the array.
- **Apps that treated waitlist Email templates as required** at composition
  time. They may omit those keys if they never send waitlist mail.
- **Apps with a custom `mountPath`** whose preview HTML still assumed
  hardcoded `/__emails` links (fixed in the package; no app edit if you use
  the module as-is).

No action if the app never registered EmailModule. New apps scaffolded on
this release already match the gate and the four required keys.


## What changed

- **Preview gate** — `EmailPreviewModule.express` returns without attaching
  routes when `emailService.mode !== "store"` or
  `process.env.NODE_ENV === "production"`. Starter may still list the
  module in every env; the Kernel gate is the safety rail.
- **`mountPath`** — inbox, detail, raw HTML, and JSON links use the
  configured path.
- **`EmailTemplates`** — required: `verification`, `passwordReset`,
  `accountDeletion`, `organizationInvite`. Optional:
  `waitlistConfirmation`, `waitlistInvite`, `waitlistUserInvite`,
  `systemWaitlistNotification`, `trialEnding`, and extra keys.
- Named Auth and waitlist wrappers stay public. Waitlist wrappers fail at
  send if that template is missing (`INTERNAL_SERVER_ERROR`).
  `sendSystemWaitlistNotification` still returns `ok` without sending when
  `systemNotificationEmail` is unset.
- Modes remain exclusive. Docs that implied store-in-addition-to-send were
  wrong; 0.36.0 documents the actual contract.

## Starter and template file changes

| Path | Action |
| --- | --- |
| `apps/<app>/server/src/app.ts` | Validate: `new EmailPreviewModule({ allowDelete: process.env.NODE_ENV !== "production" })` may stay. Production still no-ops even if `allowDelete` were true. |
| App `EmailModule(templates)` | Conditional edit: waitlist keys may be omitted. Keep the four Auth keys. |
| E2e that `GET`s `/__emails` in production or send mode | Edit: hit preview only in store + non-production. |
| `packages/cli` root templates | No new files. |

CLI `packages/cli/src/migrations/registry.ts` stays empty for this id. Do not
invent a no-op transform.

## Migration steps

1. **Manual** — Upgrade catalog pins listed above to `0.36.0`. `pnpm install`.
2. **Automatic** (`m5kdev update` apply, after `--dry-run`) — no Email-specific
   transform. There is no registry `id` `0.36.0-email-preview-gate`.
3. **Manual** — Stop depending on preview HTTP outside local store mode.
   Production `GET {mountPath}` must 404 / Kernel miss.
4. **Conditional** (no Waitlist product) — omit waitlist templates:

   ```ts
   new EmailModule({
     verification: { /* ... */ },
     passwordReset: { /* ... */ },
     accountDeletion: { /* ... */ },
     organizationInvite: { /* ... */ },
     // waitlist* optional
     trialEnding: { /* ... */ }, // still optional for Billing
   })
   ```

   Keep waitlist keys if you call `sendWaitlistInvite` and friends.
5. **Conditional** (custom `mountPath`) — no app HTML to patch; the module
   emits links on that path. Update bookmarks and e2e base URLs.

## Database migration

None. EmailModule has no tables.

## Environment and deployment changes

No new required env. Kernel email options stay `mode`, `from`,
`systemNotificationEmail`, `outputDirectory`.

- **`EMAIL_MODE` / Kernel `email.mode`** — `store` is local inspection and
  e2e only. Production should be `send` (Resend). A forgotten Resend key
  with `store` in production no longer exposes verify/reset URLs at
  `/__emails`.
- **`NODE_ENV`** — must be `production` on prod boxes for the gate to hold
  even if mode is mis-set to `store`.
- **Rollout** — backend only. No worker or schema order.
- **E2e** — keep store mode and non-production env when asserting stored
  password-reset mail.

## Verification

In this repo:

```sh
pnpm --filter @m5kdev/backend test -- src/modules/email/tests/email.preview.http.test.ts
pnpm --filter @m5kdev/backend test -- src/modules/email/tests/email.service.test.ts
```

In the app:

- Local store mode: `GET /__emails` (or `mountPath`) lists stored mail;
  detail links stay on that path.
- Send mode with EmailPreview still registered: mountPath misses.
- Production env + store mode + EmailPreview registered: mountPath misses.
- `EmailModule` typechecks with only the four Auth keys.
- `sendWaitlistInvite` without waitlist templates fails at send.
- `pnpm check-types` / `pnpm lint` succeed.

## Rollback

Revert the `@m5kdev/backend` bump. Old preview mounted in every env and
only disabled DELETE in production. Restoring that leak is not recommended.
Forward-fix: keep the gate and use store mode locally.

## Troubleshooting

- **`GET /__emails` 404 in development** — mode is not `store`, or
  `NODE_ENV` is `production`. Check Kernel email config and env.
- **Preview inbox links go to `/__emails` on a custom path** — you are not
  on 0.36.0; bump `@m5kdev/backend`.
- **Boot type error omitting waitlist templates** — still on a required-key
  `EmailTemplates` type; bump backend.
- **Waitlist send `INTERNAL_SERVER_ERROR`** — optional template missing at
  send time. Register that key or stop calling the wrapper.
- **Production still serves preview** — `NODE_ENV` is not `production`, or
  an old package is installed.
