# HeroUI 3.2.7 toggle composition in 0.45.6

## Summary

0.45.6 moves the HeroUI catalog pins from 3.0.3 to **3.2.7** and adds explicit
`react-aria` / `react-aria-components` pins so pnpm cannot keep incompatible
React Aria copies. HeroUI 3.2.7 requires `Checkbox`, `Radio`, and `Switch` to
put `Control` and visible labels inside `Content`. Updating HeroUI without those
peers fails the Landing build (`react-aria-components/Sheet`). Leaving the old
toggle tree makes SelectChips expose only `button "Selected"` in the
accessibility tree.

Shipped `@m5kdev/web-ui` controls (consent, preferences, billing admin, table
selection, group-by, SelectChips) already use the new composition. App-owned
toggles and test mocks still have to change.

There is **no** `create-m5kdev` registry transform. Catalog advancement is
`m5kdev update`. Toggle JSX is **Manual**.

## Who needs this migration

- **Every Webapp or Landing** that depends on `@heroui/react` or
  `@m5kdev/web-ui`. Catalog pins and the React Aria direct dependencies must
  move with the lockstep 0.45.6 packages.
- **Apps that compose HeroUI `Checkbox`, `Radio`, or `Switch` in their own
  source** (including table selection copies and preference forms). Those trees
  must wrap `Control` and labels in `Content`.
- **Tests that mock those primitives.** A mock without `Switch.Content` /
  `Checkbox.Content` / `Radio.Content` fails after the upgrade.

No action for Expo-only apps, Email, or servers that never import HeroUI.
Unmanaged apps that pin `@m5kdev/web-ui` without a pnpm catalog still need the
same HeroUI and React Aria versions this release tested.

## Prerequisites and upgrade order

Complete [0.45.3](/#upgrade-0-45-3) first if you are still on an earlier 0.45
line.

1. Commit or stash application changes.
2. Upgrade every `@m5kdev/*` package and `create-m5kdev` together to **0.45.6**.
3. Run `m5kdev update` so Managed catalog pins and Starter-aligned package
   manifests pick up HeroUI 3.2.7 and the React Aria peers.
4. Rewrite remaining app-owned toggle compositions, then `pnpm install` and
   typecheck.

Always invoke an exact CLI release:

```sh
pnpm dlx create-m5kdev@0.45.6 update --dry-run
```

## What changed

| Layer | Change |
| --- | --- |
| Catalog | `@heroui/react` and `@heroui/styles` are `3.2.7`. `@internationalized/date` is `3.12.4`. `@react-aria/utils` is `3.34.1`. New pins: `react-aria` `3.53.1`, `react-aria-components` `1.22.1`. |
| `@m5kdev/web-ui` | Direct `catalog:` dependencies on `react-aria` and `react-aria-components`. Toggle trees wrap `Control` (and labels) in `Content`. Billing switches and SelectChips gain `aria-label`. |
| Starter Webapp / Landing | Direct `catalog:` dependencies on `react-aria` and `react-aria-components`. |
| CLI | Generated apps inherit the same Managed catalog pins at `create-m5kdev` build. Production `packages/cli/src/migrations/registry.ts` stays empty for this id. |

`@heroui/react` remains a Boundary-library peer of `@m5kdev/web-ui`.
`react-aria` and `react-aria-components` are **not** new Kernel peers; they are
direct app dependencies so HeroUI 3.2.7 resolves `Sheet` and related modules.

## Dependency and catalog changes

Pin `@m5kdev/commons`, `@m5kdev/backend`, `@m5kdev/frontend`, `@m5kdev/web-ui`,
and `create-m5kdev` to **0.45.6** together. Do not mix 0.45.5 and 0.45.6. Do
not run `pnpm update --latest`.

| Catalog key | Previous | This release |
| --- | --- | --- |
| `@heroui/react` | `3.0.3` | `3.2.7` |
| `@heroui/styles` | `3.0.3` | `3.2.7` |
| `@internationalized/date` | `3.12.2` | `3.12.4` |
| `@react-aria/utils` | `3.33.1` | `3.34.1` |
| `react-aria` | (absent) | `3.53.1` |
| `react-aria-components` | (absent) | `1.22.1` |

Inspected: root `pnpm-workspace.yaml` holds those versions.
`packages/cli/root-templates/pnpm-workspace.yaml.tpl` still has empty
`catalogs.m5kdev` until `m5kdev update` / `create` writes Managed pins from
Starter manifests.

Webapp and Landing (and any other HeroUI host) must declare:

```json
{
  "dependencies": {
    "@heroui/react": "catalog:m5kdev",
    "@heroui/styles": "catalog:m5kdev",
    "react-aria": "catalog:m5kdev",
    "react-aria-components": "catalog:m5kdev"
  }
}
```

In this monorepo those specifiers are `catalog:` because the framework uses
the default catalog. Generated apps use `catalog:m5kdev`.

Expo, Email, e2e, and server manifests do not need the React Aria packages.
Node.js, pnpm, and lockfile requirements are unchanged. `catalogMode: strict`
stays.

## Migration steps

1. **Manual** — Upgrade every `@m5kdev/*` package and `create-m5kdev` to
   `0.45.6`. `pnpm install`.
2. **Automatic** (`m5kdev update` catalog merge) — Managed HeroUI and React
   Aria pins.
3. **Automatic** (`m5kdev update` three-way merge) or **Conditional** — add
   `react-aria` and `react-aria-components` on Webapp and Landing manifests.
4. **Manual** — rewrite app-owned toggles:

```tsx
<Checkbox>
  <Checkbox.Content>
    <Checkbox.Control>
      <Checkbox.Indicator />
    </Checkbox.Control>
    {label}
  </Checkbox.Content>
</Checkbox>

<Switch>
  <Switch.Content className="text-sm">
    <Switch.Control>
      <Switch.Thumb />
    </Switch.Control>
    {label}
  </Switch.Content>
</Switch>

<Radio value={value}>
  <Radio.Content>
    <Radio.Control>
      <Radio.Indicator />
    </Radio.Control>
    {label}
  </Radio.Content>
</Radio>
```

Remove unused `Label` imports when the text moved into `Content`. Switches
without visible copy still need `<Switch.Content><Switch.Control>…` and an
`aria-label`.

5. **Manual** — update test mocks:

```tsx
Switch.Content = ({ children }: { children?: ReactNode }) => <span>{children}</span>;
```

Do the same for `Checkbox.Content` and `Radio.Content` when those mocks exist.

```sh
pnpm --filter @starter-app/webapp check-types

```

Web UI tests pass (including billing admin Switch mocks). Webapp typecheck
succeeds. Landing build resolves `react-aria-components/Sheet`.

In the app: SelectChips exposes a checked checkbox (not only `button
"Selected"`). Preference switches still submit FormData. Table select-all, row
selection, and indeterminate state still work. Grouping radios still group.

## Rollback

Revert the `@m5kdev/*` pins, Managed catalog HeroUI/React Aria entries,
Webapp/Landing `react-aria` dependencies, lockfile, and toggle JSX together.
Leaving 3.2.7 in the catalog after reverting JSX, or the reverse, fails build
or accessibility.

No database rollback.

## Troubleshooting

| Symptom | Cause and fix |
| --- | --- |
| `Unable to resolve react-aria-components/Sheet` (or similar) on Landing/Webapp build | Catalog still has HeroUI 3.2.7 without `react-aria` / `react-aria-components`, or the app did not declare those dependencies. Add the pins and `pnpm install`. |
| SelectChips accessibility tree is only `button "Selected"` | Checkbox is missing `Content` / `Control` / `Indicator` or `aria-label`. Apply the composition above. |
| `Switch.Content is not a function` in tests | Mock defines `Switch.Control` but not `Switch.Content`. |
| pnpm `catalogMode` / missing catalog key | `react-aria` is on a manifest as `catalog:m5kdev` but not in `catalogs.m5kdev`. Re-run `m5kdev update` or add the pin by hand. |
| Mixed `@m5kdev/*` versions | Lockstep all packages to 0.45.6. |
