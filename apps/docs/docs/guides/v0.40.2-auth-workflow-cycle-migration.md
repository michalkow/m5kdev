# Auth and Workflow boot cycle in 0.40.2

## Summary

0.40.1 Auth declared `optionalDependsOn: ["workflow"]`. Workflow already
`dependsOn` Auth. `createBackendApp` throws
`Circular backend module dependency detected: auth → workflow → auth` and the
process never listens.

0.40.2 drops that graph edge. Auth still registers the daily Close Purge cron
from its `workflows()` hook when Workflow is in the app. No constructor, schema,
or bootstrap source change.

There is **no** `create-m5kdev` registry transform. Close/Restore/Purge remains
[0.40.1](/guides/v0.40.1-close-restore-purge-migration). Capability docs:
[Auth](/modules/auth).

## Who needs this migration

- **Every app on 0.40.1 that registers both `AuthModule` and `WorkflowModule`.**
  Boot fails until the pins move to 0.40.2.
- **Apps on 0.40.1 with Auth and no Workflow.** Boot already works. Still bump
  lockstep so you do not mix 0.40.1 and 0.40.2.

No action if the app never installed 0.40.1.

## Prerequisites and upgrade order

Complete [Close, Restore, and Purge in 0.40.1](/guides/v0.40.1-close-restore-purge-migration)
first if you have not applied `users.closed_at` / `organizations.closed_at`.

1. Commit or stash application changes.
2. Upgrade every `@m5kdev/*` package and `create-m5kdev` together to **0.40.2**.
3. Redeploy backend (and worker if Workflow is registered).

Always invoke an exact CLI release:

```sh
pnpm dlx create-m5kdev@0.40.2 update --dry-run
```

## What changed

- `AuthModule.optionalDependsOn` is `["billing"]` only. Workflow is not a module
  dependency of Auth.
- When Workflow is registered, the kernel still calls Auth `workflows()` with
  the Workflow runtime and Auth registers `auth.purge` (`0 0 * * *`).
- `closeAfterDays` below 1 still throws at that hook when Workflow is present.

`new AuthModule()` and `new AuthModule({ closeAfterDays, grants, hooks })` are
unchanged.

## Dependency and catalog changes

No new third-party dependencies. Node.js and pnpm engines are unchanged.
Pin `@m5kdev/commons`, `@m5kdev/backend`, `@m5kdev/frontend`, `@m5kdev/web-ui`,
and `create-m5kdev` to **0.40.2** together. Do not mix 0.40.1 and 0.40.2.

Inspected: root `pnpm-workspace.yaml` and
`packages/cli/root-templates/pnpm-workspace.yaml.tpl` list no `@m5kdev/*`
catalog versions; generated-app `catalogs.m5kdev` stays empty until
`m5kdev update` writes Managed pins.

## Starter and template file changes

Inspected `apps/starter`, `packages/cli/root-templates`,
`packages/cli/scripts/prepare-templates.ts`, and
`packages/cli/templates/minimal-app`. Starter already registers `new AuthModule()`
and `new WorkflowModule({...})` when the workflows feature is on. No starter or
template path changes in 0.40.2.

| Path | Existing app |
| --- | --- |
| `apps/<app>/server/src/app.ts` | Validate: `new AuthModule()` next to `new WorkflowModule(...)` boots. |
| CLI `packages/cli/src/migrations/registry.ts` | None. Stays empty for this id. |
| Database migrations | None. |
| `.env` files | None. |

## Migration steps

1. **Manual** — Upgrade catalog pins for `@m5kdev/commons`, `@m5kdev/backend`,
   `@m5kdev/frontend`, `@m5kdev/web-ui` to `0.40.2`. `pnpm install`.
2. **Automatic** (`m5kdev update` apply, after `--dry-run`) — no AST transform
   for `0.40.2-auth-workflow-cycle`.
3. **Manual** — Redeploy. Confirm logs no longer contain
   `Circular backend module dependency detected`.

Do not add `optionalDependsOn: ["workflow"]` on Auth in app code.

## Database migration

None. 0.40.1 `closed_at` columns are unchanged.

## Environment and deployment changes

No new required variable names.

- **Rollout order** — deploy backend (and worker) on 0.40.2 together. 0.40.1
  Auth+Workflow still cannot boot.
- **Workers** — `auth.purge` still runs only when Workflow is registered.

## Verification

In this repo:

```sh
pnpm --filter @m5kdev/backend exec jest -c jest.config.ts src/app.test.ts --no-coverage
```

The case `boots AuthModule with WorkflowModule without a circular dependency`
must pass.

In the app: process listens; Railway/Fly health checks succeed; Close Purge
cron still exists when Workflow is registered (`auth.purge`).

## Rollback

Revert pins to 0.40.1 only if Workflow is **not** registered. Auth+Workflow on
0.40.1 will fail boot again.

## Troubleshooting

| Symptom | Cause and fix |
| --- | --- |
| `Circular backend module dependency detected: auth → workflow → auth` | Still on 0.40.1. Pin 0.40.2 and redeploy. |
| Boot works but `auth.purge` is missing | Workflow is not registered, or `closeAfterDays` is below 1 (boot throw). |
| Mixed `@m5kdev/*` versions | Lockstep all packages to 0.40.2. |
