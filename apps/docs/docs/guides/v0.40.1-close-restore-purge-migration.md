# Close, Restore, and Purge in 0.40.1

## Summary

User and Organization removal is a restorable lockout (**Closed**), not
Membership soft-delete and not Better Auth `deleteUser`. A Closed User cannot
sign in. A Closed Organization cannot be used and is hidden from product UI.
Only an AdminActor **Restores**, from the Admin panel, while the row is still
Closed. After a grace window (`closeAfterDays`, default 30), **Purge**
permanently removes the row. Admin may Purge immediately.

Better Auth `deleteUser` is disabled. Admin Better Auth `removeUser` is
refused (`Use Auth Close`). Confirm Close in-app (type email or Organization
name). There is no account-deletion email.

There is **no** `create-m5kdev` registry transform. Schema generation is
**Manual**. Capability docs: [Auth](/modules/auth). Decision: ADR-0031
(`docs/adr/0031-close-restore-purge.md`).

## Who needs this migration

- **Every app that registers `AuthModule`.** Schema adds nullable `closed_at`
  on `users` and `organizations`. Login and OrganizationActor refuse Closed
  rows after you apply that schema.
- **Apps that posted `/api/auth/delete-user`** or used
  `authClient.admin.removeUser` / `useRemoveUser`. Those paths no longer
  hard-delete. Switch to Auth Close Procedures or the Danger zone.
- **Apps that copied User / Organization preferences or Admin user
  management** instead of mounting `@m5kdev/web-ui` routers. Add Danger zone
  and Admin Close / Restore / Purge (distinct from Ban).

No extra bootstrap change if you already use `new AuthModule()` and
`AuthUserRouter` / `AuthOrganizationRouter` / `AuthAdminRouter` from
`@m5kdev/web-ui`. New apps on this release already Close from preferences.

## Prerequisites and upgrade order

Complete [Inventoried File 1.0 in 0.40.0](/guides/v0.40.0-inventoried-file-migration)
first if you register File. On the 0.40.1 bump, Auth `closed_at` columns share
**one** Drizzle generate with any other 0.40.1 schema work.

1. Commit or stash application changes.
2. Upgrade every `@m5kdev/*` package and `create-m5kdev` together to **0.40.1**
   (Managed catalog lockstep). Do not mix 0.40.0 and 0.40.1.
3. Stop calling `/api/auth/delete-user` and Better Auth `removeUser`.
4. Generate and apply Drizzle migrations (`users.closed_at`,
   `organizations.closed_at`).
5. Deploy backend (and worker if Workflow is registered) before relying on
   login refusal for Closed Users.

Always invoke an exact CLI release:

```sh
pnpm dlx create-m5kdev@0.40.1 update --dry-run
```

## What changed

- `users.closedAt` / `organizations.closedAt` (nullable timestamps). Live means
  null. Do not reuse Membership `deletedAt`.
- Close User: Grant `delete` (`own` for the User, `all` for User-role admin).
  Type email in preferences. Revokes sessions, API keys, and MCP tokens. Leaves
  non-Owner Memberships. Refuses if the User Owns an Organization with other
  live Members, unless they are the only live Member (then those Organizations
  Close too). Refuses Close of the last User-role admin.
- Close Organization: Grant `delete` (`org` for Owner). Type the Organization
  name. Organization Role admin cannot Close. Refuses while a child
  Organization is live. Cancels Stripe when Billing is wired. Leaves non-Owner
  seats and pending invites. Owner Membership stays until Purge.
- Restore and Purge are AdminActor Procedures. Restore does not revive left
  Memberships or resurrect Stripe. Purge requires Closed. Purge User is
  refused while they still Own any Organization (including Closed).
- `AuthModule` accepts `{ grants, hooks, closeAfterDays }` or the previous
  `(grants, hooks)` constructor. `closeAfterDays` defaults to 30. Values below
  1 fail at boot when Workflow is present.
- Auth optional-depends on Workflow. When Workflow is registered, one daily
  cron Purges Closed rows past grace (children before parents, Organizations
  before Users). Without Workflow, Closed rows stay until Restore or Admin
  Purge. Apps hook extra cleanup with `afterPurgeUser` /
  `afterPurgeOrganization`.
- Web UI: Danger zone on User and Organization preferences; Admin lists
  Closed with Restore / Purge, distinct from Ban.
- Ban APIs are unchanged.

tRPC: `closeUser`, `closeOrganization`, `adminCloseUser`,
`adminCloseOrganization`, `restoreUser`, `restoreOrganization`, `purgeUser`,
`purgeOrganization`.

## Migration steps

1. **Manual** — Upgrade catalog pins for `@m5kdev/commons`, `@m5kdev/backend`,
   `@m5kdev/frontend`, `@m5kdev/web-ui` to `0.40.1`. `pnpm install`.
2. **Automatic** (`m5kdev update` apply, after `--dry-run`) — may merge Starter
   e2e Close tests if those paths are merge-clean. There is no registry `id`
   `0.40.1-close-restore-purge`.
3. **Manual** — Replace `/api/auth/delete-user` and
   `authClient.admin.removeUser` / `useRemoveUser` with Auth Close:

   ```ts
   await trpc.auth.closeUser.mutate({ email });
   ```

   Admin Close of another User: `trpc.auth.adminCloseUser.mutate({ id })`.
4. **Conditional** (app-owned preferences / Admin screens) — add the Danger
   zone components or mount the web-ui routers. Organization Role admin must
   not get Close.
5. **Conditional** (app tables that must die with the User or Organization) —
   register `afterPurgeUser` / `afterPurgeOrganization` on `AuthModule`.
6. **Conditional** (Workflow already registered) — Auth registers `auth.purge`
   daily. `closeAfterDays` below 1 throws at boot. Without Workflow, Closed
   rows stay until Restore or Admin Purge.
7. **Manual** — Generate Drizzle migrations with the project's usual command
   (`pnpm --filter <server> drizzle:generate`). Do not hand-write SQL. Apply
   before serving 0.40.1 Auth code. Expected Auth schema: nullable
   `users.closed_at` and `organizations.closed_at`.

## Database migration

Schema change. **Do not** create Drizzle migration files by hand. Run:

```sh
pnpm --filter <server-package> drizzle:generate
pnpm --filter <server-package> drizzle:migrate
```

Expected change: add nullable timestamp columns `users.closed_at` and
`organizations.closed_at`. There is **no data backfill**. Existing rows stay
live (`closed_at` null). Unique email and slug indexes are unchanged; Closed
rows still occupy them.

## Environment and deployment changes

No new required variable names.

- **Rollout order** — apply the Drizzle migration, then deploy backend (login
  and OrganizationActor read `closed_at`), then web (Danger zone). Old web
  against new backend can still Close via tRPC once the procedures exist; old
  backend against new web fails Close mutations until you deploy Auth 0.40.1.
- **Workers** — when Workflow is registered, `auth.purge` runs on the worker.
  Without Workflow there is no sweep.
- **Email** — stop expecting an account-deletion message. Keep the
  `accountDeletion` template in the Email registry until EmailModule drops that
  required key.

In the app:

- `POST /api/auth/delete-user` does not hard-delete. Better Auth admin
  `removeUser` returns forbidden (`Use Auth Close`).
- User preferences Danger zone: type email, Close, login fails, Admin Restore

  cannot Close.
- Admin user list shows Closed distinct from Banned; Restore / Purge appear
  for Closed rows.
- `pnpm check-types` / `pnpm lint` succeed.

## Rollback

Revert the `@m5kdev/*` / `create-m5kdev` pins to 0.40.0. After `closed_at`
columns exist, 0.40.0 Auth ignores them; leaving the columns in place is safe.
Do not re-enable Better Auth `deleteUser` against 0.40.1 AuthModule.

Closed rows applied on 0.40.1 remain Closed if you roll back the app without
clearing `closed_at`; 0.40.0 will treat those Users as sign-in-capable unless
you Restore first.

## Troubleshooting

| Symptom | Cause and fix |
| --- | --- |
| Drizzle wants to add `users.closed_at` / `organizations.closed_at` | Expected. Generate and apply; do not hand-edit SQL. |
| `/api/auth/delete-user` no longer deletes | Intended. Use `auth.closeUser` or the Danger zone. |
| Admin `removeUser` is forbidden | Intended. Use `adminCloseUser` / Close in the Admin panel. |
| Close User: “Close or transfer Organizations you Own first” | Other live Members remain. Transfer Owner or Close those Organizations, unless the User is the only Member (then Close User Closes those orgs too). |
| Close Organization: “Close child Organizations first” | A live child exists. Close children first. |
| Purge User: “Cannot Purge a User who still Owns an Organization” | Purge or transfer owned Organizations first (Closed orgs still count). |
| Login still works after Close | Migration not applied, or Restore already ran. Confirm `closed_at` is set. |
| `closeAfterDays` boot error | Value is below 1 and Workflow is registered. Use at least 1. |
| Closed org still in the switcher | Product list must come from `listUserOrganizations` (live only). Custom lists that query `organizations` directly must skip `closed_at` not null. |
